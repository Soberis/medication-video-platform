## 结论

“AI 先生成草稿，人工核对修正、提交并明确复核”是推荐方向，也是 V1.34 已定义的目标。当前提交只有局部接口与 UI，尚未形成 Qwen 生产闭环。应先完成一条可验证链路，再增加批量自动化和复杂编辑能力。

MediaPipe 与 Qwen 互补、独立执行，共用视频身份和时间基准。不要用“MediaPipe 没检测到手”阻断动作识别，更不能自动据此批准、拒绝或跳过人工任务。

## 尚未完成：不能当作已上线能力

1. **P1，Qwen 作业闭环缺失。** `AiCandidateJob` 的创建仍固定 MediaPipe；`workers/ai-worker` 没有 Qwen 执行器和动作消息消费路径。按钮只查询已有候选，不会启动模型。设计中引用的 `tools/action-poc/` 在本次 checkout 不存在，文档历史性能记录未在本轮验证。
2. **P1，候选完整 provenance 缺失。** `action_candidate` / 回传没有冻结任务 ID、输入版本、schema digest、完整模型及提示词来源、窗口完整性、原始输出等事实。服务端仍缺少任务标签成员校验、视频时长上界、重叠与窗口完整性校验。前端检查只是防御，不能替代服务端事实校验，不能据此宣布 V34-FR-002 验收通过。
3. **P1，当前候选查询不是可采纳快照。** 仍可能返回同视频不同历史作业；前端目前整体拒绝混合批次，但不能证明单作业匹配当前输入版本。上线完整自动采纳前，必须按任务/主视频/输入版本/schema/provenance 选择当前有效作业，并在提交时再校验。现有 revision 提交没有候选采纳关联。
4. **P1，V77 改写已有未提交任务的不可变 schema。** SQL 对全部未提交 ASSIGNED 任务直接改绑 v2，包括自定义 schema；可能丢失任务专属标签，并让进行中的草稿失配。本轮未改写已提交 Flyway 文件，也未操作已有数据。需要先审计实际影响，在新增迁移中保留可证明的原绑定；无法恢复原绑定时给出人工处理清单，不能猜测。
5. **P2，标签粒度混合。** v2 同层加入 `prepare_dose` 与 `draw_liquid` / `inject_mix`，宏观与细分含义重叠，缺少优先级、起止和易混淆定义。`check_info` 的“核对信息”也不能由画面推断实际认知或医疗正确性。V77 的 10 个定义摘要已按应用算法重新计算，摘要值一致，问题在语义和改绑策略。
6. **P2，编辑功能未齐。** 已有增删、时间输入、定位和片段播放；尚无完整拆分、合并、撤销、所有空白导航和边界拖拽。时间轨固定最小色块宽度会夸大极短区间并遮住空白，需区分真实宽度与点击命中区；不能声称完整时间轴编辑已交付。
7. **P2，任务状态与视觉。** 无候选、未运行、运行失败、请求失败未形成统一状态，自动查询错误被忽略；硬编码动作色表和 CSS 色值未遵循唯一 Token 来源。需按设计系统收敛，避免用色彩替代文字状态。部分既有功能仍待浏览器验收。
8. **P2，confidence 与设计不一致。** 回传和数据库强制置信度，但 V1.34 首版不要求该字段。应通过新迁移与契约变更将其调整为可选或移除；无论保留与否，不用模型自报数字决定人工确认或导出。

## 科学分工与无手视频策略

| 信息 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| MediaPipe 检测 | 采样帧中检测到的手与关键点，运行是否完成 | 药液抽取等业务动作、实际操作正确性；零检测也不能证明画面绝无手 |
| Qwen 视频理解 | 根据画面和任务标签定义提出动作及时间段候选 | 毫秒级准确边界、可靠真实置信度、自动批准结果 |
| 人工修订及复核 | 核对可观察行为和边界，形成正式版本 | 不能补造被遮挡的手部轨迹或未拍摄到的动作 |

Google 文档区分检测、手存在判断和跟踪阈值，并支持视频时间戳；这说明检测失败与语义上的“无动作”应分开。见 [MediaPipe 官方指南](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker)。Qwen 的时间戳视频能力是候选生成依据，不是本业务准确率证据，见 [Qwen3-VL 官方仓库](https://github.com/QwenLM/Qwen3-VL)。

建议默认保留以下区别：

- 检出手且有动作：Qwen 草稿 + MediaPipe 轨迹 + 人工修正。
- 未检出手但看得出动作/物体变化：仍可标动作，手部轨迹缺失如实记录。
- 人工确认的空场景或等待：可作为负样本/空闲状态研究数据；是否建立显式标签取决于用途，不能把所有未标注区间变成 IDLE。
- 解码失败、推理失败、遮挡和无法判断：显示真实失败或不确定原因，不能归入“无人操作”。

若未来希望“人工确认无动作后关闭任务”或自动跳过整片，应先新建版本化需求，定义谁确认、如何撤销、负样本怎样保存，以及如何与现有必须有手样本的 HDF5 准入区分。当前配套导出仍按原有规则执行。

## 标签库、Qwen 与前端如何统一

唯一真值是任务绑定的不可变 label schema。前端显示同一份定义；Core 在建立作业时冻结其 ID、digest、label_id、说明、起止和混淆规则；Worker 从该快照生成提示词，输出精确 label_id；Core 校验成员资格。禁止用中文 display_name 或大小写猜测非法模型输出的实际含义。

新增标签应发布新版本，供新任务采用；既有任务不自动换绑，历史导出保留旧版本。旧任务升级需要显式重绑规则、草稿影响提示、旧候选失效和重新推理。Worker 不应拉“当前最新 schema”替代任务绑定版本。

新标签通常可先用同一个 VLM 通过提示词评估，无须每次修改模型权重；但不保证模型能识别新增概念。先检查可观察性和类间区分，再测召回、误报、边界误差及人工耗时。UI 的“添加片段/删除片段”与“发布标签库版本”应明确区分。

## 导出、同步与机器人学习

用户补充的实际采集边界：在医院拍摄医务人员配药过程，当前来源是人体示范视频，不包含机器人关节、末端或夹爪控制记录。当前平台无需新增机器人采集模块。数据定位为人体配药示范视频及其动作、手部检测事实；将来用于机器人执行时，由机器人侧补充控制示教、标定或适配数据。视频无法准确还原这些未采集的控制真值。

已有 `HumanDemonstrationHdf5ExportService` 将人工区间按 `[start_ms,end_ms)` 匹配主视频手部 `frame_timestamp_ms`，`samples` 同行保存 label、区间、21 点坐标、图像尺寸及作业来源，另保留 annotations 和各机位 evidence。这一关联应复用。

需要注意：

- 主视频时间轴同步不等于多摄像头物理同步。辅助机位缺少经过验证的偏移/漂移映射时，只保留事件级证据，不复制主视频动作边界冒充同步标签。
- 可变帧率用解码 PTS；Qwen 窗口局部时间必须映射原视频时间，不能用帧号除以假设 fps。窗口重叠、末尾短窗口和漏帧都要测试。
- 现有 samples 是检测到的手与人工区间的交集，缺样不等于静止；一帧两只手可有两行。训练读取器必须按 timestamp 与 hand_index 分组，不能直接将行号当帧号；handedness 不能当稳定跟踪 ID。
- 毫秒存储不代表毫秒精度。采样分辨率及窗口边界误差必须在评估中报告。缺失轨迹不可填零伪装有效坐标。
- 数据按原始事件/录制来源划分训练、验证和测试，避免同视频不同窗口或不同机位泄漏；保留标签版本、来源 hash、人工 revision 和复核版本。
- 现有 HDF5 支持动作识别、时序定位和人体示范表征；它没有天然提供机器人关节位置、关节速度、末端位姿、夹爪开合、力/力矩、坐标标定与真实控制动作。需要这些信息的控制策略无法直接把人手关键点当作机器人 action。

[LeRobot 官方数据格式](https://huggingface.co/docs/lerobot/lerobot-dataset-v3) 将时间戳、视频和机器人观测/动作作为多模态数据组织；这支持上述用途区分，并不要求本平台立即更换导出格式或新增标定系统。

## 可交给后续 AI 的分阶段任务

按顺序执行，每阶段完成测试后再进入下一阶段，不同时铺开：

1. **修复标签绑定与定稿语义。** 审计 V77 改绑影响；不修改既有迁移 checksum。提出可证据恢复的前向修复方案。选择当前单层标签粒度和优先级，完善可观察定义。业务语义调整先建立新 DRAFT，CURRENT 不变。
2. **完成单任务 Qwen 闭环。** 复用 Core API、ai-worker、outbox/租约/重试；冻结 task/input/schema/media/model/prompt/config 来源，增加必要的版本化消息和 API。授权手动派发一条任务，执行完整窗口校验，保存候选和原始结果，提交 revision 关联候选来源。不能调用患者数据或运行时下载模型。
3. **加入已要求的自动派发与自动草稿。** 两种顺序（先质检、先建任务）均只派发一次；不等待 MediaPipe；无主视频不派发。处理重试、输入变化、旧 attempt、重复回传、部分窗口失败、空成功结果。首次未编辑任务可自动显示完整有效草稿，已编辑工作绝不覆盖；刷新显示真实运行状态。
4. **补完人工编辑与导出回归。** 在现有组件中增加拆分/合并/撤销、键盘边界操作、空白导航及上下文播放；候选和人工版本清晰区分。验证任务切换、机位切换、请求晚到、无手、无候选及历史标签任务；回归批准后导出同源 HDF5 和失效即拒绝规则。
5. **离线效果评估。** 获批固定模型、合成数据先行；授权隔离样本另行管理。比较纯人工与 AI 辅助的最终质量和总耗时，记录短动作召回、标签混淆、边界误差、失败率、GPU 峰值、冷/热启动与人工修改量。不以一个演示成功或模型自报 confidence 作为验收。

以上是较大改动的实施计划，本轮未声称完成这些阶段。
