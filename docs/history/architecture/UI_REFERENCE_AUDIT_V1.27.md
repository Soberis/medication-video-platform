# V1.27 UI 参考审查：定向收敛建议

> 审查日期：2026-09-04  
> 审查基线：`main` @ `997438010e659ee596cc74388a43fff61e3600b7`  
> 审查方式：只读。未修改产品代码、样式、测试、Golden 截图、依赖、提交或远程状态。

## 1. 执行摘要

当前 V1.27 前端已经形成了清晰且专业的单一路径：**CaptureGroup 是唯一业务对象，单路视频是 N=1 的 CaptureGroup，多路视频是同一对象的 N>1 形态**。视频管理用于发现和进入工作；事件工作台用于播放、人工判断、标注、复核、训练资格检查与审计。这个边界正确，不应重新拆回“普通视频详情”和“多机位详情”两套产品。

与 Twenty、CVAT、Medplum 对照后，结论不是要引入更复杂的工作台，而是做两处小范围的收敛：

1. 已完成事件不要同时在“当前结果”和“人工复核 / 训练资格检查”中重复完整结论；首屏保留一个结果摘要，其余证据按需展开。
2. 将事件级手部关键点导出从页头操作降到现有“视频与辅助证据”语境中，避免它和当前人工动作竞争注意力，同时明确它是独立检测证据导出，不是训练数据导出。

除此之外，现有结构应保留：平面任务/事件列表、N=1 不显示无意义机位选择器、N>1 使用紧凑机位切换、候选检测证据与正式标注分离、原生播放器、渐进披露审计信息，以及完成后的紧凑状态。

本审查没有发现需要立即阻断发布的 UI/UX 问题，因此 **P0 为零**。建议只排入两项强 P1，不做宽泛重做。

## 6. 明确保留不变的设计决定

以下是当前版本已经正确、且常被“视觉优化”误伤的部分：

- **CaptureGroup-only**：视频列表是 CaptureGroup 入口，不恢复独立单视频工作流；N=1 是统一模型的一种数据形态。
- **候选不等于正式标注**：MediaPipe / Skeleton / Candidate 只作为辅助证据；不能凭 UI 样式或快捷操作变成正式标签、人工质量、Review 或 Cleaning 决定。
- **人工闸门不删**：机位质量、事件质量、提交、管理员复核以及训练资格检查仍需要人和服务端事实共同约束。
- **独立导出边界不删**：`training-data.v3` 是 CaptureGroup eligibility/provenance manifest；`hand-landmarks.v1` 是经过 provenance 校验的当前检测事实。二者不能因页面合并而混为同一数据集。
- **渐进披露不删**：技术事实、模型信息、版本和审计不是无用信息；它们只是不应挤占主工作区。
- **不引入“专业剪辑器”**：当前视频辅助与结构化时间段编辑的复杂度适当；图形时间线、多轨播放器、图层面板、标注画布与全局快捷键系统都不在 V1.27 的最小闭环内。

## 7. P0 / P1 推荐

### P0：无

未发现会破坏 CaptureGroup-only 路径、正式标注边界、人工闸门、导出语义、响应式可用性或主工作流完成能力的界面阻断项。

### P1-A：完成态只保留一个首屏结果摘要

**问题**：完成的事件同时出现“当前结果 / 流程已完成”和“人工复核已通过 · 训练资格检查通过”的完整表达。两者都是正确事实，但在首屏相邻出现会让完成态看起来比待处理态更重。

**最小做法**：

- 保留页面顶部的“当前结果”作为唯一首屏结论，使用“人工复核已通过，当前可用于训练”这类业务句。
- 将复核与训练资格区域改为“查看复核与训练资格详情”的渐进入口；展开后保留 Revision、人工意见、规则版本、资格原因、重新检查记录等完整证据。
- 不改变任何 API、权限、复核动作、清洗/资格事实或导出准入逻辑。

**决策类型**：合并 + 减少 + 重排。  
**预期收益**：完成态更像平静的结论页，而不是把同一事实展示两次；审计能力不受影响。

### P1-B：将手部关键点导出降入“视频与辅助证据”

**问题**：事件详情页头的手部关键点导出与“刷新”和当前人工动作同处，容易让用户把它误解为当前流程的下一步或训练数据导出。

**最小做法**：

- 从 CaptureGroup 详情页头移除事件级 `HandLandmarkExportButton`。
- 在现有“视频与辅助证据”披露区域中复用该按钮，并将说明写清为“导出当前手部检测证据（hand-landmarks.v1）”。
- 项目级 `training-data.v3` 出口仍只保留在其既有的项目/任务语境；不要把两个导出入口合并成一个模糊按钮。

**决策类型**：减少 + 重排 + 复用。  
**预期收益**：页头只服务于当前工作；独立检测导出的合法边界仍清楚且可达。

## 8. P2 / P3：现在明确拒绝的方向

这些点不是遗忘项，而是按 V1.27 范围有意识地不做：

| 候选方向 | 当前决定 | 原因 |
| --- | --- | --- |
| 总览仪表盘、统计卡墙、趋势图 | P2，拒绝 | 当前核心任务是处理事件，不是经营分析；会稀释事件列表的下一步。 |
| 复制 CVAT 的画布、图形时间线、对象面板、多轨播放器 | P2，拒绝 | 标注模型是段落+标签；引入该复杂度会扩大框架、测试和学习成本。 |
| 一次展示所有 N 路视频并假装精确同步 | P2，拒绝 | 支持机位只能在服务端映射可靠时作为参考，不能用视觉布局伪造同步保证。 |
| Twenty 式任意自定义表、视图、字段管理 | P3，拒绝 | 当前业务状态和事实由契约定义，不能把关键工作流交给浏览器自由配置。 |
| Medplum/FHIR 通用资源浏览器 | P3，拒绝 | 领域对象、权限和审计需求不同，会破坏 CaptureGroup 工作流聚焦。 |
| 新全局组件库、状态管理、播放器、动画依赖 | P3，拒绝 | 现有浏览器/Ant Design/本地组件足够；没有第二个真实用例支撑抽象。 |
| 为“好看”恢复独立视频详情路径 | P3，拒绝 | 直接违背 V1.27 CaptureGroup-only 和 N=1 统一模型。 |

## 9. 跨页面一致性观察

1. **当前动作只应有一个**：列表的“下一步”、详情的“当前动作”、标注工作台的提交按钮已经基本做到这一点。事件级检测导出应从该层级移开。
2. **完成态应更轻，而不是更长**：完成后保留一个明确结果和一个可展开的事实入口；不要新增“庆祝卡片”、进度环或无意义按钮。
3. **术语需保持边界**：界面中“训练资格检查”“训练数据导出”“手部检测证据导出”应始终分别指向规则资格、`training-data.v3` 与 `hand-landmarks.v1`，避免简称为同一个“导出数据”。
4. **候选证据保持辅助层级**：无论单路还是多路，辅助覆盖层、模型结果和左右手信息都要低于正式时间段与人工决定。
5. **窄屏继续使用单列回流**：不在 720px 强保留双栏。现有 Golden 已验证该策略；新增 P1 内容应继续由现有 disclosure 承担，而不是新增横向表格。
6. **本地视频的呈现方式正确**：授权后才加载、原生控件播放、全屏带辅助覆盖层，比预加载、静态缩略图墙或另起播放器更安全也更易理解。

## 10. 可采用与不可采用的模式

### 可以采用

- **Twenty：记录列表的扫描顺序**。当前 CaptureGroup 列表已实现，后续仅在真实量级出现后补充契约支持的筛选。
- **CVAT：主工作区优先**。把注意力留给当前视频和当前标注动作，技术证据退到披露层。
- **Medplum：事实可追溯而不抢主操作**。Inspector 和复核/资格详情是正确用法。
- **Vercel Web Interface Guidelines：语义优先、键盘与媒体可控、内容可换行且无横向溢出**。这些由现有 E2E 继续守护即可。

### 不可以采用

- 用“更像专业软件”的密集面板替换当前结构化表单。
- 用 Dashboard、AI 卡片、渐变或大面积状态色制造所谓高级感。
- 把独立检测证据导出伪装为训练数据导出，或把候选结果伪装为正式结果。
- 以隐藏审计为代价压缩页面；正确方向是默认收起、随时可核对。

## 11. 最小实施顺序

1. 先统一完成态文案与信息归属：确认顶部“当前结果”是唯一摘要，复核/训练资格区域保留详情和审计事实。
2. 将事件级 `HandLandmarkExportButton` 重排进已有“视频与辅助证据”披露，不增加新菜单、新路由或新导出协议。
3. 更新与完成态、事件详情有关的单元/E2E 断言和 1440/720 Golden；确认无横向溢出、焦点路径和导出可访问名称不变。
