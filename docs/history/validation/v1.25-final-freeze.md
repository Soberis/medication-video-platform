## 运行时范围

冻结范围覆盖当前 V1.25 纵向闭环：

- `assetcapture`：显式 `CaptureGroup`、动态 `N` 路、`CaptureSession`/`CameraSet` 接入事实、Receipt 三态、每路媒体与视图身份；
- `aicandidate`：每路 MediaPipe `CandidateAnnotation` 及其 provenance，候选不成为 Ground Truth；
- `qualitycleaning`：逐视图质量、人工 `CaptureGroupQualityReview`、组准入和事件级 deterministic Cleaning；
- `annotationreview`：每组唯一 `AnnotationTask`、Primary View、append-only `AnnotationRevision` 链和 human Review；
- `datasetexport`：只读 `training-data.v3` group manifest preview/download 与 CaptureGroup 粒度的 split 校验；
- `apps/web`：配药事件列表、详情、任务路由和上述事实的用户工作区。

不把本记录中的 synthetic/service 证据表述为真实生产数据、医院硬件或批准 UAT 证据。

## 冻结的配药事件工作流

```text
CaptureGroup
→ Receipt
→ View Quality
→ Group Quality
→ one AnnotationTask
→ Primary View
→ append-only Revision
→ human Review
→ deterministic Cleaning
→ training-data.v3
```

`CaptureGroup` 是一次真实配药事件的最小数据边界；业务身份 `capture_group_id` 默认复用
`CaptureSession.capture_session_id`。归组、预期机位和 `camera_number` 必须来自显式 manifest/上游事实，缺失机位不重编号。Receipt 只表示预期文件是否收到并被显式 finalize；Media Probe、Candidate、View Quality 和 Group Quality 不回写 Receipt。

## `training-data.v3`

`training-data.v3` 是 V1.25 的最小事件级 manifest，不是 DatasetVersion 平台。它通过只读 preview/download 暴露组、Revision、Primary View、参与/排除视图、确认 View Set、质量、Review、Cleaning 和候选 provenance；不复制 MP4。正式动作区间只来自 Primary View 的人工 Revision，Supporting Views 仅作为事件级证据。训练切分以 `CaptureGroup` 为最小 split unit，同一组的视图和派生行不得跨 train/validation/test。

## 科学与数据完整性规则

- manifest declaration != actual receipt：manifest 声明预期集合不等于文件已经收到。
- Media Probe != receipt：媒体探测失败不改变已确认的收件事实。
- AI Candidate != human quality：候选只供人工参考，不产生正式质量或动作标签。
- `NO_HAND_DETECTED` != failure：成功运行且未检测到手是有效候选结果，不等于作业失败。
- Primary View is the formal timebase：正式动作时间区间只能以主视图为时间基准。
- Supporting Views are event-level evidence only：支持视图不得被静默赋予精确动作时间戳。
- `REJECTED` != deleted：拒绝视图保留原媒体、绑定、候选、原因和审计，只停止其下游参与。
- CaptureGroup is the minimum dataset split unit：同一真实事件的视图和派生数据不得泄漏到不同 split。

## V1.25 不 reopen / 延后范围

- CaptureSync；
- calibration / 3D；
- DatasetVersion platform；

- generic state machine；
- new queue/microservice；

同时继续遵守 V1.25 需求基线中的 deferred 边界：帧级同步与自动对齐、三角测量、跨相机追踪、3D 手部重建、复杂导出/训练平台、可配置质量规则平台和批量 Worker/Queue 不属于本次冻结交付。

## 已知非阻塞债务

- `AnnotationTask` 列表 enrichment 在项目规模很大时可能需要有界的 group-id lookup；当前实现保持现有简单查询，暂不扩展。
- candidate-failure synthetic 场景在没有现成受控 fixture 时保持 `NOT RUN`；不通过新增 failure-injection framework 解决。
