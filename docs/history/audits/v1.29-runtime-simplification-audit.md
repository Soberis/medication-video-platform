# V1.29 Runtime Simplification 冻结审计

状态：COORDINATOR FREEZE / 只读
日期：2026-09-04
基线状态：**V1.29 保持 DRAFT；V1.28 仍是当前正式 runtime 基线。**

## 冻结结论

V1.29 的目标默认路径已经由四份专项审计和当前代码交叉证实：`CaptureGroup` 是中性的上游数据组身份与成员边界，不是配药事件工作流容器；默认路径是接收、媒体检查、MediaPipe `CandidateAnnotation` 和 `hand-landmarks.v1` detection evidence。人工质量、Annotation、Review 与 Cleaning 只在项目明确需要 human ground truth 时才有职责。

这不是 runtime 已完成收缩的结论。当前 Java、OpenAPI、Web、synthetic 验收和运行手册仍把 quality-qualified 后自动创建 `AnnotationTask` 作为现有行为。V1.29 不能升级为 CURRENT：项目 human-label opt-in 的授权/审计规则尚未批准，相关 runtime 与契约尚未成组改造和验证。故不修改 V1.29 DRAFT 或 `AGENTS.md`。

本报告将 Task A/B 及既有数据组、接入/AI 审计中的分类统一为 `KEEP`、`SIMPLIFY_NOW`、`SAFE_DELETE_NOW`、`DEFER`、`HISTORICAL_ONLY`。**没有 `SAFE_DELETE_NOW` 项：每个候选删除仍有真实调用、公开兼容面、历史保留或尚未完成的前置条件。** 因此没有保留无法解释的 `UNCERTAIN`。

## 最小领域边界

```text
CaptureGroup（中性数据组；明确上游归属）
  └─ CameraStream / ClipAsset
       ├─ Media Probe / media facts
       └─ MediaPipe job/attempt/CandidateAnnotation provenance
            └─ hand-landmarks.v1（独立、只读、fail closed）

仅项目需要 human ground truth 时：
QualityReview → included/excluded label inputs → AnnotationTask → append-only Revision
             → AnnotationReview → deterministic LabelEligibility（现名 Cleaning）
```

- `CaptureGroup` 保留 `project_id`、稳定 ID、显式上游 key/source、声明和实际成员、receipt close/missing 事实、`ClipAsset` SHA-256、`CameraSet`/`CameraStream`/`DeclaredSyncStatus`。这些是数据与 provenance，不是医院、患者、药品或设备管理。
- `QualityReview` 是逐视图的人工标签输入事实；媒体技术可用性仍来自 Media Probe/asset。没有 human-label 需求的数据组不应被创建 Quality 或被它阻塞。
- `CaptureGroupQualityReview` 的可保留价值是不可变的 included/excluded view set、digest 与 label-input 审计；“所有视图 resolved → 自动派单”的默认仪式应移除。
- `AnnotationTask`、Revision、Review 仅服务人工标签。Review 评价 revision 可信度，不评价原视频、Candidate 或 CaptureGroup 生命周期。
- Cleaning 只保留 approved-review、eligibility/exclusion reason、规则 digest、fingerprint、幂等和审计；它不改媒体，也不是 `hand-landmarks.v1` 准入。新表面可称 `LabelEligibility`，但不应在本次简化中迁移或删除历史 Cleaning 事实。
- 不持久化 `stage`、`next_action`、`blockers`，也不建立通用 workflow engine。前端只呈现独立事实和现有 `can_*` capability；写命令继续由服务端 guard 作真值。

## 调度竞态裁决

结论：**FOLLOW-UP: regression coverage**。

已验证的当前事实：

- `services/core-api/src/main/java/com/medicationvideo/platform/assetcapture/ClipAssetMediaIngestService.java` 在成功 Media Probe 后调用 `HandPoseSchedulingPort.scheduleAfterMediaIngested`。
- `CaptureSessionIngestService.java` 在 `CameraStream` `saveAllAndFlush` 后，针对当前读到 `INGESTED` 的 asset 调用同一 port；`PlatformLocalCaptureSessionService.java` 对 N=1 作相同补调度。
- `aicandidate/HandPoseAutoSchedulingService.java` 将既有 transaction 的调度注册为 `afterCommit`，并在 `REQUIRES_NEW` 调 `HandPoseJobService.queueAfterMediaIngested`；辅助调度失败不会回滚已提交的媒体事实。
- `HandPoseJobService.java` 的固定 idempotency key、receipt 与 natural key 使正常重复 ensure 不重复创建 job/attempt。
- `ClipAssetMediaIngestServiceTests`、`PlatformLocalCaptureSessionServiceTests`、`HandPoseAutoSchedulingServiceTests`、`HandPoseJobServiceTests` 分别覆盖成功调度、已 INGESTED 的 N=1 补调度、after-commit/异常隔离和重复 job 去重。

仍缺少一个真实数据库事务级测试固定：CaptureSession 先读取 `UPLOADED`，Media Probe 在 stream 事务提交前置为 `INGESTED`，并在两个 after-commit 后断言恰一个 current job/attempt。由于 binding 后的两处 service 仍根据先前读取的 asset status 决定是否调用 port，现有 Mockito/单事务测试不足以把该交错标为 `RESOLVED IN CURRENT MAIN`。这只是 regression coverage follow-up：不新增扫描器、补偿表、队列、状态机或 P0 设计。

## API、event、Web、tools、Worker 兼容边界

- API/OpenAPI：保持 upload/manifest V2、CaptureGroup、媒体/AI、人工链历史读取和 `hand-landmarks.v1`；任何停止自动派单必须同时修正 OpenAPI 中“qualified 原子创建 task”的描述与 contract tests。公开 orphan-like path 一律 `DEFER`，直到 inventory/弃用完成。
- Event：quality-qualified JSON schema 没有 broker/Worker consumer，但 Java in-process event 是当前 task creation 的执行链。先替换行为，后处理 event/schema；Worker AI/media event contract 及 Inbox/Outbox 都 `KEEP`。
- Web：用户默认词汇为“数据组”；保留 `CaptureGroup`/`CaptureSession` 等技术 ID。默认不展示固定线性 lifecycle；任务列表只作已启用 human-label 工作的 inbox，详情是事实/capability 的 canonical deep link。
- Tools/scripts：`tools/synthetic-upload-client` 和 `tools/synthetic-capture-group-client` 保留，但后者拆为 machine-evidence default smoke 与 opt-in human-label scenario。`candidate-capacity-review`、`hand-pose-evaluation` 和 `scripts/quality-gate.*` 都保留；前两者不是训练 runtime，后者不是旧产品功能。
- Workers：`workers/media-worker` 和 `workers/ai-worker` 只处理 media/AI job，继续不写 Quality、Annotation、Review、Cleaning 或 frozen dataset；无 Worker 删除或协议迁移。

## 唯一导出与保留/删除清单

`hand-landmarks.v1` 是唯一 current detection evidence export。`HandLandmarkTrainingExportService` 只读取 current enabled/available `CameraStream`/`ClipAsset` 和 `CandidateEvidenceQueryService`，在 SHA-256、job/attempt/message/result、模型/profile、21 landmarks 或 current view 不可证明时 fail closed；它不读 Quality、Annotation、Review 或 Cleaning。它不是 human ground truth、训练 consumer 或效果评估证明。

保留：数据组/media/AI 事实与可靠性、权限/审计、human-label 的全部历史事实与约束、scoped Media Probe、受控 recovery、worker internal protocol、质量门禁和合成/评估工具。

现在不删除：任何 Java runtime、migration、数据库事实、公开 API/schema、Worker、Web route、测试或工具。后续可处理的候选均列为 `DEFER`，而非 `SAFE_DELETE_NOW`。

## 风险与不应做的改动

1. 不只删除 listener、schema、页面或测试中的任一层；自动派单的当前行为跨 Java、OpenAPI、Web、synthetic、runbook 和 contract tests。
2. 不把 Candidate、handedness、Media Probe 或浏览器推导提升为 Quality、正式标签、Review、Cleaning 或 group lifecycle 真值。
3. 不删除/回写 migration、历史 Quality/task/revision/review/Cleaning、audit、receipt、provenance、Outbox/Inbox、lease/retry。
4. 不恢复旧 manifest、`training-data.v2`/v3、CaptureSync、DatasetVersion、训练平台、独立单视频 task/cleaning，或以简化名义新增 project-wide workflow engine、持久化 `next_action`/`blockers`。
5. 本审计未运行全量质量门禁，也未接触真实视频、账户或外部服务；运行时改动必须按后附实施计划验证。
