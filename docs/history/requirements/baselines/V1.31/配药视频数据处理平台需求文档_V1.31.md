# 配药视频数据处理平台需求基线 V1.31

日期：2026-09-07  
状态：DRAFT / P0 实施中

## 1. 目标

在保留现有视频、MediaPipe 检测事实和人工标注审计边界的前提下，提供唯一的管理员 HDF5 数据导出。管理员可维护动作标签库，并在视频列表中选择一个、多个或当前项目内全部已完成标注的采集记录导出。

本版本继承 [V1.30](../V1.30/配药视频数据处理平台需求文档_V1.30.md) 的界面与业务边界；冲突时以本版本为准。

## 2. P0 范围

### 2.1 标签库

- 标签库由平台管理员管理，所有项目共享；普通成员只能读取当前标签。
- 管理员可新增一个 `PRIMARY_STEP` 动作标签：稳定英文 `label_id`、中文显示名称和说明均为必填。
- 新增标签发布一个新的不可变 label schema；新建标注任务使用新 schema，已有任务、revision 和已导出数据保持原 schema/digest，不编辑、不删除、不重写。
- P0 不支持编辑、删除、排序或按项目覆盖标签，避免破坏历史标签语义。

### 2.2 HDF5 导出

- 平台只保留唯一的 `human-demonstration-hdf5.v1` 下载。`capture_group_id` 可重复指定一个或多个采集记录；缺省时导出当前项目全部合格采集记录。
- 仅导出当前输入和媒体 provenance 仍有效、人工标注已审核通过的记录；规则复用现有人工标注导出。没有合格记录时以明确错误拒绝，不生成空的“可训练”文件。
- 显式选择一个或多个采集记录时采用 fail-closed：任一已选择记录在下载时已经失去导出资格，则整次选择导出拒绝，不静默漏掉该记录后继续生成部分文件。
- 一个合格 `CaptureGroup` 为一个 HDF5 episode。episode 保存源视频身份/SHA-256、标签 schema/revision provenance 和当前 MediaPipe provenance。
- 训练消费的主数据面为 `samples` 列式表：只使用人工标注的主视频；每一行对应一个落入已审核动作区间的 MediaPipe Candidate，并在同一行保存 `frame_timestamp_ms`、`hand_index`、`handedness`、`landmarks[21,3]`、`label`、`segment_start_ms`、`segment_end_ms`。标注区间按 `[start_ms, end_ms)` 匹配，不把区间标签复制给无时间对应关系的参考机位。
- 当前 `annotations` / `views` 只作为最小审计与来源 provenance 保留，不构成第二套导出格式；下游训练读取 `samples` 即可获得 MediaPipe 数据与对应人工动作标签。
- HDF5 不包含 MP4 字节、对象存储键、预签名 URL、患者身份、机器人状态或控制动作。它是平台自定义的 `human-demonstration-hdf5.v1`，不是 LIBERO/robomimic 兼容文件；不得虚构 `states`、`actions`、reward 或 success。
- 多机位的原始 MediaPipe provenance 可以保留用于审计，但不进行自动时间对齐，也不将主机位人工标签复制到参考机位。
- 当前仅允许 synthetic profile；非合成授权和导出仍等待人工治理审批。

### 2.3 界面

- 管理员在“设置”中可进入“标签库”，查看当前标签并新增标签；标签发布后新建标注任务使用新规范，历史任务继续绑定原规范。
- 视频列表是唯一导出选择面：只对已完成标注并通过复核的记录提供勾选；管理员可选择一条或若干条，也可从顶部“导出数据”直接下载当前项目内全部合格记录的一个 HDF5。详情页不提供导出入口。
- 下载前文案明确范围和 HDF5 所含内容；不新增数据集版本、异步导出队列、导出历史页面或跨项目打包逻辑。

### 2.4 导出收敛

- 移除 `hand-landmarks.v1` CSV、`human-annotations.v1` CSV 及其预览、下载入口和 Web 菜单；平台不再提供 CSV 导出。
- HDF5 只提供一个用户可见导出入口；`samples` 是下游训练主表，人工审核标签与主视频 MediaPipe Candidate 已按源时间直接对应。
- `annotations` 与 `views` 如保留，仅用于审计、回读和 provenance，不增加第二种用户操作或第二份文件。

## 3. 契约与验收

| ID | 需求 | 最小验收 |
| --- | --- | --- |
| V31-FR-001 | 新增标签发布不可变 schema | 管理员新增后新任务可用新标签；旧任务仍只接受旧标签；成员写入被拒绝 |
| V31-FR-002 | 单记录/多记录/当前项目全部 HDF5 导出 | 三种范围均下载一个 `.hdf5`；非管理员、无合格标注、选择项失效和 provenance 漂移被拒绝 |
| V31-FR-003 | HDF5 内容可回读 | 合成文件可读取 episode、视频 SHA、`samples` 的 label/时间区间、landmark `[N,21,3]` 和 AI provenance |
| V31-FR-004 | 机器与人工事实正确对应 | `samples` 只匹配主视频中落入审核区间的 Candidate；参考机位不复制主机位标签；不输出虚构机器人 action |
| V31-UX-001 | 管理与导出入口 | 管理员可从标签库新增标签，并仅从视频列表选择一个、多个或导出当前项目全部合格记录；成员不见写入或导出入口 |

## 4. 非目标

- CSV、LIBERO / robomimic `states/actions` 兼容导出；
- LeRobot、RLDS、Parquet、视频打包、模型训练或机器人控制；
- 真实患者数据、生产导出、自动数据放行；
- 标签编辑、删除、项目专属标签库、跨项目一键打包、数据集版本或导出作业系统。

V1.31 成为 CURRENT 前仍须完成合成数据契约、HDF5 `samples` 回读、前端交互验证、用户验收和非合成治理评审。
