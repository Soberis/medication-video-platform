# 配药视频数据处理平台需求基线 V1.34

日期：2026-09-09
状态：DRAFT / 待实现验证与用户验收

继承 [V1.33](../V1.33/配药视频数据处理平台需求文档_V1.33.md) 及其未变更边界。本版优化已有草稿，新增动作预标注与人工修正；配套导出沿用既有规则。文档更新不代表功能已实现、模型已部署或效果已验证，CURRENT 保持不变。

实施细节见[动作标注技术设计](../../../../architecture/v1.34-action-annotation.md)。本基线定义需求与验收，技术设计不得另设标签、权限或导出规则。

## 1. 目标与结论

标注任务回答一个问题：**视频的哪个时间段，在做什么？**

AI 生成时间段草稿，人工查看、修改并提交，复核通过后与同源手部检测数据配套导出。目标是在最终标注质量不降低的前提下减少人工耗时，收益通过对照试验确定。

动作标注与 MediaPipe 独立运行。动作预标注不等待手部检测；只有配套导出时，两类数据才必须同时满足既有准入条件。首版不引入 YOLO、手物交互推断、三维标定或模型训练。

用户已提供 RTX 4090 24GB。首选评估模型为 `Qwen/Qwen3-VL-8B-Instruct`、BF16、单任务推理；这是待实测方案，不是效果或显存保证。

## 2. 数据与业务规则

### 2.1 标注内容

每个片段保留 `start_ms`、`end_ms`、`label`。示例仅说明格式，标签实际值遵循任务绑定的 label schema：

```json
{
  "segments": [
    { "start_ms": 10000, "end_ms": 25000, "label": "DRAW_LIQUID" }
  ]
}
```

- 使用主视频原始时间轴，区间为 `[start_ms, end_ms)`；满足 `0 ≤ start_ms < end_ms ≤ 视频时长`。
- 复用标签库和任务绑定的不可变 schema，不硬编码新的五类标签，不自动创建标签。
- 沿用单层 `PRIMARY_STEP` 不重叠约束。这是标注规则，不表示现实动作天然互斥；并行动作按标签说明选择主步骤。
- 标签说明明确可观察含义、起止判据和易混淆情况。粒度按任务用途统一，不强制将所有业务步骤拆成原子动作。
- 未覆盖表示“尚未标注”，不自动判为 `IDLE`、无动作或不合格。无法判断时留待人工处理，不补写没有画面证据的动作。
- 毫秒是存储单位，不承诺毫秒级精度。模型自报置信度不是正确率；首版不要求 `confidence`。

### 2.2 候选与人工版本

```text
质检合格(Admitted Quality)＋创建标注任务 ──[自动调度派发]──> 动作候选
(质检未决或特殊情况 ───────────────[手动触发兜底]───────────────┘    │
                                                                   │
                                           [合规候选自动铺设初始轨道 / 存疑候选手动确认]
                                                                   ↓
                                                            人工微调与编辑 ──> 提交 revision ──> 人工复核
                                                                                                    ↓
同源 MediaPipe 当前有效证据 ───────────────────────────────────────────────────────────────────→ HDF5
```

AI 输出只进入 `aicandidate` 候选事实；人工提交通过 `annotationreview` 生成不可变 revision。复核、Cleaning 和导出保持既有权限与守卫，AI 不自动放行。

沿用 V1.32：全局 ADMIN 且具有 ACTIVE 项目 ADMIN Membership 的管理员可确认自己提交的标注，不要求另一人复核；提交不自动确认。第 6 节独立质量复核是试验评估方法，不新增日常双人审批要求。

候选保留视频身份与 SHA-256、任务输入与标签 schema 版本、模型版本及权重摘要、提示词和推理配置版本、job/attempt、原始输出。人工采纳可追溯至候选；重新推理或新回传结果不得静默覆盖人工草稿或已提交 revision。

## 3. 最小功能闭环

| ID | 需求 | 可观察结果 |
| --- | --- | --- |
| V34-FR-001 | 质检合格任务自动派发异步预标注，异常场景支持手动兜底 | 数据组通过质检（admitting group quality）并建立标注任务后，系统自动向队列派发动作推理作业，无需人工手动点击；未通过质检、存疑或特殊视频不自动占用 GPU，保留授权用户在任务内手动触发入口；不等待 MediaPipe；状态明确可区分，失败不阻塞纯人工标注 |
| V34-FR-002 | 候选经服务端校验后才可采纳 | 严格校验结构、时间半开区间与标签合法性；拒绝错误格式、越界、非法标签及过期来源；重叠等冲突明确反馈，不静默截断 |
| V34-FR-003 | 预标注智能初始化呈现与人工安全编辑 | 经校验完整合规的动作候选，在标注员首次打开未编辑任务时自动铺设为初始轨道草稿，标注员免去手动载入点击直接进行时间微调；若候选存在冲突、部分失败或来源失效，不发布可采纳候选；显示原因，支持人工从零标注或授权重试；任务若已有历史编辑或已提交版本，绝不静默覆盖；人工可自由微调时间、修改标签、增删、拆分、合并与撤销 |
| V34-FR-004 | 人工提交与复核保持原规则 | AI 不直接写正式标签；保留旧版本；过期候选不能冒充当前结果 |
| V34-FR-005 | 复用配套导出 | 所选记录全部通过最终准入后生成原有 HDF5；失效项沿用 fail-closed 规则 |

采用“合格自动派发与初始化，异常手动兜底，已有工作防覆盖”策略。4090 每卡采用单消费者串行执行，并限制实际输入预算；串行只降低并发争抢风险，不保证无 OOM。

在现有标注面板实现，遵守[设计系统](../../../../DESIGN_SYSTEM.md)和[前端 UX 规范](../../../../architecture/web-ux-and-frontend-guidelines.md)：

- 时间轴联动视频；支持拖动边界，也提供输入时间、设为当前播放时刻等非拖拽操作。
- 所有空白可见，可按时间顺序导航候选与空白，并连续浏览；短空白不得因固定阈值消失。
- 错误长片段内部也可能漏动作，允许定位后拆分；播放过不等于人工确认过。
- 保留 Tab 原生焦点导航；快捷键不干扰输入框，提供按钮等价操作；状态不只靠颜色表达。
- “无候选”“部分窗口失败”“解析失败”分别反馈；首版不把部分输出作为完整草稿。

### 3.1 “合格自动、异常手动”的边界

| 判定对象 | 合格意味着什么 | 自动化范围 |
| --- | --- | --- |
| 视频与任务 | 媒体就绪、主视频与 schema 有效、已有人工任务且当前质检准入 | 自动派发一次预标注 |
| AI 候选 | 来源有效、所有窗口成功、结构与区间校验通过 | 在未编辑任务中自动呈现待确认草稿 |
| 动作内容 | 是否看对、是否漏标、边界是否准确 | 首版仍由人工检查、提交并按原规则复核 |

候选校验通过不证明识别正确，不按模型自报置信度自动批准。有效空数组表示本次模型未给出候选，不证明视频无动作；人工仍须检查全部视频与空白。

自动派发以条件同时成立为准，覆盖先建任务后质检、先质检后建任务以及主视频就绪的不同顺序；同一任务、输入版本、schema 及推理配置不得因重复事件重复派发。无人工任务不自动创建任务。手动触发只绕过自动调度条件，不绕过权限、媒体/隐私准入、来源校验、人工提交或导出守卫。

“未编辑”同时检查服务端版本和当前页面未保存的改动；用户清空过草稿也算编辑。候选晚到或版本变化只提示，不覆盖；来源在呈现、采纳和提交时均重新检查。部分失败输出仅供诊断，不提供首版选择性采纳，以避免把缺失片段误当成无动作。

## 4. 实现与导出边界

Core API 管理权限、作业事实、校验与持久化；Python Worker 只推理并回传结果，不直接写业务表。复用现有作业和模块边界，不新增微服务、通用工作流或模型服务平台。

实现前审计既有 `CandidateAnnotation` 和 job 类型扩展点，区分动作候选与 MediaPipe evidence，避免手部查询或导出误读动作结果。`action-candidate.v1` 仅为拟议契约名，尚未落地；实施时同步 OpenAPI、所需 Schema、兼容性及模块测试。

现有 [HDF5 服务](../../../../../services/core-api/src/main/java/com/medicationvideo/platform/datasetexport/HumanDemonstrationHdf5ExportService.java) 已按区间关联样本，继续遵守 [V1.31](../V1.31/配药视频数据处理平台需求文档_V1.31.md)：

- 使用当前输入下符合条件的已复核人工 revision；校验主视频、哈希、机器证据来源和权限，不只靠时间戳配对。
- `samples` 每行是主视频中落入已审核区间的一条现有 MediaPipe 手部样本，含标签、时间与 `landmarks[21,3]`。不是每个视频帧都有一行，未检测到手时不补造坐标。
- 参考机位保留既有来源信息，不自动同步、不复制主视频标签。21×3 数组不代表经标定的真实世界三维轨迹。
- 文件为平台自定义 `human-demonstration-hdf5.v1`，不含 MP4 字节，不新增格式，不承诺生成耗时。

## 5. RTX 4090 部署方案（待实测）

| 项目 | 初始选择 | 依据与限制 |
| --- | --- | --- |
| 模型 | Qwen3-VL-8B-Instruct | 官方有视频推理能力；配药场景效果未知 [S1][S2] |
| 精度 / 并发 | BF16 / 1 | 先减少量化与并发变量，不预设 Thinking 或量化更优 |
| GPU | RTX 4090 24GB | 用户提供；整机可用显存与吞吐待测 |
| 系统内存 | 建议 32GB，64GB 更宽裕 | 工程预算建议，非官方最低配置 |
| 环境 | Python 3.12、CUDA PyTorch、Transformers、FFmpeg | Linux 或 Windows＋WSL2；匹配驱动，用 uv lockfile 固定实测版本 |
| 视频输入 | 先固定 15–30 秒片段、1 fps 基线，2 fps 作对照 | 仅试验起点；限制总视觉输入预算，短动作召回不足时调整 |

显存由权重、视觉编码、中间结果、KV cache 和运行时开销共同决定。按约 8B 参数、每参数 2 字节估算，权重量级约 16GB；这不是完整加载占用实测值，更不是视频推理用量。不得承诺“固定低于 22GB”或“杜绝 OOM”。

部署分三步：

1. 受控准备环境下载固定模型 revision，记录权重 SHA-256 与审批；存放在仓库外，运行时仅从本地路径加载，禁止自动下载。
2. 独立离线脚本处理合成片段并输出 JSON；记录模型、依赖、帧数、像素预算、生成参数、峰值显存、端到端耗时与错误。耗时包含解码、推理和解析。
3. 配置通过固定测试集后接 Worker。显存不足时限制输入、明确失败并保留人工入口；调整采样或模型后重新验证质量，不无限重试。

长视频分窗须保留原视频时间映射与边缘上下文。同名相交片段不能仅凭时间 IoU 自动合并，因为可能是重复动作；窗口、重叠和拼接规则由离线误差分析确定并记录。先测单轮基线，只有边界误差确实影响人工耗时时才加局部精修。

若 8B 在可接受输入预算下仍不满足资源或耗时要求，用 4B-Instruct BF16 做同集对照，再决定是否量化。首版不训练模型，人工修正不会自动更新权重。

开发、测试与 CI 只用合成数据，不接触真实患者视频、身份映射或生产系统；脱敏样本也需另行明确授权并隔离。既有 synthetic-only 导出边界不变。

## 6. 验证与实施顺序

### 6.1 离线可行性

先用 3–5 段合成演示视频验证输入、时间映射和输出链路，覆盖重复动作、快速动作、空白与遮挡。完成条件是结果可解析、时间可回查、失败可解释；此阶段不证明准确率、真实场景效果或节省工时。

### 6.2 最小集成

完成第 3 节闭环，按受影响组件验证候选格式与越界、标签版本不匹配、重试幂等、视频换源、部分失败、人工修改保护、权限、编辑和键盘操作；完成所变更 API/事件契约检查。

复用合成 fixtures 回读 HDF5，验证主视频、标签 revision、区间起点包含/终点排除、无匹配手部样本与 provenance 失效等边界。仅文档更新不执行应用测试。

### 6.3 人工减负试验

比较“从零标注”和“AI 草稿＋人工修改”，使用相同标签定义与独立质量复核。按人员、拍摄批次和难度分组；同一操作的切片和机位不得作为独立样本泄漏到调参集与评估集。交叉分配，避免标注员先记住同一视频答案。

| 指标 | 计算 / 报告方式 |
| --- | --- |
| 主要指标 | 人工总分钟 ÷ 视频总分钟；计入检查、补标、修改、提交、复核返工及因 AI 阻塞产生的等待 |
| 节省比例 | `1 − AI 辅助组每分钟人工耗时 / 纯人工组每分钟人工耗时` |
| 最终质量 | 独立复核漏标、误标、类别和边界误差；不能用平均耗时掩盖质量下降 |
| 模型诊断 | 同类片段一对一匹配后报告 precision/recall、时间 IoU、边界误差；未匹配片段计入漏检/误检 |
| 资源稳定性 | 峰值显存、端到端耗时、失败率、OOM 次数；同时报告样本量、分布和不确定性 |

对照前固定片段匹配阈值、边界容差和质量可接受差异，不得看完结果再改门槛。按完整视频或拍摄批次统计不确定性，不把相邻帧视为独立样本。

**减少至少 30% 人工耗时是试点目标，不是既有结论。** 质量门槛满足、耗时收益可信且失败可控后才建议扩大使用；样本不足则继续试验，不标记验收通过。合成结果仅证明该测试分布下的表现。
