# V1.29 Web / Contracts / Edge / Tools Runtime Surface 审计

日期：2026-09-04
范围：Web 路由、页面、API client、OpenAPI/JSON Schema、事件、Synthetic/Worker 调用、scripts、tools、运行手册。
基线：V1.29 是 DRAFT；它定义“数据组 → Media Probe → MediaPipe Candidate → 可选人工链 → `hand-landmarks.v1`”的目标边界，但不授权在本报告中删除或改变现有 runtime。当前实现仍包含 V1.28 的人工质量、Annotation、Review 与 Cleaning 链。

## 结论

当前公开、可运行的检测证据导出只有 `hand-landmarks.v1`，且 Web 在项目列表和数据组详情调用同一 preview/download 契约；没有发现第二条 current export runtime，也没有重新暴露 `training-data.v2`。`training-data.v2` 和旧 event manifest 仅出现在标明历史的资料、迁移语境或过期架构资料中，未发现当前 controller、OpenAPI path、Web route、Worker 或 synthetic caller。

Web 的主要不一致是呈现而非底层接入：`CaptureGroup` 被系统性叫作“配药事件”，详情把人工质量、标注、复核、清洗推导成默认五阶段流程，列表为每组额外读取 group quality 与 AnnotationTask；同时左侧导航和 `/annotation-tasks` 又重复展示相同 CaptureGroup 的任务。它与 V1.29 “人工链可选”不一致，但现在确实有真实 Web、OpenAPI、Java、synthetic 和测试 caller，不能孤立删除 API 或实体。

`external-video-ingest-v2` 是仓库内唯一实际 edge/synthetic 发送版本，并且是显式 receipt finalization 与缺失机位声明所需版本。V1 endpoint/schema/runtime/test 仍存在，但仓库没有 V1 发起方；它是公开兼容面，缺少外部调用库存，不能据此安全删除。

`capture-group-quality-qualified.v1` 的 Java domain event 仍在同一事务内驱动“一次合格 → 一个 AnnotationTask”。其 JSON Schema 没有发现 broker/outbox/Worker/Web consumer；这是一份未接线的外部事件契约。必须先由产品决定 human-ground-truth policy，再一并停止默认派单、更新 Java/Web/OpenAPI/synthetic。不能仅删 schema 后保留强制派单。

## 方法与证据边界

- 读取了 V1.29 DRAFT、`v1.29-data-group-workflow-audit.md`、`v1.29-ingest-ai-pipeline-audit.md`，以及当前 main 的 Java/TypeScript/OpenAPI/JSON Schema、Worker、Synthetic、scripts、runbook 与测试引用。
- 使用 `rg` 追踪 endpoint、schema version、事件名、导出名、调用者和测试；未接触真实视频、真实账户或外部服务，也未运行全量质量门禁。
- “无仓库调用者”不等于没有外部调用者。对公开 API/schema，除非已有弃用窗口、consumer inventory 与迁移计划，结论为 `UNCERTAIN` 或保留兼容，绝不据此直接删除。
- 分类仅使用：`KEEP_CORE`、`KEEP_SUPPORT`、`SIMPLIFY_NOW`、`DELETE_CANDIDATE`、`HISTORICAL_ONLY`、`UNCERTAIN`。

### 契约与实现核对

- OpenAPI 记录了 V1/V2 manifest、CaptureGroup、人工链、media/AI worker 和 `hand-landmarks.v1`；controller mapping 与上述 route 族存在对应实现。关键 HTTP contract 有 MockMvc 覆盖，例如 External Ingest、CaptureGroup/Annotation、Media/AI、hand-landmarks。
- 本次定位到的 repo-orphan public 面不是“可删 API”：V1 manifest、raw media-job operator APIs 和 `GET hand-pose-detections` alias 分别仍有兼容、运维或未知外部消费者风险。唯一可直接提出删除候选的是未接线的 `capture-group-quality-qualified.v1` JSON Schema；其 Java domain event 不在候选内。
- `scripts/quality-gate.{ps1,sh}` 只会对 OpenAPI 做 lint（PowerShell `:236-246`），不会把 OpenAPI 每个 operation 与 Spring mapping/response 自动对比。因此“未发现路径缺失”是静态审计结论，不是 generated-contract 的证明。
- `capture-group-quality-qualified.v1.schema.json` 被 `quality-gate.config.json` 列为被校验的 JSON Schema，但没有找到 schema validator 对 Java `CaptureGroupQualityQualifiedEvent` 的 payload 测试，也没有 outbox/RabbitMQ serializer/consumer。它不能被描述为对外投递中的 event contract。

## `capture-group-quality-qualified.v1`：生产、消费与强制派单

实际流如下：

```text
PUT CaptureGroup quality = admitting
  -> CaptureGroupQualityReviewService.publishEvent(...)
  -> @TransactionalEventListener(BEFORE_COMMIT)
  -> CaptureGroupAnnotationWorkflow.assignAfterQuality(...)
  -> create or refresh exactly one AnnotationTask
```

证据是 `CaptureGroupQualityReviewService.java:153`、`CaptureGroupQualityQualifiedTaskListener.java:22-24` 与 `CaptureGroupAnnotationWorkflow.java:92-129`；OpenAPI 也在 `openapi.yaml:3106-3108` 明说合格会原子创建一个 AnnotationTask。Web 同时依赖 task 查询来驱动列表 next-step 和详情 rail，Synthetic 完整验收在 `tools/synthetic-capture-group-client/index.mjs:220-321` 断言任务必然出现，Java 合同测试还验证 requalification 复用该任务。

结论：

- Java **in-process domain event**：`SIMPLIFY_NOW` 的目标是将“无条件派单”改为 project human-ground-truth policy 条件，而不是删除质量/审计事实或把 AI 变成人工结论。
- JSON Schema `contracts/events/capture-group-quality-qualified-v1.schema.json`：`DELETE_CANDIDATE`。它没有发现 transport producer/consumer，现有 Java listener 也不读取 JSON；删除须与 quality-gate 配置和任何已确认的外部文档一并处理。
- 当前 runtime 中“每个合格组必有 AnnotationTask”：`KEEP_SUPPORT`，直到 policy、Web、OpenAPI、Synthetic 和 tests 同步迁移。此项不是 V1.29 已生效行为。

## `hand-landmarks.v1` 唯一 current detection export 核验

- Runtime producer 是 `datasetexport/HandLandmarkTrainingExportService`（`SCHEMA_VERSION` at `:37`）和 controller 的 `/preview`、`/download`；OpenAPI 的 schema const 在 `openapi.yaml:6956`。
- Web 只有 `apps/web/src/api/hand-landmarks.ts` 的两调用，列表/详情只传可选 `capture_group_id`，是同一契约的两个范围；Java `HandLandmarkTrainingExportContractTests`、Web `HandLandmarkApi`/button tests 与 Python CSV readback 都有实际证据。
- `README.md:20`、`production-readiness.md:128,175` 均确认它同步、只读、不持久化 export object，且不读取人工质量/Annotation/Review/Cleaning。
- 搜索没有找到 `training-data.v2` preview/download controller、OpenAPI path、Web route/API client、Worker caller 或 synthetic current caller。旧 `training-data.v3` 只在历史文档中出现，当前 V1.29/DRAFT 和 README 都不把它作为产品路径。

结论为 `KEEP_CORE`：`hand-landmarks.v1` 是唯一 current detection evidence export；它仍不是 human ground truth、训练 consumer 或模型效果证明。

## 调度相关核对

`ClipAssetMediaIngestService`、`CaptureSessionIngestService` 和 `PlatformLocalCaptureSessionService` 都调用同一 `HandPoseSchedulingPort.scheduleAfterMediaIngested`（分别见 `ClipAssetMediaIngestServiceTests.java:42`、`CaptureSessionIngestService.java:285`、`PlatformLocalCaptureSessionService.java:109`）。`HandPoseAutoSchedulingService` 在 commit 后以 `REQUIRES_NEW` 调现有幂等 job service，并吞掉辅助能力的 eligibility/dispatch 异常，不改变已提交 media 状态。

- `PlatformLocalCaptureSessionServiceTests.java:58` 断言 N=1、已 `INGESTED` asset 会补调度；`HandPoseAutoSchedulingServiceTests.java:33-77` 覆盖 after-commit 与异常隔离；`ClipAssetMediaIngestServiceTests.java:42` 覆盖媒体完成路径。
- `CaptureSessionIngestService.create` 已在保存 streams 后对当时 `INGESTED` assets 调度，因此此前“只在 probe completion 一侧调度”的缺口**当前代码看来已修复（CURRENT CODE APPEARS FIXED）**。
- **FOLLOW-UP: regression coverage**：没有找到一个真实数据库并发/事务交错测试，同时覆盖“CaptureSession 读取到 `UPLOADED`、probe 在 stream commit 前变为 `INGESTED`、commit 后只产生一个 AI job”。这不是 P0 重提；后续改动调度时补一个定向 integration regression test 即可。

## SAFE SIMPLIFICATION

1. 在批准 V1.29 runtime 变更后，将默认 Web/Runbook/Synthetic 验收收敛为数据组接收、Media Probe、MediaPipe Candidate、`hand-landmarks.v1`；不读取/不强制展示 task、quality、Review、Cleaning。
2. 将用户可见“配药事件”替换为“数据组”，保留 `CaptureGroup` 作为技术 ID。先改文案与默认 action，不引入新的 DTO、持久化 workflow 或 project-policy framework。

## 风险与 Coordinator 决策

1. **human-ground-truth policy 的最小表达**：谁/何时声明项目需要人工标签？没有这一决定，不能正确停止默认 `CaptureGroupQualityQualifiedEvent → AnnotationTask`，也不能安全隐藏任务入口。优先确认产品规则，再决定是否需要最小现有项目配置字段；不要先建通用流程引擎。
2. **兼容期**：V1 manifest 与 duplicate GET 的外部 client 情况仓库不可见。决定是否发布弃用、如何观测调用、何时删除；在此之前它们是 `UNCERTAIN`，不是可立即删除项。
