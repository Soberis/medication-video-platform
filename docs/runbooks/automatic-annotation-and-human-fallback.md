# 自动标注、修改与提交

状态：V1.35 当前运行手册。媒体就绪后的 Action Candidate 自动派发已接线；真实 Worker 推理、候选质量和生产运行仍须分别验收，不能从本文推断已上线。

## 正常路径

1. 视频完成接收和 Media Probe 后，后台扫描会为 ACTIVE 项目的有效视频自动派发 Action Candidate；不要求人工任务、负责人、人工质量或打开页面。
2. MediaPipe 与 Action Candidate 独立处理。已有人工任务使用绑定 schema；无任务时使用派发时冻结的全局已发布 schema。
3. 完整有效候选初始化未编辑的草稿；用户无需逐段采纳，可检查后直接提交或先局部修改。候选失败或为空时仍可进入人工从零标注。
4. 进入人工提交路径时，授权用户准备或复用 CaptureGroup AnnotationTask；显式提交整份标注，产生不可变 Revision，再按现有权限复核。符合条件的管理员可以复核自己的提交。
5. 从项目列表选择记录导出；后端复验当前批准 Revision 和媒体/MediaPipe 证据。历史 Cleaning 只读展示，不再产生新的 Cleaning 事实或 recheck 结果。

保存草稿、AI 成功、打开页面均不等于提交。提交不自动批准或下载，不新增机器批准枚举。

## 异常处理

| 情况 | 处理 |
| --- | --- |
| 没有动作候选 | 显示有效空结果，允许从零标注，不推断没有动作 |
| MediaPipe 成功无手 | 保留成功状态；没有区间内样本时最终导出拒绝，编辑与提交仍可进行 |
| 查询失败 | 重试读取，不能把 job 改为 FAILED 或显示有效空结果 |
| 部分窗口失败 / 非法标签 / 越界 | 不初始化完整草稿；保留错误原因，允许重试或人工标注 |
| confidence 缺失 | 不伪造数值，不单独判失败；有值也不证明标签正确 |
| 候选晚到或人工已编辑 | 保留人工内容，提示新候选，禁止静默覆盖 |
| 租约失效 / Worker 重启 | 使用既有 retry、attempt、inbox/outbox；拒绝旧执行覆盖 |
| 导出失效 | 显示具体原因，保留选择；整批拒绝，不静默跳过 |

## 验证与观测

使用合成数据测试正确草稿直接提交、修改后提交、空结果、无手、部分失败、换源、schema 变化、重复回传和未提交不可导出。真实标签质量另用获准的独立样本评估。

记录有效草稿比例、人工修改比例、人工总耗时、候选质量和失败原因。无需新增批准策略或逐字段摘要；复用视频/模型身份、schema、job/attempt 和既有审计。
