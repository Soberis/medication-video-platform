# 配药视频数据管理平台设计简报

## 定位

这是一份 Web 管理端视觉简报，只回答界面应呈现什么气质、如何组织信息。API、权限、状态与验收规则以[需求基线](./requirements/README.md)和[前端体验规范](./architecture/web-ux-and-frontend-guidelines.md)为准。

用户是管理护士配药视频数据的项目管理员和项目成员。界面的核心任务是帮助用户快速确认：一次配药操作是否完整、当前处于什么状态、下一步能做什么。

## 设计方向：克制的临床作业台

界面应像可靠、可追溯的操作记录，而不是监控大屏或消费视频站点。

**状态比装饰重要，证据比印象重要，操作比页面效果重要。**

平台的识别性来自真实对象关系：`项目 → 配药操作 → 相机流 → 视频资产 → 处理状态`。只有存在真实顺序或归属时才使用编号、时间线和连线，不增加纯装饰结构。

## 视觉语言

沿用当前蓝灰色系，不额外引入字体、图片或视觉依赖。

| 角色 | 值 | 用途 |
| --- | --- | --- |
| 页面底色 | `#f3f6fa` | 长时间操作的低干扰背景 |
| 内容墨色 | `#172033` | 标题与主要事实 |
| 主操作蓝 | `#2f5ec4` | 主要按钮和链接 |
| 成功绿 | `#12643b` | 已完成、校验通过 |
| 风险红 | `#b42318` | 删除、失败和高风险动作 |
| 分隔灰 | `#dce3ee` | 表格、卡片和层级边界 |

- 正文使用系统无衬线与中文回退字体；ID、摘要和错误码使用等宽字体。
- 状态必须有文字，颜色只作辅助。
- 圆角、阴影和动效弱于内容层级；不用渐变、装饰插画或“科技感”背景替代信息。

## 信息层级

```text
项目
└── 配药操作（默认入口）
    ├── 相机流完整性与处理状态
    └── 单路视频资产（排障时下钻）
```

- 列表优先展示状态、时间、完整性和异常，缩略图不是默认信息中心。
- 详情先说明对象、所属项目和当前状态，再展示来源、技术摘要和可执行动作。
- 每个任务区域只有一个视觉上的主要动作；高风险动作与普通动作分开。
- 笔记本、1080p、2K 和 4K 使用同一桌面工作台语言；宽屏扩大有效工作区，但不无限拉长正文、放大控件或增加装饰信息。
- 当前 P0 不以手机端为验收目标；已有窄屏回退不应影响桌面信息层级，也不代表移动端兼容承诺。

## 交互语言

- 使用用户能理解的动词，如“进入项目”“上传视频”“重新加载”“删除视频”。
- 按钮、确认框和结果提示对同一动作使用同一名称。
- 空态和失败态说明原因与下一步，不只显示“暂无数据”或“操作失败”。
- 新页面开始实现前，只需明确用户、单一任务、必要状态和完成条件。

## 非目标

- 不把平台设计成实时监控室、视频娱乐平台或药品识别系统。
- 不因设计简报创建空页面、假图表、假缩略图或不可执行按钮。
- 没有真实需求时，不引入独立设计系统、字体服务、动画库或图表库。
- 视觉设计不改变权限、状态机、审计和数据安全边界。
