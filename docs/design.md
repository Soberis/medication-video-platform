# 配药视频数据管理平台：设计简报

## 1. 定位

这是一份面向 Web 管理端的视觉与交互设计简报。它回答“界面应当呈现什么气质、优先帮助用户完成什么”，不定义 API、权限、状态机或数据库字段。

业务与实现规则仍以[需求基线](./requirements/README.md)和[前端体验规范](./architecture/web-ux-and-frontend-guidelines.md)为准；发生冲突时，后两者优先。

## 2. 用户、对象与单一目标

- **用户**：管理护士配药视频数据的项目管理员和项目成员。
- **核心对象**：一次配药操作是一个 `CaptureSession`；视频是该操作下的单路 `ClipAsset`。
- **界面的单一目标**：让用户在最少认知负担下确认“这次配药操作是否完整、目前处于什么状态、下一步能做什么”。

因此，默认入口是项目和配药操作，而不是无上下文的视频墙。

## 3. 设计方向：克制的临床作业台

界面应像一份可靠、可追溯的操作记录，而不是监控大屏、消费视频站点或炫技仪表盘。

设计主张：**状态比装饰重要，证据比印象重要，操作比页面效果重要。**

唯一的识别性表达是“**操作证据线**”：在 Session 详情中，按真实顺序组织“配药操作 → 相机流 → 视频资产 → 处理状态”。它只在对象之间确有顺序和归属关系时出现，不把编号、时间线或连线作为装饰。

## 4. 视觉令牌

沿用当前前端已使用的克制蓝灰色系，不额外引入字体、图片或视觉依赖。

| 角色 | 值 | 用途 |
| --- | --- | --- |
| 页面底色 | `#f3f6fa` | 降低长时间操作的视觉疲劳 |
| 内容墨色 | `#172033` | 标题、主要事实与可读性基础 |
| 主操作蓝 | `#2f5ec4` | 主要按钮、可操作链接 |
| 状态蓝 | `#3867d6` | 当前范围、普通进行状态与辅助强调 |
| 成功绿 | `#12643b` | 已完成、校验通过；必须同时显示文字 |
| 风险红 | `#b42318` | 删除、失败、不可恢复风险；不用于普通提醒 |
| 分隔灰 | `#dce3ee` | 表格、卡片和层级边界 |
| 次要文字 | `#667085` | 说明、时间、辅助事实 |

- 正文字体使用系统无衬线与中文回退字体；ID、摘要和错误码使用等宽字体。
- 圆角、阴影和动画应弱于内容层级，不构成界面记忆点。
- 不使用渐变、装饰插画、自动播放、模拟仪表盘或“科技感”背景替代状态说明。

## 5. 页面结构

```text
项目
└── 配药操作（Session，默认工作入口）
    ├── 相机流完整性与处理状态
    └── 单路视频资产（需要排障时下钻）
        ├── 元数据与文件夹
        └── 仅在能力获准后出现的操作
```

- **列表页**：先显示可判断下一步的事实；筛选、状态、时间和异常优先于缩略图。
- **详情页**：标题区说明对象、所属项目和状态；事实卡片按“当前状态、来源、技术摘要、可执行动作”组织。
- **高风险动作**：与普通动作分组隔离，使用明确动词和影响说明；不能只凭红色或弹窗标题表达风险。
- **空态和失败态**：说明原因与下一步。例如“当前身份未加入项目”比“暂无数据”更有用。

## 6. 交互与文案

- 动作使用用户能理解的动词：`进入项目`、`上传视频`、`重新加载`、`删除视频`；同一操作在按钮、确认框和结果提示中使用同一名称。
- 先展示状态文字，再用颜色、图标或位置辅助；枚举英文码只在详情与排障上下文保留。
- 页面不得凭本地计时器伪造上传、作业或审批成功；刷新后应回到服务端事实。
- 加载、空、成功、失败和无权限是正常页面状态，必须有清晰反馈和键盘可达的下一步。
- 移动端优先保留状态、完整性和关键操作；可以重排或横向滚动，不能静默隐藏关键字段。

## 7. 组件使用边界

- 优先使用现有 Vue、Element Plus 和浏览器原生控件；相同控件出现重复实现时才提取组件。
- 页面局部数据保持局部状态；没有跨路由的真实需求时，不建立 Pinia Store。
- 不因设计文档存在而创建空页面、空组件、假图表、假缩略图或不可执行按钮。
- 每个新页面先写出：用户、单一任务、状态来源、失败恢复方式和一个可验证的完成条件；再开始实现。

## 8. 设计验收清单

- 用户能在 5 秒内识别当前项目、对象和主要状态。
- 关键操作可通过键盘到达，焦点、错误和结果反馈可感知。
- 颜色不是唯一信息来源；错误不泄露内部地址、令牌或堆栈。
- 一页中只保留一个主要动作；高风险操作有明确对象、影响和理由。
- 新的视觉效果能够解释其业务作用；不能解释的效果应删除。
- 设计改动仍通过现有 `lint`、`type-check`、单元测试和构建门禁。

## 9. 非目标

- 不把平台设计成实时监控室、视频娱乐平台或药品识别系统；
- 不在当前阶段引入独立设计系统、字体服务、动画库、图表库或图片生成依赖；
- 不以“更漂亮”为由改变权限、状态机、审计或数据安全边界。
