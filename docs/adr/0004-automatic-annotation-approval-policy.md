# ADR 0004：自动生成标注草稿，人工可修改并显式提交

日期：2026-09-15
状态：当前需求决策；2026-09-16 明确媒体就绪即自动派发，真实 Worker 联调仍须独立验收。
依据：[V1.35](../requirements/baselines/V1.35/配药视频数据处理平台需求文档_V1.35.md)。

## 决策

系统自动完成媒体处理、动作候选生成和初始草稿准备。正确的片段无需逐段点击采纳；用户检查后可直接提交整份草稿，也可先修改。最后提交必须是授权用户的显式操作。

沿用 Candidate → 草稿 → AnnotationRevision → AnnotationReview APPROVED → Export Eligibility → HDF5。不增加机器批准对象或新状态枚举。提交与现有复核分开，满足权限的管理员可复核自己的提交；本次不合并接口。

所有 ACTIVE 项目中的有效媒体就绪视频默认自动派发 Action Candidate，不要求人工任务、负责人或人工质量批准，也不等待 MediaPipe。无人工任务时冻结当前已发布全局 schema，有任务时保留绑定版本。人工分配、质量、提交、复核与导出守卫留在人工及导出步骤；系统只创建机器作业与候选。多机位分别分析，不混用时间轴。

## 依据与简化

结构合法、schema 匹配、来源一致、检测到手只能证明结果可处理，无法证明动作类别和时间边界正确。模型 confidence 可缺失；有值也不是校准正确率，不凭它跳过提交或复核。

保留已有输入身份、schema 版本、job/attempt 与可靠性约束，复用已有摘要；不增加逐字段哈希、评分路由或通用工作流。模型质量需通过独立样本评估，不能从合成流程测试推断。

## 编辑与提交

2026-09-21 按用户确认简化人工权限：ACTIVE 项目成员可查看、编辑和提交本项目任务；管理员另外可复核，包括复核自己的提交。负责人保留为归属记录，不限制操作。首次任务可由成员显式为自己准备，已有任务复用；为他人分配及刷新变化的输入仍由管理员执行。项目隔离、版本冲突和审计继续生效。

- 完整且当前有效的候选仅可初始化从未编辑的任务；服务端版本与浏览器未保存内容均受保护，清空也算编辑。
- 候选晚到、重试或更换模型不得覆盖人工工作或已提交 Revision。
- 空结果与失败分开显示，支持人工从零标注。AI 失败不禁止人工提交合法标注。
- 显式提交产生不可变 Revision；复核拒绝后提交新版本，保留历史。
- 下载仍需后端验证当前批准 Revision、媒体、MediaPipe 与既有准入。

## 验收

验证正确草稿整份提交、局部修改、空草稿、失败恢复、迟到不覆盖、重复提交、越权提交和未提交不可导出。分别报告草稿可用率、人工修改比例、最终标签质量和人工总耗时。

本决策取代本文件先前的“默认自动批准、异常转人工”草案。D1–D5 维持原范围。
