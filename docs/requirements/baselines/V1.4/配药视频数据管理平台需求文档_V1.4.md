# 配药视频数据管理平台需求基线 V1.4

> 文档版本：V1.4
> 文档状态：当前基线
> 生效日期：2026-07-22
> 前一版本：V1.3
> 生效规则：本版本继承 V1.3；本版本明确修改的条款优先于 V1.3、V1.2 和其继承的 V1.1.13。

## 1. 本次变更

平台是内部训练数据管理工具。医院现场相机和 RK3588 边端只负责采集并自动上传；医院人员不使用 Web 管理端。平台内部人员需要直接查看技术校验通过的视频，判断数据是否适合保留、标注和进入训练数据集。

主业务流程调整为：

```text
医院现场相机 / RK3588 边端程序
→ 自动上传视频、采集元数据和事件日志
→ 平台完成对象完整性和媒体可读性检测
→ 项目成员播放并人工判断数据质量
├── 合格：进入人工标注与独立复核
├── 不合格：记录原因并排除或由管理员删除
└── 发现异常敏感内容：隔离并停止后续使用
→ 复核通过的正式标签进入清洗、数据集冻结和导出
→ 后续机器算法仅生成候选标注，仍需人工确认和复核
```

本次明确修改：

1. 采集规范应避免患者、姓名、病历号、屏幕信息等可识别内容；在此前提下，隐私评估不再是每条视频播放前的强制门槛。
2. 视频完成对象完整性和媒体可读性检测并进入 `INGESTED` 后，当前项目的 ACTIVE 成员可申请短期只读地址并直接播放原始视频，用于数据质量审核和标注准备。
3. 播放授权仍必须校验登录会话、项目 Membership、资产状态、删除/隔离状态和媒体类型；地址短时有效、不得落库，并记录授权审计。不得公开对象存储地址或把签名地址当作长期下载链接。
4. 人工质量判断先于正式标注。第一版以人工标注和独立人工复核形成可信标签；机器标注属于后续提效能力，只能写入候选标注，不能自动成为正式标签。
5. 若审核时意外发现敏感或可识别信息，应立即停止正常播放、标注和数据集使用并进入隔离处理。该机制是异常兜底，不是所有视频的默认放行流程。

## 2. 视频查看与质量筛选

### 2.1 播放条件

- 用户已登录且账号有效。
- 用户具有目标项目的 ACTIVE `ADMIN` 或 `MEMBER` Membership。
- `ClipAsset` 已完成媒体探测，状态为 `INGESTED`，未被软删除且没有活动隔离。
- 当前首版播放器支持浏览器可直接播放的 MP4；不支持的编码或封装返回稳定错误，不自动降级为公开下载。
- 每次播放由用户显式触发；服务端签发短期、只读、`no-store` 的对象地址并记录项目、用户、资产版本、用途和请求标识，不记录签名 URL。

### 2.2 人工质量判断

人工质量判断回答“这段数据是否适合后续训练”，不承担诊疗或用药判断。最低结果为：

| 结果 | 含义 | 后续动作 |
| --- | --- | --- |
| `QUALIFIED` | 画面、时序、操作内容和采集完整性满足当前项目规则 | 可创建人工标注任务 |
| `REJECTED` | 明确不满足规则，例如严重遮挡、关键动作缺失、损坏或错误场景 | 记录稳定原因并从训练候选中排除；管理员可按保留策略软删除 |
| `NEEDS_REVIEW` | 信息不足或边界情况 | 交由另一名内部人员复查，不进入正式标注 |

质量规则必须按项目和版本管理。媒体探测通过只证明文件可读取，不等于业务质量合格；人工播放也不自动改变质量状态。

## 3. 标注、复核与机器候选

1. 仅 `QUALIFIED` 视频可进入正式人工标注任务。
2. 标注结果以不可覆盖的 Revision 保存；标注提交人与复核人应为不同人员。
3. 复核通过的 Revision 才能进入清洗和数据集候选；驳回时必须保留原因并产生新修订，不能覆盖历史证据。
4. 在标签规范稳定、已有复核通过的基准样本并完成离线评估前，不启用 MediaPipe 或其他模型作为生产标注来源。
5. 机器结果只进入 `CandidateAnnotation`；人工确认后才能形成新的正式 Revision，并再次经过独立复核。

| 编号 | 类型 | 需求 | 最低验收 |

V1.3 的内部账号、边端自动上传与两级角色，V1.2 的项目、文件夹、本地测试上传和软删除，以及 V1.1.13 中未被本版本修改的上传、标注、清洗和数据集要求继续有效。

## 5. 验收场景

1. 普通项目成员和项目管理员都能在视频 `INGESTED` 后显式获取短期播放授权并使用浏览器播放；未加入项目的用户不能通过构造 URL 越权。
2. `UPLOADED`、`INGESTING`、`INGEST_FAILED`、已删除、活动隔离或不支持的媒体不得签发播放地址，并返回稳定错误码。
3. 播放响应使用 `no-store`；数据库、应用日志和审计事件均不保存签名 URL。
4. 同一用户可在地址过期后重新申请；前端能清楚显示检测中、检测失败、授权过期和浏览器播放失败状态。
5. 人工将视频标记为 `REJECTED` 或 `NEEDS_REVIEW` 后，系统拒绝为其创建正式标注任务；`QUALIFIED` 视频才可进入人工标注。
6. 发现异常敏感内容后，活动隔离阻断新的播放授权、标注、机器候选、数据集和导出操作。
7. 机器候选不能覆盖正式人工标签；只有经人工确认形成新 Revision 并由另一人复核通过后，才可能进入数据集。

## 6. 实施边界

- 当前纵向切片实现 FR-039：项目成员直接播放、短期授权、状态提示和审计，并移除普通播放对隐私放行和派生 Variant 的默认依赖。
- FR-040 的质量判断状态、原因字典和审核页面是紧随其后的独立切片，不与播放授权混在同一事务或接口中。
- FR-041 继续属于 P1；P0 先完成纯人工标注、独立复核、清洗、冻结和导出闭环。
- 现有隐私评估和隔离能力保留为异常敏感内容处理工具，但不在视频详情页强迫每条数据先评估后播放。
- 项目改名和项目归档属于项目生命周期切片；已有视频、审计或数据集引用的项目不得物理删除。
