# 配药视频数据管理平台需求基线 V1.5

> 文档版本：V1.5
> 文档状态：当前基线
> 生效日期：2026-07-22
> 前一版本：V1.4
> 生效规则：本版本继承 V1.4；本版本明确修改的条款优先于 V1.4 及其历史继承基线。

## 1. 本次变更

第一版产品只交付训练数据管理主闭环：

```text
边端或平台本地上传
→ 媒体技术校验
→ 项目成员播放
→ 人工质量判断
→ 人工标注与独立复核
→ 清洗、冻结和导出训练数据集
```

为降低尚未验证的复杂度，P0 不建设专门的隐私评估、隐私放行、脱敏 Variant、隔离审批或自动隐私检测子系统。采集协议仍要求画面不包含患者身份、姓名、病历号、屏幕隐私等敏感内容；人工审核意外发现此类内容时，将视频判定为 `REJECTED`，记录固定原因，并由项目管理员软删除。

只有出现真实合规要求、真实敏感样本或外部数据共享需求时，才建立新的需求版本评估专门隐私能力。不得为未来假设提前保留未闭环的运行接口和页面。

## 2. P0 保留能力

- 内部账号、ADMIN/MEMBER 项目 Membership 和服务端权限检查；
- 边端自动上传和平台本地测试上传；
- Multipart、SHA-256、媒体探测和 MediaReport；
- 项目、文件夹、Session、ClipAsset 列表与详情；
- 项目成员短期审核播放；
- 人工质量判断、软删除和追加式审计；
- 人工标注、独立复核、清洗、数据集冻结和导出。

## 3. P0 删除或后置能力

- 删除未形成产品闭环的 PrivacyAssessment 和 Quarantine 运行 API、前端客户端与状态页面；
- 不生成 PREVIEW/DEIDENTIFIED Variant 作为播放前置条件；
- 不启用自动隐私检测、隐私放行审批、隔离解除、CVAT、MediaPipe、AI Worker 或多级角色；
- 历史数据库迁移不得删除或改写；已有空表允许保留，未来使用新迁移演进。

## 4. 需求调整

| 编号 | 调整 | 当前口径 |
| --- | --- | --- |
| FR-010 | P0 简化 | 不建设专用隔离区；敏感或明显不合格视频通过 FR-040 判为 `REJECTED`，再由管理员按 FR-035 软删除。 |
| FR-025 | 后置 | 自动隐私检测、脱敏和放行退出 P0；出现真实证据后另行立项。 |
| FR-039 | 保持 | ACTIVE 项目成员可播放媒体校验通过、未删除的 MP4；短期 URL 不落库并记录授权审计。 |
| FR-040 | 保持 | 人工记录 `QUALIFIED`、`REJECTED`、`NEEDS_REVIEW` 和稳定原因；仅 `QUALIFIED` 进入标注。 |
| FR-041 | 保持 P1 | 机器结果只生成候选标注，不能自动成为正式标签。 |

## 5. 最低验收

1. 合成视频能完成上传、媒体检测、项目内播放和软删除。
2. 普通项目成员可以审核播放，但不能管理成员、项目、文件夹或删除视频。
3. 视频质量结论与原因可追溯；`REJECTED` 和 `NEEDS_REVIEW` 不能进入正式标注。
4. 平台没有公开隐私评估、隐私放行或隔离 API，也不显示未实现的相关页面和提示。
5. 历史 Flyway 迁移在空库和升级库中仍可顺序执行；清理运行代码不得改写已发布迁移。
6. Java、Vue、Python、OpenAPI 和模块边界门禁通过后，才能宣布底座稳定。
