# 配药视频数据管理平台需求基线 V1.11

> 文档版本：V1.11
> 文档状态：当前基线
> 生效日期：2026-08-05
> 前一版本：V1.10
> 生效规则：本版本继承 V1.10；本版本明确修改的条款优先于 V1.10 及其历史继承基线。

## 1. 本次变更

平台当前由同一运营团队管理，不要求两位不同人员完成 P0 的人工审批闭环。平台账号
`ROLE_ADMIN` 在其拥有有效项目 `ADMIN` Membership 的项目内，可以由同一账号完成申请、
复核、冻结和导出审批；`ROLE_MEMBER` 仍不能执行任何项目管理员命令。

这是一项受限的单管理员运营规则，不是项目边界、审计或异步 Worker 身份的放宽：

1. `ROLE_ADMIN` 仍必须是目标项目的 ACTIVE `ADMIN` Member；全局账号角色不能绕过项目边界。
2. `ROLE_MEMBER` 只能保留既有成员范围内的读取、上传和被分配标注能力，不能创建/分配任务、
   记录管理员复核、冻结数据集、申请或批准导出，亦不能执行管理员受控重放或投递恢复。
3. 人工审批的 `requested_by`、`approved_by`、时间、决定、幂等键和追加式审计必须照实保存；
   当两者相同时，审计和 UI 必须明确标识为 `SELF_ADMIN_APPROVAL`，不得表述为“独立审批”。
4. Media Worker、Export Worker 仍使用独立机器身份和 attempt-scoped lease capability；本规则
   不允许 Web 管理员冒充 Worker，也不改变 Outbox、Inbox、DLQ、摘要校验或下载授权边界。

## 2. 受影响的 P0 工作流

在满足所有原有状态、证据、摘要、权限和幂等守卫的前提下，以下原先要求不同人工账号的
守卫改为允许同一 `ROLE_ADMIN` 账号执行：

1. 已提交 AnnotationRevision 的管理员复核；同一管理员可提交并记录 APPROVED/REJECTED，
   后置清洗仍按既有规则执行。
2. DatasetVersion 的冻结前 PASS 审批与冻结；同一管理员可创建/触发 validation 后批准并冻结。
3. 已冻结 DatasetVersion 的 `MODEL_TRAINING` 导出申请与批准入队；同一管理员可申请并批准，
   首个 ExportAttempt、Outbox 和审计仍须在同一事务创建。

本版本不要求自动审批、批量审批、审批旁路、成员提权、匿名访问或删除历史 ApprovalRequest /
ApprovalDecision。已有历史审批事实不改写；新代码只在上述命令被 `ROLE_ADMIN` 调用时允许
同人决定。

## 3. 最低验收

1. `ROLE_ADMIN` + ACTIVE 项目 `ADMIN` Membership 可以对自己发起的标注复核、冻结和导出申请
   成功完成；响应、审计和页面都真实显示申请人与审批人为同一账号及
   `SELF_ADMIN_APPROVAL`。
2. `ROLE_MEMBER` 对上述管理员命令一律得到既有稳定 403/409 权限错误，不产生审批、状态、
   Outbox 或审计副作用。
3. 缺少项目 Membership、Membership 非 ACTIVE 或项目角色为 MEMBER 的 `ROLE_ADMIN` 账号，
   仍不得访问其他项目或绕过项目管理员守卫。
4. 原有状态机、冻结证据重校验、导出文件/摘要验证、Worker 独立身份、租约、幂等、审计追加
   约束和下载短期授权继续通过回归测试。
5. OpenAPI、React 权限文案、Java 服务/合同测试和 UAT 手册同步移除“独立人工审批”的错误表述；
   不得把同人审批误记为独立审批。

## 4. 继承与冲突处理

除本版本明确替换的“不同人工账号独立审批/复核”要求外，V1.10 的全部条款继续有效。历史
基线、技术设计、OpenAPI 或运行手册中将管理员人工复核、冻结或导出审批表述为必须由另一位
管理员执行的内容，统一由本版本替换。Worker 服务身份独立性、项目隔离、审计不可变性和
数据完整性要求不受影响。
