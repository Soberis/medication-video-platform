# 配药视频数据管理平台需求基线 V1.13

> 文档版本：V1.13
> 文档状态：当前基线
> 生效日期：2026-08-10
> 前一版本：V1.12
> 生效规则：本版本继承 V1.12；本版本明确修改的条款优先于 V1.12 及其历史继承基线。

## 1. 本次变更

V1.12 已冻结 Ego 视频手部姿态候选标注的产品边界。V1.13 不扩大产品范围，只修订实施顺序：
在继续建设平台 AI Worker、候选存储和审核界面前，先用隔离的本地 PoC 验证 MediaPipe Hand
Landmarker 对第一人称配药操作视频是否具有足够的可用性。

实施分为两个明确阶段：

```text
Phase A：本地算法 PoC 和可测量效果验证
→ 人工评审试点报告并作出 GO / TUNE / REPLACE / STOP 决定
→ Phase B：接入 AIJob → CandidateAnnotation → 人工审核流程
```

Phase A 的 Overlay MP4 只用于观察和评估，不是正式标注、正式派生视频或训练数据。

## 2. FR-042A Ego 手部姿态本地 PoC

1. 工具接收本地 MP4、离线 `.task` 模型绝对路径和输出目录，不连接 Core API、PostgreSQL、
   RabbitMQ、S3 或医院系统。
2. 工具使用 MediaPipe Tasks API `HandLandmarker` 的 `VIDEO` 模式；输入为 RGB/SRGB，传给
   `detect_for_video` 的时间戳必须严格递增。
3. 默认对每个解码帧执行推理，以优先验证截图所示的连续骨架效果。可选采样只用于实验，范围为
   1–15 FPS，必须在输出中记录；它不改变 Phase B 已批准的固定 10 FPS profile。
4. 每帧最多输出两只手。每只手包含固定编号 0–20 的 21 个二维归一化图像关键点、
   `Left`/`Right`/`Unknown` handedness 候选、`handedness_score`、有效关键点数和由有效关键点
   生成的归一化 bbox。
5. `handedness_score` 只能描述左右手分类分数，不得称为通用 confidence、关键点置信度或 bbox
   置信度。Ego 视频是否需要交换左右手语义必须由 Golden Set 验证，工具只提供显式配置并记录事实。
6. Overlay MP4 在原分辨率画面上显示关键点、固定手部骨架连接和 `Left/Right +
   handedness_score`。bbox 默认只用于标签定位，不要求绘制。
7. 每个解码帧写一条 JSONL。未检测到手时写 `hands=[]`；因实验采样未执行推理时必须另写
   `inference_performed=false`，不得把“未推理”伪装成“无手”。
8. 输出同时保存帧序号、归一化视频时间戳和时间戳来源。优先使用容器 PTS；PTS 缺失时默认失败，
   只有用户显式允许才按标称 FPS 回退，回退必须告警并写入 summary。
9. 模型不进入 Git，运行时不得联网下载。工具计算并记录模型 SHA-256、MediaPipe 版本和全部推理
   参数。
10. `world_landmarks` 仅允许作为显式开启的研究调试输出；默认不保存，也不得描述为相机或房间
    坐标系中的真实三维手部位置。
11. PoC 必须在阻断公网出站的受控环境中执行，并记录断网运行和无连接尝试的验收证据。输入在本地
    处理不代表第三方运行时绝不会发送性能或使用指标，不能只凭代码中没有 HTTP 调用宣称零出站。

## 3. Phase A 输出

一次成功运行只生成三类文件：

```text
hand_pose_overlay.mp4
hand_landmarks.jsonl
run_summary.json
```

不默认导出逐帧图片，不把输入路径、视频帧、对象存储 key、令牌、人员身份或其他敏感信息写入
summary。第一版 Overlay 可以不复制音轨，但必须在 README 和 summary 中明确。

## 4. 科学评估要求

截图效果是视觉目标，不是模型质量证明。进入 Phase B 前必须使用合成数据或明确授权且隔离的脱敏
Ego Golden Set，覆盖至少以下分层：单手、双手、近距离、远距离、部分出画、双手遮挡、持药瓶、
持针筒、小物体抓取、快速运动、手背和手掌朝向。

最终评估必须在看结果前冻结统计口径和通过阈值，并按 session 聚类、按场景分层报告：

- 有手帧召回率、无手帧误检率；
- 双手帧完整检出率；
- handedness 准确率、左右手交换次数和出画后恢复时间；
- 关键点可用率及相对人工 Golden Set 的归一化误差；
- bbox IoU、候选接受/修改/拒绝率；
- Overlay 时间轴误差、失败率、处理吞吐和资源占用；
- 点估计、样本量和按 session 计算的置信区间。

不得用单个演示视频、官方样例或“画出了 21 个点”代替上述质量评估。Golden Set 数量和阈值由
业务方、标注负责人和算法负责人在正式评估前批准，不在缺少真实样本证据时编造数字。

## 5. Phase A 最低验收

1. 正常 CFR MP4 可完整输出 Overlay、JSONL 和 summary；输出分辨率与输入一致，时长偏差有记录。
2. 合成的 0、1、2 手结果均可序列化和渲染；21 个关键点编号和骨架拓扑有自动测试。
3. BGR/RGB 不混用；传入 MediaPipe 的数组明确为 SRGB。
4. PTS 正常时推理时间戳严格递增；缺失、重复或倒退时稳定失败，显式回退除外。
5. 模型摘要、参数、软件版本、时间戳策略、解码帧数和推理帧数均进入 summary。
6. `ruff format --check`、`ruff check`、`mypy` 和 `pytest` 通过；测试不依赖真实医院视频。
7. 模型、输入视频和生成输出均被 Git 忽略；程序不自动联网下载模型。
8. 使用至少一个获批 Ego 样本完成人工观察后，才能声称达到参考截图的实际效果。
9. 在阻断公网的环境中完整运行，并确认没有 DNS 或外连尝试。

## 6. Phase B 进入条件和边界

只有 Phase A 评估得到明确 `GO`，才继续实现平台接入。Phase B 仍遵守 V1.12：

```text
ClipAsset → AIJob/attempt → AI Worker → Core API
→ CandidateAnnotation → 人工确认/修改 → AnnotationRevision
→ Review → PostClean → DatasetVersion
```

AI Worker 不直接写数据库；机器输出不能直接写正式 revision 或进入数据集。Phase A 不修改正式
OpenAPI、Flyway、RabbitMQ、DatasetVersion、AnnotationRevision、Media Worker 或 Export Worker。
现有未完成的 AIJob 基础代码不能作为 MediaPipe 效果已经验证的证据，也不得在 Phase A 中继续扩张。

## 7. 非目标

本版本不增加动作分类、Step 自动识别、药品/剂量/SOP 判断、物体检测、永久 hand track ID、
DeepSORT/ByteTrack、实时摄像头推理、跨相机 ReID、三维重建、CVAT、Redis 或新微服务。

## 8. 冲突处理

V1.12 对正式平台候选流程的约束继续有效。总体技术设计中要求 `PrivacyRelease`、
`DEIDENTIFIED Variant` 或 Quarantine 才可运行 MediaPipe 的旧条款，与当前 P0 不运行专门隐私状态机
的规则冲突；Phase A 以“只使用合成或明确授权且隔离的脱敏本地样本”为准。Phase B 的正式资产
准入必须在接入前另行冻结，不能沿用冲突条款或自行猜测。
