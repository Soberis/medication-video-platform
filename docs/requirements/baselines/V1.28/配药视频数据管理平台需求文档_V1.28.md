# 配药视频数据管理平台需求基线 V1.28

状态：CURRENT
发布日期：2026-09-04
主题：单一 CaptureGroup 路径与唯一手部检测导出

## 1. 版本定位

V1.28 继承 V1.27 的 CaptureGroup、N=1 统一模型、媒体事实、人工闸门、权限、审计和 provenance 约束；本版本只收敛导出边界：产品只保留一个面向用户的手部检测事实导出 `hand-landmarks.v1`。

当前业务主链：

```text
Local Upload / External Ingest
→ CaptureGroup
→ CameraStream / ClipAsset
→ Media Probe
→ MediaPipe Candidate
→ per-view Quality
→ CaptureGroup Quality
→ one CaptureGroup AnnotationTask
→ AnnotationRevision
→ Review
→ deterministic CaptureGroup Cleaning
```

`N=1` 仍是一个 CaptureGroup 的一路 CameraStream，不创建第二条单视频流程。MediaPipe 只产生 Candidate evidence，不能改写人工质量、正式 Revision、Review 或 Cleaning。

唯一导出是独立的当前检测事实读取：

```text
CaptureGroup → CameraStream / ClipAsset → MediaPipe Candidate → hand-landmarks.v1
```

它不等待或读取人工质量、AnnotationRevision、Review 或 Cleaning；这些仍是业务闭环事实，不是手部检测导出的准入条件。

## 2. 唯一导出

`hand-landmarks.v1` 是唯一当前公开导出。它可以按项目导出全部当前视图，也可以按一个 CaptureGroup 导出该事件的视图；两者是同一契约的范围参数，不是两个产品。

- 每一行是当前有效 21 点 MediaPipe hand candidate；同一帧多手分别成行。
- 保留 CaptureGroup、CameraStream、camera、ClipAsset SHA-256、AI job/attempt、算法/模型/profile provenance 和源视频本地帧时间。
- 不包含 MP4、人工动作标签、人工质量、Review、Cleaning 或跨相机时间对齐。
- 仅当前成功且含手的 Candidate 产生行；无任务、排队、运行中、失败和无手状态只在预览计数中体现，不伪造空样本。
- 导出前必须校验当前视图、ClipAsset 和 Candidate provenance；无法证明时 fail closed。

## 3. 明确删除

以下内容不属于 V1.28 当前产品、API、OpenAPI、Web、合成验收工具或运行时：

- CaptureGroup eligibility/provenance manifest `training-data.v3`；
- `training-data.v3` preview、download 和 split validation；
- 任务页上的第二个训练数据导出入口；
- v3 专用服务、响应模型、客户端方法、测试和公开 schema。

V1.27 及更早版本的迁移文件、历史文档和历史测试记录只作为不可变审计材料保留，不构成兼容性承诺；V1.28 的 V75 forward migration 清除当前数据库中的旧 eligibility view，不删除 CaptureGroup、Review 或 Cleaning 事实。

## 4. 验收与边界

- CaptureGroup 主链、N=1/N>1 统一模型、人工闸门和模块所有权保持 V1.27 语义。
- Web 只展示 `hand-landmarks.v1` 导出；事件详情支持单事件范围，事件列表支持项目范围。
- OpenAPI 只公开 `hand-landmarks.v1` preview/download；不存在 v3 路由或 schema。
- 自动化测试必须验证唯一导出、项目/事件范围、21 点和 provenance fail-closed 语义；合成测试不等于真实 UAT。
- 不引入 workflow engine、DatasetVersion、CaptureSync、calibration、独立导出 Worker 或新的状态框架。
