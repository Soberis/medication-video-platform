# 配药视频数据管理平台需求基线 V1.12

> 文档版本：V1.12
> 文档状态：当前基线
> 生效日期：2026-08-10
> 前一版本：V1.11
> 生效规则：本版本继承 V1.11；本版本明确修改的条款优先于 V1.11 及其历史继承基线。

## 1. 本次变更

平台新增 P1 的 **Ego 视频手部姿态候选标注**。它使用经批准、离线部署的
MediaPipe Hand Landmarker，为单路 Ego 视频生成可人工审阅的手部候选；不改变 P0 的
人工 Step 标注、复核、清洗、DatasetVersion 或训练包导出规则。

本版本只交付双手二维姿态候选：每个采样帧最多两只手、左右手候选、21 个归一化图像
关键点、由关键点生成的 `human_hand` 边界框，以及可追溯的模型和参数事实。模型输出
不是正式标注，不得单独进入数据集或用于临床判断。

## 2. FR-042 Ego 手部姿态候选标注

1. 只有拥有 ACTIVE 项目 `ADMIN` Membership 的 `ROLE_ADMIN` 可以为属于当前项目、已完成
   上传完整性校验且未删除的单路 Ego `ClipAsset` 创建一次手部姿态 AI 作业；请求必须使用
   `Idempotency-Key`。
2. 作业输入固定 `clip_asset_id`、输入摘要、采样配置、算法/模型版本和模型 SHA-256；任一
   输入变化均创建新 AI 作业，历史结果不可覆盖。
3. Worker 使用 MediaPipe Tasks API 的离线 `VIDEO` 模式。每帧传入严格递增的
   `frame_timestamp_ms`；首个实现切片固定使用经过批准的 10 FPS profile。只有在有评估证据
   的后续 profile 版本中，才可经管理员明确选择 1–15 FPS，不能接受任意运行参数。
4. 每个候选帧最多包含两只手。每只手保存 `left`、`right` 或 `unknown` 候选、handedness
   score、21 个二维归一化图像关键点、有效关键点数、图像尺寸和由有效关键点包络生成的
   `human_hand` bbox。bbox 必须保存其 recipe 版本和 margin ratio。
5. 关键点的模型相对深度和世界坐标可作为 Worker 调试输出，但不进入正式数据集，不代表真实
   三维空间坐标，不用于跨相机关联或三维重建。
6. 候选页面必须在用户显式点击播放后叠加显示当前帧候选骨架、bbox、左右手和置信度；页面
   不预加载视频、不持久化短期播放 URL，且能显示候选为空、失败或低置信度的原因。
7. 管理员可以对一个候选逐条确认、修改或拒绝；确认/修改创建新的不可变正式手部姿态
   revision，并保留来源候选、操作者和时间。拒绝不改写候选。未经人工确认、复核和后置清洗
   的机器结果不得进入任何正式数据集。

## 3. 边界和非目标

1. 不进行实时摄像头推理、硬件控制、自动播放、自动 Step 识别、药品/剂量/SOP 判断、跨相机
   ReID、跨视角统一 hand ID 或三维手部重建。
2. 不从公网下载 MediaPipe 模型或 Python 依赖。模型文件由部署流程离线提供，必须有固定
   SHA-256、算法版本和批准记录。
3. AI Worker 不连接业务数据库；只能通过 attempt-scoped lease 从 Core API 读取已批准输入，
   并通过版本化结果契约回传候选。AI 输出只能由 `aicandidate` 写入
   `CandidateAnnotation`。
4. 开发、测试和 CI 只使用合成 Ego 视频或明确授权且隔离的脱敏样本；日志、候选响应和审计
   不得包含视频帧、对象存储 key、预签名 URL、令牌或真实身份映射。

## 4. 最低验收

1. 合成单手、双手、无手、遮挡和低置信度视频均能产生可追溯的稳定候选或稳定失败码；每个
   作业只使用其固定输入摘要和模型摘要。
2. 非管理员、跨项目、已删除或未完成上传的资产不能创建作业，也不产生 AIJob、Outbox、审计
   或候选副作用。
3. 同一 `Idempotency-Key` 与相同请求返回原作业；不同请求稳定冲突；同一输入/算法/采样配置
   的重复请求按契约去重。
4. Worker 结果必须校验 attempt、输入摘要、模型摘要、采样配置、帧时间戳递增性、关键点数量、
   坐标范围和 bbox 计算；无效结果不得写入候选。
5. 候选确认、修改、拒绝均保留追加式审计；只有确认/修改形成的正式 revision 才进入既有复核
   和清洗流程。
6. OpenAPI、事件 Schema、Flyway、Java/React/Python 测试和离线 Golden Set 回归同步更新；
   MediaPipe 试点扩大前仍须完成效率、质量、资源和离线网络评估。

## 5. 当前实现切片

2026-08-10 的第一切片仅实现管理员创建固定 10 FPS 的不可变 `AIJob`，并在一个数据库
事务中写入 attempt、Outbox 和追加式审计；同时冻结 `ai-hand-pose-job.v1` 消息 Schema。
它不宣称已经执行 MediaPipe、回写候选或完成候选人工确认。后续必须先交付 Worker 的 lease
与结果校验、`CandidateAnnotation` 写入及其合成 Golden Set，随后才扩展正式手部姿态 revision
和网页叠加/确认。P0 UAT 状态不因该 P1 切片改变。

## 6. 继承与冲突处理

除本版本明确新增的 P1 Ego 手部姿态候选能力外，V1.11 的项目隔离、角色、审计、人工复核、
数据集冻结、导出、Worker 身份和 P0 UAT 要求继续有效。AI 结果不放宽任何人工确认、复核、
清洗或训练数据准入守卫；发生冲突时，以本版本的“候选而非正式真值”规则为准。
