# 配药视频数据管理平台需求基线 V1.6

> 文档版本：V1.6
> 文档状态：当前基线
> 生效日期：2026-07-23
> 前一版本：V1.5
> 生效规则：本版本继承 V1.5；本版本明确修改的条款优先于 V1.5 及其历史继承基线。

## 1. 本次变更

P0 保持“内部团队管理训练视频数据”的主闭环，不把项目或视频的日常管理误做成不可恢复的物理销毁。

```text
管理员建立项目
→ 边端自动上传或平台本地上传
→ 媒体技术校验
→ 项目成员手动播放与人工质量判断
→ 标注、复核、清洗、冻结和导出
```

医院侧仅负责采集和按正式协议自动上传；Web 管理端由内部团队使用。项目和视频的业务删除必须保留可追溯事实，不能直接作为对象存储物理删除的快捷入口。

## 2. 项目生命周期

1. `ADMIN` 可修改 ACTIVE 项目的显示名称。改名不改变稳定 project ID、成员、文件夹、视频、上传记录或审计历史。
2. P0 不提供“彻底删除项目”。管理员可将项目从 `ACTIVE` 归档为 `ARCHIVED`；归档项目从日常项目列表移除，并拒绝新的项目内读取和操作。
3. 项目归档保留项目、成员、视频、对象存储对象和审计记录。P0 不提供恢复或物理销毁 UI；若未来需要恢复、保留期届满或法律销毁，必须另立需求版本并设计审批、依赖检查、可验证清理和审计证据。
4. 归档是显式管理员操作，界面必须展示影响、要求输入完整项目名称确认，并记录追加式审计。

## 3. 视频删除与保留

1. 管理员删除视频仍使用 FR-035 的可审计软删除：保存 `deleted_at`、`deleted_by` 和明确原因。
2. 软删除后，视频立即退出普通列表、播放、新标注任务和新数据集候选；同一 CaptureSession 的其他视频不受级联影响。
3. P0 不在用户点击“删除视频”时物理删除对象存储文件、上传完整性记录、历史标注、冻结数据集引用或审计。物理清理由未来的保留/销毁流程在明确授权、依赖检查和可观察验证下处理。
4. 软删除不代表误报或系统故障。它是面向日常审核、上传错误和不合格视频的安全业务删除；管理员应在确认框中看到该语义和影响范围。

## 4. 继承能力与最低验收

V1.5 未修改的上传、媒体检测、项目内审核播放、人工质量判断、标注复核、清洗、数据集冻结和导出要求继续有效。V1.6 追加以下最低验收：

1. 管理员能改名，且项目 ID、成员、文件夹和视频归属不变，并有审计证据。
2. 管理员能归档项目；归档后项目不在正常列表中，项目数据仍存在且不物理删除。
3. 管理员删除视频后，视频不能再播放、标注或进入新训练候选；历史对象和审计不被日常操作销毁。
4. 普通成员不能改名、归档项目或删除视频。
5. 物理删除没有 P0 公开 API 或 Web 按钮。
