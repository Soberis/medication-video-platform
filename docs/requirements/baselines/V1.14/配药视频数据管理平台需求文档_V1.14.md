# 配药视频数据管理平台需求基线 V1.14

> 文档版本：V1.14
> 文档状态：当前基线
> 生效日期：2026-08-10
> 前一版本：V1.13
> 生效规则：本版本继承 V1.13；本版本明确修改的条款优先于 V1.13 及其历史继承基线。

## 1. 本次变更

本版本把“用 MediaPipe 做手部姿态识别、Ego 数据标注”收敛为两个可验收且不越权的交付物：

1. **手部姿态识别**：对一段获批的 Ego 视频，离线输出每帧最多两只手、每只手 21 个二维关键点的
   候选结果和可人工查看的骨架 Overlay。
2. **Ego 姿态候选标注**：把上述关键点候选作为待审查标注事实；人工可接受、修改或拒绝后，才允许按
   已有标注修订和复核规则形成正式训练数据。

这里的“Ego 数据标注”仅指与手部姿态相关的候选和人工确认。它**不**意味着自动识别配药步骤、药品、
剂量、SOP 合规性或临床结论；这些仍不在范围内。

## 2. FR-042B 识别与候选标注闭环

1. 识别算法固定为已批准、离线可用且 SHA-256 可核验的 MediaPipe Hand Landmarker `.task` 模型；
   使用 Tasks API `VIDEO` mode，输入 RGB/SRGB 和严格递增的 PTS 时间戳。
2. 每个候选必须包含：Ego 视频/资产的不可变输入摘要、帧时间戳、图像宽高、0–2 手、手序号、
   `Left`/`Right`/`Unknown`、handedness 分数、21 个编号固定的二维关键点、有效关键点数、bbox
   计算规则和完整推理参数摘要。
3. 未推理帧与已推理但无手帧必须可区分；不得从相邻帧复制关键点来伪造连续跟踪。
4. 模型输出只能成为候选。候选进入正式 `AnnotationRevision` 前必须经过具备项目权限的人工
   接受、修改或拒绝，并保留操作者、时间、输入/模型摘要和审计记录。
5. 模型输出、Overlay 和候选记录不得直接改变人工 Step 标注、质量判断、数据集版本或导出内容。
6. 输入仅可为合成数据或有明确授权、隔离且已绑定预先批准 Ego camera role 的视频；不能仅凭
   `content_type=video/*` 推定其为 Ego 视频。
7. Phase B 获得人工 `GO` 后，ACTIVE 项目成员都可以为符合输入条件的视频发起候选生成；该权限只创建
   候选作业，不授予候选审核、正式标注、质量结论或数据集放行权限。

## 3. 两阶段交付与进入条件

```text
Phase A：离线识别工具 + 获批模型 + Ego Golden Set + 试点评估
→ 人工 GO / TUNE / REPLACE / STOP
→ Phase B：受控候选写入、人工审核与既有 AnnotationRevision 闭环
```

Phase A 仅当同时具备以下材料时才能声称“识别需求完成”：

- 一个离线 `.task` 模型及其批准记录、SHA-256；
- 合成或明确授权、隔离的 Ego Golden Set；
- 在断公网出站环境中的实际运行证据；
- 按 V1.13 冻结的分层指标、阈值、session 聚类统计和人工评审结论。

Phase B 仅当 Phase A 得到书面 `GO`，并冻结候选结果 Schema、资产 Ego 准入、人工审核权限、
幂等/租约/迟到结果语义、存储策略和审计契约后才可开始。不能把现有 AIJob 草稿或 PoC 自动测试
当作这两个阶段的完成证据。

## 4. 验收边界

| 需求 | 当前可验证证据 | 完成判定 |
| --- | --- | --- |
| 手部姿态识别 | 本地 CLI、合成管线测试、MediaPipe runtime | 获批模型和 Ego Golden Set 运行后达到预冻结阈值，并经人工评审 |
| Ego 姿态候选标注 | JSONL 候选格式和 Overlay | Phase A 先人工核对候选；Phase B 再验证候选写入、人工修改/拒绝与正式修订隔离 |
| 正式训练数据标注 | 既有人工 Step 标注闭环 | 不由 MediaPipe 自动完成；须由人工审核后依既有规则完成 |

## 5. 非目标

本版本不增加实时摄像头推理、自动 Step/动作分类、自动药品识别、跨视频追踪身份、三维重建、
自动数据集放行、直接数据库写入、独立 AI 微服务或未经批准的模型下载。
