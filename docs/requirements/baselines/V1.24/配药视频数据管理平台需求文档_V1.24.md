# 配药视频数据管理平台需求文档 V1.24

> 文档版本：V1.24  
> 状态：当前正式业务需求基线（FLOW-FIRST P0 自动任务衔接）  
> 生效日期：2026-08-20  
> 正式继承基线：V1.23  
> V1.22：仅为 DRAFT / DEFERRED，不属于本正式继承链

## 1. 基线定位

V1.24 在 V1.23 的 FLOW-FIRST LEAN-P0 闭环上，只补齐“人工质量合格”到“人工动作标注”的无歧义衔接。除本文件明确覆盖的条款外，V1.23 以及其继承的 V1.21、V1.20、V1.18 条款继续有效。

本版本不把任何人工事实自动化为正式标签；自动化只负责创建可追溯、可分配的工作项。V1.22 多视角、CaptureSync runtime、DatasetVersion、机器人控制和模型训练继续不属于当前 P0。

## 2. 当前唯一 P0 主线

当前产品必须保持一条可运行、可审计、可回退的纵向闭环：

```text
边端接收
→ CaptureSession / Camera / ClipAsset 事实
→ Media Probe
→ INGESTED
→ 自动单视频 MediaPipe Hand Candidate / Skeleton Overlay
→ 人工质量判断
→ 质量合格时自动创建并分配 AnnotationTask
→ 人工 AnnotationRevision
→ 人工 Review
→ 自动规则 Cleaning
→ 管理员确认的 training-data.v2 / training_data.parquet 导出
```

MediaPipe 只产生 `CandidateAnnotation` 与辅助显示；`HAND_DETECTED`、`NO_HAND_DETECTED` 和 AI `FAILED` 都不得替代、阻断或伪造人工质量、正式标注、复核、清洗或导出事实。

## 3. 质量合格后的自动任务规则

### 3.1 触发条件

当且仅当一个 ACTIVE 项目成员成功把一个未删除、`INGESTED` 的视频质量结论新建为或修订为 `QUALIFIED` 时，系统必须在同一数据库事务内自动创建该视频的唯一 P0 `AnnotationTask`。

- 自动任务的 `assignee_actor_id` 和 `created_by` 都是作出这一次 `QUALIFIED` 结论的项目成员；不得根据文件名、上传顺序、时间接近、AI 结果或浏览器本地状态猜测受理人；
- 同一视频已经存在标注任务时，系统不得重复创建、覆盖或重新分配该任务；
- 相同质量结论与原因的幂等重试不得新增任务或审计；
- `REJECTED`、`NEEDS_REVIEW` 与未完成媒体入库不得创建任务；
- 质量结论、自动任务与两项审计事实必须一起提交或一起回滚，不能留下“质量已合格但没有任务”的半完成状态；
- 自动任务使用当前冻结的 P0 `LabelSchema` 绑定，不创建第二套动作标签或任务模型。

### 3.2 人工边界保持不变

自动分配不代表自动标注。只有受分配的 ACTIVE 项目成员可以提交不可变 `AnnotationRevision`；正式动作标签仍只来自人工 revision。项目管理员仍须进行人工 Review；只有 Review 通过的 revision 才能进入自动规则 Cleaning。Cleaning `PASS` 仅表示可参与训练数据导出，管理员仍须在有权限的导出入口显式确认。默认导出不包含 MP4。

## 4. 交互与可见性

视频详情和任务列表必须如实展示“任务已由质量合格自动分配”的服务端事实，而不是让用户选择一个伪造的受理人或手动补建正常任务。

- 当前质量确认人可在个人范围看到自己的自动任务；项目管理员在项目范围看到任务事实；
- 任务读取尚未完成或失败时，界面必须明确显示“正在确认自动分配”或可重试错误，不得声称任务已经创建；
- 自动 MediaPipe 处理中的视频应显示真实的处理中状态；完成、无手和失败必须使用不同且可理解的状态文案；
- 用户仍可在人工质量判断前安全查看已经完成上传完整性校验的视频；媒体/AI 状态不得伪装为人工质量结论。

## 5. 本版本不新增的能力

本版本不新增数据库表、批量标注分配 API、通用工作流引擎、外部调度器或 AI 自动正式标注。既有管理员手动创建任务的兼容 API 可仅作为受控恢复入口保留，不是正常产品主路径，也不得覆盖自动任务的唯一性和人工守卫。

## 6. 验收要求

本版本变更完成后必须证明：

1. `QUALIFIED` 首次写入或结论变化时，恰好创建一个、分配给当前质量确认人的 `AnnotationTask`，并留下审计证据；
2. 幂等重试、非合格结论、不可复核视频和已有任务均不会产生重复或错误分配；
3. 自动任务与质量结论在同一事务下回滚安全，跨模块写入只经内部领域事件和公开只读查询完成；
4. 人工 `AnnotationRevision`、Review、Cleaning 和管理员导出确认仍不可绕过；
5. OpenAPI、Web 文案、契约测试、Spring Modulith 与当前质量门禁一致，不以放宽断言掩盖失败；
6. V1.23 已退役的 CaptureSync runtime、V1.22 Draft 和未来机器人/模型能力未被重新引入当前 P0。
