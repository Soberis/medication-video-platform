# 配药视频数据管理平台需求基线 V1.27

状态：CURRENT
发布日期：2026-09-02
主题：单一 CaptureGroup 产品路径、training-data.v3 与 hand-landmarks.v1

## 1. 版本定位

V1.27 是当前正式业务需求基线，取代 V1.26 的当前地位。V1.26、V1.25 和 V1.24 文档保留为历史与演进参考；本基线不回写历史文档，也不把历史运行时行为继续承诺为当前产品能力。

当前唯一支持的业务流程是：

```text
Local Upload / External Ingest
→ CaptureGroup
→ CameraStream / ClipAsset
→ Media Probe
→ MediaPipe Candidate
├→ per-view Quality
│  → CaptureGroup Quality
│  → one CaptureGroup AnnotationTask
│  → AnnotationRevision
│  → Review
│  → deterministic CaptureGroup Cleaning
│  → training-data.v3（CaptureGroup eligibility / provenance event manifest）
└→ current enabled camera views
   → hand-landmarks.v1（current MediaPipe landmark detection evidence）
```

核心原则仍然是：`AI provides evidence. Human makes final decisions.` MediaPipe 只能产生 `CandidateAnnotation`；它不得改写人工质量、正式修订、Review 或确定性 Cleaning。`hand-landmarks.v1` 是经 provenance 校验的当前 MediaPipe 检测事实导出，不是人工动作标签、质量结论或 Cleaning 结果，也不要求先完成这些人工流程。

V1.27 必须区分两个不同的导出产物：

```text
training-data.v3
= CaptureGroup eligibility / provenance event manifest
≠ primary machine-learning feature dataset

hand-landmarks.v1
= current MediaPipe hand landmark detection evidence export
```

`training-data.v3` 只说明一个 `CaptureGroup` 是否满足当前资格以及它的来源链，不能把 event row、`eventCount` 或 candidate provenance 摘要解释为机器学习样本。`hand-landmarks.v1` 独立记录当前启用且可用视图中的 MediaPipe 检测手部事实；它没有人工 action label，也不声称是已完成训练的数据集。当前两者均已有可验证的服务端导出运行时：前者是事件 manifest，后者是当前检测视图的 CSV feature/evidence artifact。尚无实际 training consumer 读取后者的证据，不能据此声称真实模型训练成功。

### 1.1 退役的业务路径

以下内容从 V1.27 当前产品范围和需求承诺中正式退役：

| 退役内容 | V1.27 语义 |
| --- | --- |
| `/projects/:projectId/videos` | 不再是当前视频管理或单视频业务入口 |
| `/projects/:projectId/assets/:id` 作为独立工作台 | 不再承担独立的业务工作流；ClipAsset 只能作为事件内视频证据查看 |
| standalone single-video annotation task workflow | 不再创建或维护单视频业务任务 |
| single-video task creation product flow | 不再作为产品操作或自动衔接 |
| single-video Cleaning workflow | 不再作为当前清洗流程；Cleaning 以 CaptureGroup 事件为单位 |
| `training-data.v2` | 退役；历史单视频 landmark Parquet 只作为迁移/审计证据，不是 V1.27 当前导出 |
| V1.24-compatible runtime behavior | 不再是当前产品兼容性承诺或验收目标 |

以上退役语义是 V1.27 的稳定产品边界。历史单视频数据、旧迁移、旧读模型和旧路由按审计与迁移策略保留或另行清理；它们不构成当前产品入口、数据模型或验收范围。

## 2. 领域事实与所有权

### 2.1 CaptureGroup 是唯一业务工作对象

- 一个真实配药过程对应一个 `CaptureGroup`；当前实现可由 `CaptureSession` 承载该稳定业务身份。
- `CameraSetSnapshot` 固化事件的视图集合，`CameraStream` 表示事件内的机位视图。
- `ClipAsset` 是物理视频证据对象，保存上传文件、对象存储引用、内容大小、`SHA-256`、媒体状态、播放授权所需事实和软删除状态；它不再是独立的产品工作流对象。
- 事件与机位必须通过显式 manifest/metadata 和 `CameraStream → CaptureSession/CaptureGroup → ClipAsset` 事实建立关系，不得按文件名、上传顺序或时间邻近猜测归组。

### 2.2 N=1 不是第二条流程

本地单视频上传仍然形成一个正常的 `CaptureGroup`：

```text
CaptureGroup
└─ CameraStream #1
   └─ ClipAsset
```

产品界面可将它显示为“机位 1”，但不得创建 `CaptureGroupView` 新表、单视频专用任务或单视频专用清洗状态。`N=1` 与 `N>1` 使用同一领域路径、权限、审计和导出语义。

### 2.3 必须保留的低层视频与平台事实

V1.27 继续保留以下事实和责任边界：

- `ClipAsset`、`CaptureSession`、`CameraSetSnapshot`、`CameraStream`；
- upload pipeline、外部 ingest manifest、对象存储引用和受控 playback authorization；
- 内容 `SHA-256`、文件大小、媒体版本、软删除和 governance；
- Media Probe、`MediaReport`、媒体作业和验证后的解码事实；
- MediaPipe Worker、`ai_job`、`ai_job_attempt`、`CandidateAnnotation` 和候选查询；
- 权限、项目隔离、append-only audit、provenance、人工 Review 和 Cleaning 事实。

模块仍只能写入自己拥有的表。AI Worker 只处理媒体和 AI 作业，不直接写正式标注、Review、Cleaning 结论或冻结数据集；跨模块通过公开应用服务、只读查询或版本化事件协作。

## 3. 产品信息架构

产品入口固定为：

```text
视频管理
└── 配药事件列表
    └── 配药事件工作台
        └── 1..N 个机位视图

配药动作标注
└── CaptureGroup task inbox
    └── 对应配药事件工作台
```

- “视频管理”只有一个面向用户的主入口，默认进入配药事件（`CaptureGroup`）列表。
- 事件工作台统一承载收件、机位质量、事件质量、动作标注、Review 和训练资格结果。
- “配药动作标注”是 `CaptureGroup` 任务待办入口，必须深链回同一个事件和当前操作。
- 不得再提供第二套以单视频为对象的视频管理、任务或清洗工作台。
- 事件列表、任务待办和详情不得要求用户重复选择服务端已经唯一确定的项目、事件、机位或任务。

## 4. 功能需求

### V27-FR-001 统一接收与显式归组

- Local Upload 和 External Ingest 都必须先形成或绑定到 `CaptureGroup`。
- 所有视频通过 `CameraStream / ClipAsset` 成为事件视图；外部 manifest 必须显式声明事件、机位和文件身份。
- Receipt 状态、项目权限、上传完整性和软删除事实必须可审计。

### V27-FR-002 逐视图媒体与 AI 证据

- 每个事件视图独立执行 Media Probe；媒体未验证通过时不得作为已可用视图进入下游。
- 每个已入库且获准检测的视图可执行 MediaPipe hand detection，结果只能进入 `CandidateAnnotation`。
- AI job、attempt、模型/算法/profile、输入摘要、运行摘要、失败与重试事实必须保持可查询；`handedness` 只作为辅助元数据。
- `HAND_DETECTED`、`NO_HAND_DETECTED`、`UNKNOWN` 和技术失败不得自动改写人工质量、事件质量或训练资格。

### V27-FR-003 逐视图与事件质量

- 逐视图 `QualityReview` 是人工事实；局部媒体或 AI 失败必须绑定具体机位。
- `CaptureGroupQualityReview` 是独立的事件级人工准入；不得由 Candidate 或视图数量自动生成。
- `N=1` 与 `N>1` 都使用相同质量语义；排除一个视图不等于删除整个事件。

### V27-FR-004 单组任务与修订链

- 有效事件质量后，系统只能幂等创建并分配一个 `CaptureGroup AnnotationTask`。
- 正式动作标签必须通过 append-only `AnnotationRevision` 提交；主视图是正式 action interval 的权威时间基准。
- 不得按机位创建多个任务、多个事件动作标签或单视频任务。

### V27-FR-005 人工 Review 与确定性 Cleaning

- `Review` 是人工闸门，必须记录真实操作者、权限、决定、理由、时间和事件/视图上下文。
- Review `APPROVED` 后，Core API 按冻结规则执行事件级 `CaptureGroup Cleaning` 和训练资格检查。
- Cleaning 不是人工选择 PASS/REJECT 的审批步骤；管理员 recheck 只能重新运行既有确定性规则。
- Cleaning 结果、规则版本/digest、输入事实、视图参与/排除、provenance 和审计必须保留。

### V27-FR-006 CaptureGroup 资格与来源 manifest

- `training-data.v3` 是以 `CaptureGroup` 为单位的 eligibility / provenance event manifest，保留事件、主视图、视图集合、人工 Revision、Review、Cleaning 和现有 candidate provenance 语义。
- `training-data.v3` 不是主要机器学习特征数据集；它的 event row、`eventCount` 和 `eligibleGroupCount` 都不是 frame、hand 或 sample count。
- 只有通过确定性 `CaptureGroup Cleaning` 的事件才可出现在该 manifest 中；本基线不把 manifest 误命名为 landmark sample export。
- 本基线不重新设计 `training-data.v3` 的现有运行时实现；其剩余追溯性缺口按审计记录为后续工作。

### V27-FR-007 保留低层视频事实与安全边界

- `ClipAsset`、`CaptureSession`、`CameraSetSnapshot`、`CameraStream`、Media Probe、MediaPipe Candidate、权限、审计和 provenance 仍必须保留。
- AI Worker 只处理媒体和 AI 作业，不直接写正式标注、Review、Cleaning 结论或冻结数据集；跨模块通过公开应用服务、只读查询或版本化事件协作。

### V27-FR-008 退役单视频业务路径与兼容性承诺

- 退役 `/projects/:projectId/videos`、独立 `/assets/:id` 工作台、单视频任务、单视频 Cleaning、`training-data.v2` 和 V1.24-compatible runtime behavior 不属于当前产品承诺。

### V27-FR-009 MediaPipe landmark training export

V1.27 定义独立的 `hand-landmarks.v1` MediaPipe detection landmark export。它从当前 `CaptureGroup` 的启用且可用 `CameraStream / ClipAsset` 读取当前候选证据；它不依赖 View Quality、CaptureGroup Quality、`AnnotationRevision`、Review、Cleaning 或 `training-data.v3` eligibility。其契约为：

- `feature`：MediaPipe hand landmarks；
- `sample unit`：当前启用且可用的每个 `ClipAsset` 中一个采样 frame 内的一只检测到的手；同一 frame 的多只手分别形成 sample；
- `label`：不提供人工 action label；不得由 MediaPipe detection、handedness 或 candidate 状态伪造业务标签；
- `time association`：保留每个源 `ClipAsset` 的 source-local `frame_timestamp_ms`，不与人工 interval 或其他相机时间轴对齐；
- `provenance`：`CaptureGroup`、`CameraStream`、`camera_number`、`ClipAsset` 及其 `SHA-256`、当前 AI job/attempt、算法/模型/profile 身份与 digest；
- `state`：仅 `SUCCEEDED_WITH_CANDIDATES` 的当前 job 产生行；`NO_JOB`、`QUEUED`、`RUNNING`、`FAILED` 和 `SUCCEEDED_NO_HAND` 不产生行，但在 preview 状态计数中保留；
- `preview`：返回检测视图数、已完成视图数、检测到手部的视图数、样本数、运行中/失败/无手视图数、文件名和 `media_type`。

导出覆盖所有当前启用且可用的检测视图，保留 `CameraStream`、camera number 和 `ClipAsset` 身份；不选择 Primary View，不使用 View/Group Quality，不读取人工 Annotation/Review/Cleaning 快照，也不做跨相机时间对齐。只有实际检测到并通过 21 点与 provenance 校验的手部样本才形成 row，不补造 no-hand row。它与 `training-data.v3` 互补且完全独立，不能由后者的 event manifest 代替。

当前已形成可用的 `hand-landmarks.v1` 服务端 CSV export runtime，并有 synthetic contract/readback evidence；尚无实际 training consumer 读取该 artifact 的证据。本条冻结的是 V1 语义和范围，不构成真实模型训练成功声明。

## 5. 自动化与人工边界

允许的自动化必须有明确触发事实、可安全重试、失败可恢复并可追溯：

- 上传完成后的媒体探测和合格媒体视图的 MediaPipe Candidate 作业；
- 本地 `N=1` 在明确的批次完成事实下关闭 receipt；外部或多机位事件仍需显式 finalize；
- 有效事件质量后幂等创建唯一组任务；
- Review `APPROVED` 后确定性执行 Cleaning；
- 服务端成功后的权威快照刷新、当前用户未决机位聚焦和安全导航。

以下动作必须由有权限的人工明确提交：逐视图质量、事件质量、Primary View、正式 AnnotationRevision、Review、删除/隐私放行和任何导出或放行决定。不得自动接受 AI 结果、自动创建正式标签、自动 Review 或自动修改 Cleaning 结果。

## 6. 追溯、权限与安全

- 每个业务事实必须按项目隔离，并记录真实 actor、角色、授权依据、UTC 时间、request/trace 关联和版本事实。
- 原始视频和模型文件不得进入普通日志、审计 payload 或导出文件；预签名 URL、令牌和生产凭据不得写入仓库。
- AI Candidate、媒体检测、边端声明、人工质量、Revision、Review、Cleaning、`training-data.v3` manifest 和 `hand-landmarks.v1` sample export 必须在语义上分层；任何一层不得伪装成另一层。
- 当前 V1.27 AI 证据的 attempt/result 和导出 lineage 缺口见[AI evidence pipeline audit](../../../history/architecture/v1.27-ai-evidence-audit.md)与[training traceability audit](../../../history/architecture/v1.27-training-traceability.md)，这些缺口是后续设计/实施项，不改变本基线的人工闸门。

## 7. 验收条件

- Local Upload 和 External Ingest 均能进入统一的 `CaptureGroup` 事件路径；本地单视频显示为一个事件的一路“机位 1”。
- 事件列表是“视频管理”的唯一主入口，事件工作台统一处理所有机位和业务阶段。
- 服务端能够显式证明事件、机位、ClipAsset、Media Probe 和 Candidate 的关系；不得依赖文件名、顺序或时间猜测。
- 事件中最多只有一个 `CaptureGroup AnnotationTask` 和一条 append-only Revision 链；人工 Review 通过后才能执行 Cleaning。
- `NO_HAND_DETECTED`、AI 失败或局部媒体失败不会自动生成质量、标注、Review 或 Cleaning 结论。
- 只有通过确定性 Cleaning 的事件才可进入 `training-data.v3` eligibility manifest；`training-data.v2` 和单视频导出不属于 V1.27 验收范围。
- `hand-landmarks.v1` 的验收必须证明它不读取人工质量、AnnotationRevision、Review、Cleaning 或 v3 eligibility，能够覆盖 N=1/N>1 的所有当前启用视图，正确使用当前 MediaPipe job，保留 CameraStream/ClipAsset/SHA/AI job/model provenance，区分各检测状态，并执行 21 点、输入 SHA、软删除和 no-hand row 的 fail-closed 规则；在实际训练 consumer 读取该 artifact 前，不得宣称真实模型训练成功。
- 权限、审计、provenance、原始视频 SHA-256、软删除和播放授权事实保持可验证。
- 自动化与合成测试可以证明实现行为，但不等同于真实 UAT、医院验收或生产部署验收。

## 8. 非目标与延期

- V1.27 不支持 standalone single-video workflow、`training-data.v2` 或当前 `DatasetVersion` 工作流；不新增 `CaptureGroupView` 表、通用 `WorkflowEngine` 或持久化 `next_action`/`blockers`。
- V1.27 不把历史单视频业务数据迁入当前 CaptureGroup 产品路径；V72 在无历史依赖时退役纯 legacy runtime，发现历史依赖则原样保留相关旧对象并继续升级，等待单独的迁移/保留决策。决策完成且旧行已显式处置后，V74 移除被保留的旧对象；它不得自动删除业务行。旧迁移文件作为数据库审计历史保留。
- 不新增 `CaptureGroupView` 表、通用工作流引擎、持久化 `next_action`/`blockers`、CaptureSync runtime、3D/标定或跨相机自动对齐。
- 当前实现最小的 `training-data.v3` 事件资格 manifest 与独立的 `hand-landmarks.v1` 当前检测事实 CSV export；不实现独立 DatasetVersion/导出平台、frame extraction platform、新 AI training service、自动模型训练或完整 AI result artifact/Media Report 直连。AI provenance 当前仅保存已验证的 ClipAsset/job/attempt/result/candidate-set 摘要。
- 不实现 supporting-view time alignment、不补造 fake no-hand rows、不使用 MediaPipe 生成 action labels；`hand-landmarks.v1` 保留各当前 CameraStream 的 source-local timestamp，不把任一机位提升为 Primary View。
- 不实现批量质量决定、一键通过全部机位、自动选择主视图、自动 Review、自动修复正式标注或相机/机器人/PLC 控制。
