# 配药视频数据管理平台需求基线 V1.17

> 文档版本：V1.17<br>
> 文档状态：当前基线<br>
> 生效日期：2026-08-10<br>
> 前一版本：V1.16<br>
> 生效规则：本版本继承历史基线中未被明确替代的安全、权限、审计和数据完整性要求；本版本对产品范围、默认交互和实施顺序具有最高优先级。

## 1. 产品定位与边界

平台名称和总体定位仍为**配药视频数据管理平台**。它的目标是将医院配药场景的视频，从云端接收、管理、自动预标注、人工标注、清洗复核，逐步沉淀为可用的数据资产。

平台不建设、不控制边端设备。医院侧边端设备或已有采集系统负责固定相机采集医护人员配药动作、本地缓存、视频分段，以及何时批量或增量上传。平台只通过约定接口接收视频及元数据，并在云端管理后续数据生命周期；不得向相机或边端系统发送采集、停止、删除或上传触发命令。

相机安装在采集舱/操作台周围，医护人员不佩戴相机。一次采集可有任意数量的固定相机；页面按“相机 1 … 相机 N”展示，任何业务逻辑不得写死为 3 路。

当前主要矛盾不是删去数据标注和数据清洗，而是让完整的数据闭环不被项目、采集批次、队列等内部概念遮蔽。手部检测是当前优先建设的自动化能力，用于减少人工标注成本；它不是平台的唯一目的，也不能替代人工确认。

```text
医院边端设备或采集系统
  （采集、缓存、按其策略上传）
            ↓ 对接上传
配药视频数据管理平台
  接收与完整性校验
  → 视频与数据管理
  → MediaPipe 手部关键点候选
  → Ego 配药动作标注与复核
  → 数据清洗
  → 可用数据资产 / 后续数据集
```

## 2. 核心能力与简约导航

默认导航以用户任务组织，而不是以领域表、队列或 Worker 组织。

| 入口 | 用户目的 | 必须能力 |
| --- | --- | --- |
| 视频管理 | 查找、筛选、播放、归档、恢复和批量管理已接收视频 | 默认首页；视频是操作单位 |
| 数据管理 | 查看数据规模、来源、相机、采集时间、数据状态和保留状态 | 概览与可追溯查询 |
| 手部检测 | 查看/发起 MediaPipe 预标注、失败重试和 Overlay | 当前优先建设 |
| Ego 标注与清洗 | 领取标注任务、审阅候选、提交动作标注、复核与清洗 | 核心数据生产流程 |
| 上传接入 | 查看边端/采集系统上传批次及本地测试上传 | 接收状态与失败原因 |
| 设置 | 查看接入、模型、相机配置和权限 | 管理员能力 |

`CaptureSession`、`CameraStream`、AIJob、attempt、Outbox、队列、Worker、对象键、SHA 等是内部实现事实，不得成为默认导航、页面标题或用户必经步骤。管理员排障可在默认关闭的“高级信息”中查看必要摘要。

### 2.1 视频管理与数据管理

视频管理按最近接收时间倒序，采用服务端分页或游标加载，不能一次将所有历史视频加载到浏览器。首屏展示最近视频，用户可通过时间、相机、上传来源、媒体状态、手部结果、标注状态和清洗状态定位历史视频。

每条视频至少显示：文件名或可读名称、相机编号、采集/接收时间、当前数据状态、手部预标注结果、标注与清洗进度，以及“播放、开始/重试检测、进入标注、归档”等当前可用操作。批量操作只作用于用户显式勾选且有权限的视频。

数据管理是视频库的汇总和治理视图，至少展示视频总数、总时长、存储占用、按来源/相机/状态的数量、待标注数、待复核数、待清洗数和可用数。点击任一统计项必须跳转到保留同一筛选条件的视频管理或任务列表，不要求用户重新查找同一批数据。

### 2.2 云端接收边界

平台接收的每路视频至少关联以下不可变接收事实：

```text
source_system
source_device_id
external_capture_session_id（如边端提供）
camera_number（1…N）
captured_at 与时区
received_at
source_batch_id（如边端提供）
file_name、媒体摘要与对象引用
```

平台对重复上传、断点续传、完整性、媒体可读性、项目隔离和接收状态负责。边端的视频缓存规则、上传阈值、网络重传策略和相机控制不属于平台需求；平台只返回接收成功、待处理或失败等接口结果。

### 2.3 MediaPipe 手部预标注

媒体检查完成后，管理员可对单路或显式勾选的视频发起手部预标注；经批准的自动策略也可对符合条件的视频自动入队。系统采用 MediaPipe Hand Landmarker 生成每帧手框、21 个关键点、左右手和置信度候选，并在原视频播放器上以 Overlay 显示。

原视频绝不被改写。候选结果属于 `CandidateAnnotation`，只能辅助人工标注，不自动成为正式标签、清洗通过依据或可用数据。

对用户显示的检测状态为“上传中、待检测、检测中、已完成、失败”；“已完成”下另显示“发现手部”或“未发现手部”。不同相机的候选绝不混合。本阶段不做 3D 重建、跨相机关联或自动判定配药动作。

### 2.4 Ego 配药动作标注与复核

本项目中的“Ego 数据标注”是业务标签名称，指为医护人员配药动作理解准备的时序动作标注；它不表示视频来自佩戴式第一人称相机。标签定义、版本和标注指南必须独立版本化，具体动作词表不得在代码中写死。

标注人员在原视频、可选手部 Overlay 和候选关键点辅助下，创建或修订动作时间段、类别及必要属性。标注任务应支持领取、保存草稿、提交、退回和复核；每次提交形成不可覆盖的 revision。MediaPipe 无结果或漏检不得阻断人工标注。

人工确认后的正式标注与 AI 候选分开保存；任何候选转为正式标注都必须有明确操作者、时间和 revision 审计。

### 2.5 数据清洗与数据资产

数据清洗在标注提交/复核后进行，目标是识别并处置不适合后续使用的数据，而不是直接删除原始视频。最小清洗项包括媒体可读性和完整性、重复/近重复、必要元数据、标注完整性、时间范围合法性、标签版本一致性及人工质量结论。

清洗结果至少为“待清洗、通过、需修正、拒绝”。自动规则产生的是证据和建议；拒绝、修正、例外或重新处理必须留存原因、规则版本和审计。清洗通过的数据可以进入“可用数据”视图，并为后续数据集构建提供候选；训练导出和模型训练不是当前优先交付，但不再被错误地定义为废弃能力。

### 2.6 删除与保留

“删除项目”只能归档项目，绝不等价于删除视频数据。普通删除为可审计软删除/归档，保留恢复与追溯证据。彻底删除仅允许对本地或明确标识为 `SYNTHETIC_TEST` 的测试数据执行，必须展示影响范围、二次确认、异步执行和逐项审计；不得按项目无条件级联物理删除。

## 3. 领域边界与实施原则

### 3.1 当前活跃能力

- 边端/采集系统的标准上传对接、断点续传、完整性校验和媒体检查；
- 云端视频、采集元数据、相机与上传来源管理；
- 动态 N 路固定相机与原视频播放；
- MediaPipe 手部候选、异步作业、失败恢复和 Overlay；
- Ego 配药动作标注、revision、复核和审计；
- 数据清洗、质量结论和可用数据查询；
- 后续数据集构建所需的候选查询与可追溯性。

### 3.2 暂不作为当前重点

- 直接控制边端相机、边端缓存或上传触发；
- 实时视频、3D、跨相机手部融合、自动动作判定；
- 在运行时下载模型、在线训练或自动发布模型；
- 任意项目级物理级联删除；
- 未获批准的新标签体系、动作词表或真实医院数据接入。

简化原则是隐藏不必要的内部术语、合并重复跳转并用任务视图服务不同角色，不是删除标注、清洗、审计或数据完整性约束。

## 4. 最小数据与状态

用户视角的一条视频记录由 `ClipAsset` 表示，可关联内部 `CameraStream` 和 `CaptureSession`。后两者用于多相机归属与可追溯性，不要求普通用户直接操作。

```text
VideoDataRecord
  video_id
  display_name
  source_system / source_device_id
  external_capture_session_id（可选）
  camera_number (1…N)
  captured_at / received_at
  media_status
  hand_detection_status / hand_result
  annotation_status / current_revision
  cleaning_status
  retention_status
```

内部保留输入摘要、模型摘要、检测 profile、AIJob、attempt、CandidateAnnotation、正式 annotation revision、cleaning run/result 和审计事件，以支持重试、复核、数据集准入与追溯。

## 5. 算法基线与演进

当前基线为离线 MediaPipe Hand Landmarker `VIDEO` 模式：每路独立、10 FPS、最多两只手、检测/存在/跟踪阈值均为 0.5。该基线用于产生辅助候选，不宣称已对全部舱内视角最优。

优化顺序为：先验证云端接收、预标注、人工标注和清洗闭环；再用经授权样本统计漏检、误检、关键点可用率、对人工效率的影响和每分钟处理耗时；优先配置每路固定相机的 ROI、采样率和阈值；只有基线不能满足经批准指标时，才对照评估两阶段手框检测加关键点或 MMPose/RTMPose Hand。训练新模型、手网格和 3D 必须单独立项。

## 6. 验收标准

使用合成或明确授权、隔离的数据，至少证明：

1. 平台可接收外部边端/采集系统上传的视频及规定元数据，但不会向边端发送控制或触发命令；
2. 上传完整性、重复处理、媒体检查和动态 2、4、6 路相机归属正确；
3. 至少 1,000 条合成视频时，视频管理仍通过服务端分页和筛选定位，浏览器不全量加载；
4. MediaPipe 对含手/无手视频均产生正确终态，含手视频可在原视频查看 Overlay；
5. AI 候选不能自动成为正式标注，标注人员可在有或无候选时提交可追溯的 Ego 动作 revision；
6. 复核退回后产生新 revision，历史 revision 不被覆盖；
7. 清洗可识别至少一类媒体问题、一类元数据问题和一类标注完整性问题，结果可追溯；
8. 数据管理的统计与同条件视频/任务列表一致；
9. 软删除不误称物理删除，测试数据彻底清理只影响确认范围内的合成数据；
10. 默认界面不暴露队列、Worker、对象键或内部 UUID。

## 7. 实施顺序

1. 固化边端对接上传契约与云端接收状态，不建设边端控制；
2. 完成视频管理、数据管理的分页筛选和采集元数据追溯；
3. 打通 MediaPipe 手部候选、任务恢复和播放器 Overlay；
4. 用候选辅助 Ego 配药动作标注、提交、复核与 revision；
5. 完成清洗规则、质量结论和可用数据视图；
6. 用连续合成上传做端到端、分页、候选与标注清洗回归；
7. 再依据评估数据优化 ROI、采样率、阈值或模型，并决定数据集构建/导出下一切片。
