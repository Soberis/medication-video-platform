# 配药视频数据管理平台需求基线 V1.15

> 文档版本：V1.15  
> 文档状态：当前基线  
> 生效日期：2026-08-10  
> 前一版本：V1.14  
> 生效规则：本版本继承 V1.14；本版本明确修改的条款优先于 V1.14 及其历史继承基线。

## 1. 本次变更

V1.15 不扩大手部姿态业务范围，而是把 V1.14 的 Phase A/Phase B 进入条件、结果事实和验收证据
具体化，避免把已经存在的 AIJob、Worker、Outbox 或候选查看代码误认为已获准启用的业务能力。

本版本的顺序不可倒置：

```text
Phase A 工具加固
→ 获批模型 + 隔离 Ego Golden Set 实测
→ 书面 GO / TUNE / REPLACE / STOP
→ 冻结 Phase B 契约与存储决策
→ Phase B 最小纵向闭环
```

任何一项中间代码、迁移、接口或页面都只能标为“实现草稿”；没有书面 `GO` 不得向用户开放候选生成，
不得运行生产候选作业，也不得声称 FR-042B 已完成。

## 2. Phase A 工具与试点评估

### 2.1 运行事实

1. 输入只可为合成数据或明确授权、隔离的 Ego Golden Set MP4；不得以任意“真实视频”替代 Golden Set。
2. 模型必须是预先批准的离线 `.task` 文件，运行前后记录 SHA-256；运行时不得下载模型。
3. 使用 MediaPipe Tasks API `VIDEO` mode、RGB/SRGB 输入和严格递增的毫秒时间戳。
4. 优先采用容器 PTS；缺失、重复、倒退或毫秒换算后不递增的 PTS 默认失败。只有人工检查源视频后
   显式启用回退策略时才可继续，且每帧必须记录 `timestamp_source`。不得静默以 `previous + 1 ms`
   伪造容器时间轴。
5. 每个解码帧必须保留 `inference_performed`；未推理、已推理但无手、以及检测到 1/2 手三种事实
   必须可区分，且不得复制相邻帧关键点。

### 2.2 鲁棒性与输出

1. 单个 landmark 的 NaN/Inf 不得导致整帧、整段视频或整次试验失败；无效点及其连接线不绘制，
   其余有效点继续输出，并如实记录有效点数。
2. Overlay、JSONL 和 summary 必须以临时文件原子发布；失败后的 `.partial` 文件必须被清理，或由
   明确的恢复命令安全清理，不能阻止同一试验重新运行。
3. `duration_ms` 必须准确表述为“最后解码帧时间戳”或改为容器实际时长；性能指标必须标明是端到端
   处理吞吐还是仅推理吞吐，不得混用。
4. Overlay 只用于人工效果核对，不是正式候选存储，也不构成 Phase B 的输入契约。

### 2.3 GO 决策记录

Phase A 评审记录至少包含：模型与软件摘要、Golden Set 授权/隔离证明、断公网证据、分层样本和
session 聚类统计、预冻结阈值、失败案例、人工结论和决定人/时间。结论只能是 `GO`、`TUNE`、
`REPLACE` 或 `STOP`；仅 `GO` 可进入 Phase B。

## 3. FR-042B Phase B 冻结要求

### 3.1 Ego 输入准入与权限

1. 只接受已绑定预先批准 `EGO` camera role 的单路资产；`INGESTED`、文件扩展名或
   `content_type=video/*` 不是 Ego 证明。
2. 准入必须同时证明项目、资产、CameraStream、相机角色、授权/隔离状态和固定输入 SHA-256。
3. ACTIVE 项目成员只可对符合上述准入的资产创建候选作业。候选查看、审核、正式标注、质量结论、
   数据集冻结和导出仍是彼此独立的权限。

### 3.2 不可变推理 Profile

每次作业必须固定并持久化 profile 原文和 SHA-256，至少包括：

```text
profile_schema_version
algorithm_key / algorithm_version
model_sha256 / approved_software_digest
num_hands
min_detection_confidence
min_presence_confidence
min_tracking_confidence
sampling_fps
handedness_policy
timestamp_policy
bbox_recipe_version / bbox_margin
world_landmarks_enabled
```

handedness score 只能表示类别分数；bbox 必须标为来自关键点包络，不得冒充 bbox 检测置信度。

### 3.3 结果语义与存储决策

1. 每帧结果必须包含：原始/归一化时间戳和来源、图像宽高、`inference_performed`、0–2 手及每只手的
   固定序号、左右手、分数、21 点、有效点数、bbox、bbox recipe 和 profile 摘要。
2. 仅保存“检测到手”的行不足以表达未推理和无手帧；结果契约必须保留完整帧级事实。
3. Phase A `GO` 后须以 Golden Set 的时长、帧率、候选密度、查询/Overlay 访问模式和保留期做容量评估，
   冻结为以下之一：关系型帧/手记录，或对象存储不可变结果工件加关系型 Job/摘要/审核索引。未经该决定
   不得把 dense landmark 规模化写入 PostgreSQL。
4. Python Worker 不得直接写平台数据库；候选、工件索引、审核和审计均由拥有表的 Core API 写入。

### 3.4 作业、Outbox 与 Worker

1. 作业、attempt、审计和 Outbox 必须在同一数据库事务创建；attempt 仅保存 lease capability 的摘要。
2. 发布确认前 Outbox 可受限地持有原始 capability；确认成功后必须在同一事务从所有 AI job payload
   删除 `lease_token` 并记录 `payload_redacted_at`。日志、DLQ、审计和查询响应不得包含原始 capability。
3. Idempotency-Key 必须有可重放 receipt：相同 key + 相同请求返回同一结果；相同 key + 不同请求稳定冲突。
   自然键命中旧作业时也必须为新 key 建立一致 receipt；并发自然键冲突不得泄露数据库唯一约束错误。
4. Worker 必须校验下载输入的大小和 SHA-256，以独立机器身份领取、持续心跳并在失去租约后停止提交旧结果。
   租约过期、迟到结果、重复结果、可重试/永久错误、最大重试次数和回收策略必须在契约中冻结。
5. Phase B 的 PTS 语义必须与 Phase A 一致；不得为生产通路引入未声明的静默时间戳修正。

### 3.5 人工审核与正式标注隔离

候选必须支持 `ACCEPT`、`MODIFY`、`REJECT`，并记录候选/输入/profile 摘要、操作者、时间、修改内容和
追加式审计。只有接受或修改后，才可通过现有 AnnotationRevision 提交流程产生正式修订；机器输出不能
自动改变 Step 标注、质量判断、DatasetVersion、导出或任何放行决定。

## 4. Phase B 验收

Phase B 只有在下列证据齐全时才可标为完成：

| 场景 | 最小可执行证据 |
| --- | --- |
| 准入 | 非 Ego、无授权、非成员和非活跃项目均被拒绝；获批 Ego 资产可创建作业。 |
| Worker | 合成 MP4 经过 RabbitMQ、独立 Worker、输入摘要校验、心跳、回传和幂等接收。 |
| 时间语义 | 未推理、无手、1 手、2 手、PTS 缺失/倒退和迟到结果均有稳定、可审计行为。 |
| 安全 | 发布确认后的 AI Outbox payload、日志、DLQ 和 API 响应均无原始 lease token 或签名 URL。 |
| 审核 | 接受、修改、拒绝均有审计；只有接受/修改可创建正式 AnnotationRevision，且仍经过既有复核。 |
| 隔离 | AI 候选不会自动进入质量、数据集冻结或导出。 |

自动单元/契约测试不能替代上述合成跨进程验收，也不能替代 Phase A Golden Set 的人工 `GO`。

## 5. 非目标

本版本不增加实时摄像头推理、自动 Step/动作分类、自动药品识别、跨视频追踪身份、三维重建、自动数据集
放行、独立 AI 微服务或未经批准的模型下载。
