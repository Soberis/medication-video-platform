# 配药视频数据管理平台需求基线 V1.26

状态：CURRENT  
发布日期：2026-08-31  
主题：统一视频管理与配药事件工作台

## 1. 版本定位

V1.26 继承 V1.25 的 `CaptureGroup` 多机位事实模型、人工质量准入、单组任务与追加修订链、Review、事件级 Cleaning、权限、审计、provenance 和 `training-data.v3` 约束。本版本收敛入口、导航、可安全自动化的收件衔接和配药事件工作台的信息层级，不改变领域所有权。

人工决策包括逐视图 `QualityReview`、`CaptureGroupQualityReview`、正式 `AnnotationRevision` 和 Review。Cleaning 是 Review `APPROVED` 后由冻结规则执行的确定性训练资格检查，不是人工选择 PASS、WARNING 或 REJECT 的审批步骤；管理员 recheck 只重新执行同一确定性检查。MediaPipe Candidate 不得写入任何上述人工决策。

V1.24-compatible 单视频历史路径继续保留，用于既有数据与路由兼容；新接收的视频不得再以孤立 `ClipAsset` 作为默认业务工作对象。

## 2. 核心体验

一个真实配药过程对应一个“配药事件”，系统内部身份为 `CaptureGroup`。用户只需从“视频管理”进入事件列表，并在一个事件工作台内查看其所有机位视频、处理状态和下一项人工动作。

主流程固定为：

```text
视频管理 → 配药事件 → 机位质量 → 事件质量
→ 配药动作标注 → 人工复核 → 训练资格检查 → training-data.v3
```

## 3. 功能需求

### V26-FR-001 单一视频管理入口

- 项目侧边栏只提供一个“视频管理”入口，默认进入 `CaptureGroup` 列表。
- 列表和详情使用用户语言“配药事件”；`CaptureGroup` 作为 API 和领域标识保留。
- `/videos` 和 `/assets/:id` 继续作为历史兼容路由，不再作为新事件主入口。

### V26-FR-002 事件内视频自动归并

- 新接收视频必须通过服务端 `CameraStream → CaptureSession/CaptureGroup` 事实归组，禁止依据文件名、上传顺序或时间邻近推断。
- 打开已属于 V1.25 `CaptureGroup` 的单视频详情时，前端必须自动进入对应配药事件工作台，不展示一套并行的旧任务状态。
- OpenAPI 必须在资产会话绑定读模型中返回是否为 CaptureGroup 工作流、CaptureGroup ID 和收件状态。

### V26-FR-003 本地单视频收件自动闭合

- 对平台本地上传形成的 `N=1` 事件，已完成且仅含一个视频的 `UploadBatch` 是明确的收件完成事实。
- 系统创建本地 `CaptureSession` 和 `CameraStream` 后，必须以批次完成时间自动将事件收件状态写为 `COMPLETE`；既有符合条件的数据通过版本化迁移回填。
- 外部边端、多机位或仍可能补传视图的事件不得按数量相等、等待超时或当前可见视频数自动终结，仍须使用版本化显式 finalize 信号。

### V26-FR-004 自动化边界

- 收件关闭后，媒体检测和 MediaPipe Candidate 可继续按既有规则自动执行。
- 系统不得自动填写逐视图 `QualityReview`、事件质量结论、正式 `AnnotationRevision` 或 Review。
- Review `APPROVED` 后，系统必须使用冻结规则自动执行 Cleaning / 训练资格检查；管理员 recheck 仅重新执行既有规则，不提供人工选择 PASS、WARNING 或 REJECT 的入口。
- 人工事件质量达到有效准入结论后，沿用 V1.25 的幂等规则自动创建并分配唯一组 AnnotationTask。
- Candidate 始终不是 Ground Truth；handedness 始终只作为辅助元数据。

### V26-FR-005 配药事件 current-task-first 工作台

- 页面必须优先回答“我在处理哪个配药事件”“当前进行到哪一步”“我现在应该做什么”。
- 桌面端信息层级固定为：顶部事件身份、拍摄时间、机位数量和当前业务阶段；中部以约 70% 的聚焦视频工作区和约 30% 的 `Current Action` 面板为主；底部渐进披露技术、历史和审计信息。具体比例可按目标视口响应调整，但视频和当前动作必须保持主导。
- 主业务流程只展示六个阶段：接收、机位质量、事件质量、配药动作标注、人工复核、训练资格检查。Media Probe、媒体状态、MediaPipe、Candidate 和 technical quality 是辅助事实，不得成为额外主流程节点。
- Candidate 失败或 `NO_HAND_DETECTED` 不得在没有真实服务端业务守卫时显示为流程阻断。
- 每个当前业务上下文只能有一个视觉主操作。操作必须由现有服务端事实和 capability 授权，不得由浏览器臆造。
- 典型主操作为：`RECEIVING` 时“结束接收”；机位质量未决时“判断当前机位质量”；机位质量已决而事件准入未决时“确认事件质量”；任务已分配或返工时“进入/继续配药动作标注”；revision 已提交且 `can_review` 时“进入人工复核”；Review 已通过时“查看训练资格检查”；流程完成时“查看结果”或进入获准的导出上下文。
- `N=1` 直接显示单个视频，只保留低权重“机位 1”身份，不渲染冗余机位切换轨道。`N>1` 使用紧凑机位选择器；选择项只保留扫描和选择所需信息，不永久展开媒体、technical quality、Candidate、安装元数据、ID 和同步事实。
- `Current Action` 是唯一常驻动作中心，不得在 Overview、Inspector、Annotation、Review 或 Quality 区域重复设置竞争性的“下一步”面板。
- `CaptureGroup ID`、`ClipAsset ID`、`capture_group_key`、batch ID、device、server receive time、上传/文件事实、媒体技术详情、Candidate 详情、同步声明与 `time_offset`、Revision/Review 历史、Cleaning provenance、审计和危险操作默认进入渐进披露区域，但必须保持可访问、可审计。

### 工作流展示推导与延期决策

- 当前工作台必须从已有权威服务端事实和 capability 推导展示状态，包括 `receipt_state`、逐视图质量、事件质量、`task.status`、`can_select_primary`、`can_submit`、`can_review` 和 `can_recheck_post_cleaning`。
- V1.26 不新增持久化 `CaptureGroup.next_action`、`CaptureGroup.blockers`、工作流状态表或 `WorkflowEngine`。
- 前端后续实现可使用 feature-local 纯展示函数集中推导 `stage`、`steps`、`primaryAction` 和 `blocker`，但它不是新的业务状态机，也不得覆盖服务端授权。
- 只有真实 UAT 证明多客户端重复解释已成为问题后，才重新评审 current-user-scoped、只读的 `stage`、`next_action`、`blocker_codes` 聚合读模型；该能力当前为 DEFERRED，不是永久拒绝。

## 4. 验收条件

- 本地完成单视频上传后，用户看到“打开配药事件”，事件 receipt 为 `COMPLETE`。
- 从事件内资产兼容 URL 进入时，页面替换跳转至对应 CaptureGroup，且不显示旧单视频“待确认标注任务”。
- 侧边栏只有一个“视频管理”入口，目标为 CaptureGroup 列表；历史 `/videos` 路由仍可直接访问。
- 外部 `RECEIVING` 事件在未收到显式 finalize 前保持 `RECEIVING`。
- 人工质量、Revision 和 Review 的既有权限、审计和人工闸门继续生效；Review `APPROVED` 后由系统确定性执行 Cleaning，管理员 recheck 不接受人工结果值。
- 工作台覆盖 `N=1`、`N>1`、当前阶段、单一主操作、Quality、Annotation、Review、Cleaning 结果、Candidate 失败不伪造阻断、渐进披露、键盘焦点和动态状态反馈。
- OpenAPI、Flyway、Java 定向测试、Web 单元测试、type-check 和 build 通过；自动化测试不等于真实 UAT。

## 5. 非目标

- 不合并 `ClipAsset`、`CaptureSession` 和 `CaptureGroup` 的数据库身份。
- 不恢复 CaptureSync runtime，不引入通用工作流引擎、超时终结或自动质量规则引擎。
- 不新增持久化 `next_action` / `blockers`，不把前端展示推导升级为领域状态机。
- 不删除历史单视频数据、路由、`training-data.v2` 或 V1.24-compatible 行为。
- 不实现多视频编辑器、全机位自动播放、3D、标定或 DatasetVersion 平台。
- 不控制相机、机器人、PLC 或医院边端设备。
