## 1. 目标与适用范围

用户希望界面“大道至简、大气、美观、简约、实用”，允许重新选择视觉方向，并委托先形成实施文档。本方案将上一轮推荐收敛为：**浅色专业工作区 + 视频优先详情页**。

本文件是独立的 V1.30 需求基线，取代本次尚未实施的 V1.29 UX v2 草案。继承 [V1.29 业务需求](../V1.29/配药视频数据处理平台需求文档_V1.29.md) 与 [视频工作区体验补充](../V1.29/v1.29-video-workspace-ux.md) 中未被本版本改变的边界；界面方向冲突以 V1.30 为准。V1.29 保留为前序 DRAFT，不因版本升级被视为已冻结或已完成。

正式视觉规范仍在 [设计系统](../../../DESIGN_SYSTEM.md) 中维护。实施时先将本方案验证后的视觉决策写入设计系统，再修改共享 Token 与组件，避免形成两套规范。V1.28 仍为上一正式运行时基线；现有实现、契约与测试证据应逐项核对，不能从历史版本名称推断当前功能。

首个交付闭环：打开项目视频列表 → 进入单/多机位采集记录 → 查看视频与检测事实 → 按需标注 → 使用现有导出入口。

## 2. 依据与设计判断

依据包括 V1.29 需求及 UX v1、现有列表与详情页代码、仓库 1440px 合成场景截图、上一轮查阅的官方产品资料。截图属于既有基线，不能据此声称当前运行界面已经过审计。

| 观察 | 本次设计响应 |
| --- | --- |
| 截图中深色侧栏比主体更抢眼 | 浅色导航退居辅助层，让视频和主要操作成为视觉中心 |
| 列表名称、状态与日期分散，浏览线索较弱 | 用稳定列对齐组织名称、时间、机位和已有状态 |
| 活跃任务截图中长表单接近占据详情一半宽度 | 默认以观看为主，进入标注后再展开编辑面板 |
| 已有大量追溯事实，但日常观看不需要同时阅读 | 技术详情按需展开，当前异常与恢复操作保持可见 |

这些是设计判断，不是用户测试结论；实施前以相同合成数据的列表和详情视觉稿验证。

## 4. 视觉与页面规格

### 全站框架

- 白色内容区、中性浅灰导航、深灰正文；蓝色集中表达主要操作、选中和焦点。深色用于媒体画布，不在首期增加主题切换。
- 使用现有无衬线字体栈和字号体系；实现前检查实际中文字体渲染，不通过缩小字号制造精致感。
- 以对齐、间距和文字层级划分内容；减少重复边框、阴影和卡片嵌套。具体尺寸和颜色在视觉验证后统一写入设计系统与现有 Token。
- 当前项目保持明确。优先复用现有项目选择能力；项目切换必须保持权限隔离并清理旧项目页面状态。
- 主导航突出“视频”和“标注任务”。成员与账号入口在后续共享导航调整中归入设置，保留角色可见性和原路由。上传以视频页主要操作呈现。

### 视频列表

- 顶部使用紧凑标题与操作区；“上传视频”为主要动作，保留已有导出范围及刷新反馈。
- 每行是一条采集记录，固定组织：名称、采集时间、机位接收情况、已有人工任务状态、操作。采集时间与平台接收时间使用准确字段标签。
- 打开记录后，返回列表应保持仍有效的已加载内容和浏览位置；刷新失败保留原内容并提供重试。
- 首期只使用 API 已提供的信息和分页能力。筛选、搜索、批量操作、检测汇总和缩略图均在确认契约支持后另行确定；不能对当前页过滤后暗示全量搜索。
- 相似画面下优先依靠名称、时间与机位信息识别记录。未提供受控缩略图时用简洁媒体图标，不伪造预览。

### 视频详情与可选标注

2026-09-06 用户追加确认：可直接优化重复入口和文案，优先科学逻辑与“大道至简”。界面统一用“标注”表达人工动作编辑，任务列表保留为跨记录待办入口；导出仍明确区分人工标注与机器检测。标注准备检查随侧栏展开，取消重复的二级开关；技术事实和历史继续按需查看。

- 顶部保留返回、名称、接收摘要和已有导出入口；播放器占据主体可用空间，默认不常驻长标注表单。
- 单机位省略选择器；多机位使用紧凑切换条，明确当前机位、缺失/不可用原因和标注时间基准，不暗示已同步播放。
- 检测摘要靠近播放器。处理中、失败、未检出与未知保持各自语义；骨架叠加复用现有实现，不将检测结果表达成人工合格。
- 普通观看入口按需展开标注准备或编辑面板；从标注、复核任务深链接进入时，直接显示对应操作上下文，保持原有权限和服务器状态判断。
- 展开编辑面板后仍能同时看到播放器、播放控制与主要提交操作；较窄视口使用上下排列，不产生页面级横向滚动。
- “设为开始/结束”靠近时间控制。复用当前时间精度、表单校验和提交方式，首期不自建拖拽时间轴或自动保存。
- 收起面板不丢弃未提交输入；切换机位、记录或离开页面时按现有能力补足未保存提示，不能把本地输入表述为已保存。
- 媒体参数、ID、来源、历史和审计放入详细信息；当前阻断原因、失败重试和权限提示在相关操作附近可见。

## 5. 保留的事实与行为

CaptureGroup 归属、多机位身份、项目权限、媒体授权、provenance、人工质量前置校验、任务状态、revision、Review 与 Cleaning 语义继续由现有服务端和契约决定。界面简化不删除事实或绕过判断。

播放仍经用户操作获取授权，不自动播放或预加载无权媒体；导出继续区分人工标签与 MediaPipe 检测事实，保留各自范围、权限、校验与确认。关闭面板不提交质量结论，不自动创建正式标签。

2026-09-06 用户追加授权：完善已发现的流程逻辑，并以本方案作为后续 UI/UX 权威。实现采用下列最小规则，不新增工作流引擎、数据库业务状态或模型依赖：

| ID | 逻辑修复 | 验收 |
| --- | --- | --- |
| V30-FR-001 | 人工导出重新核对最新组级质量、各机位质量与媒体输入快照，旧批准不替代当前有效性 | 批准后修改质量或输入即拒绝导出；历史修订不被修改 |
| V30-FR-002 | 正式提交、批准与人工导出必须有已验证媒体时长，时间段不得超过时长 | 缺时长和越界均失败；用户输入保留以便修正；拒绝复核仍可执行 |
| V30-FR-003 | 输入变化后，由管理员显式更新原任务输入并返工；新输入尚未提交时可重新选择主机位 | 同一输入提交后继续锁定；旧修订与原时间基准不可变；新机位重新标注 |
| V30-FR-004 | 10 fps 采样使用固定时间网格，取目标时刻及之后首个实际帧；稀疏视频不补造帧 | 24/25/30/60 fps 合成输入采样密度一致；时间戳仍来自 PTS；更新 profile 摘要以区分新证据 |
| V30-FR-005 | 新复核由不同于提交者的管理员执行 | 服务端拒绝自审；前端不显示可自审操作；既有审计记录保持原样 |
| V30-FR-006 | 播放位置仅在当前机位为标注主机位时可用于设置起止时间 | 切到参考机位禁用取时；折叠、刷新与导航不静默丢弃未提交输入 |

MediaPipe 与人工导出保持独立。历史证据不重新标记成新采样 profile；未完成旧 profile 作业应在切换前排空或由显式新作业重跑，不自动下载模型或改写历史结果。数据库历史、模型文件和派单策略不因本版本自动清理或变更。

## 7. 验收与验证记录

- 使用合成数据覆盖：空列表、加载失败、单机位、多机位、缺失机位、检测处理中/失败、无权限、无任务、待标注、复核与返工。
- 观看态不默认展开长表单；从任务深链接进入可找到对应操作；折叠不丢输入，变更上下文不会静默丢弃未提交内容。
- 1366 × 768 与 1440 × 900 无遮挡或页面级横向滚动；1920px 及更宽桌面检查内容上限；记录显示缩放比例。既有窄屏回退保持可用。
- 键盘可进入记录、切换机位、展开/收起面板和操作对话框；焦点可见，关闭后返回合理位置；状态不只靠颜色表达。
- 保留原有业务断言，为实际交互变更新增聚焦测试；截图更新前逐张检查差异，不以更新快照替代验收。
- 代码实施后执行仓库已有 `pnpm run web:check` 与 `pnpm run web:e2e`；导出仅用合成场景验证，不在设计阶段执行真实数据导出。
