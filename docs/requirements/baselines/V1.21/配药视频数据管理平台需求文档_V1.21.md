# 配药视频数据管理平台需求基线 V1.21（FLOW-FIRST MINIMAL EXPORT）

> 文档版本：V1.21<br>
> 文档状态：**当前业务需求基线**（LEAN-P0）<br>
> 生效日期：2026-08-14<br>
> 前一版本：V1.20<br>
> 生效规则：本版本只覆盖 V1.20 中与 MediaPipe 准确率、播放器和训练数据导出冲突的条款。V1.20 及 V1.18 未被替代的安全、权限、审计、数据完整性和领域边界继续生效；V1.19 多相机同步仍为 DEFERRED。

## 1. 当前唯一业务主线

```text
边端接收
→ 视频管理
→ 单视频 MediaPipe 手部 Candidate
→ 人工配药动作标注
→ Review
→ Cleaning
→ 可用数据
→ training_data.parquet
```

当前优先级为：流程完整性 > 数据正确落库 > 人工标注可用性 > 可用数据导出 > MediaPipe 准确率优化。

## 2. MediaPipe 与 Ground Truth

- MediaPipe 只产生 `CandidateAnnotation`，提供时间戳、bbox、21 点、handedness、置信度和 provenance；
- `CandidateAnnotation` 不是 Ground Truth，不能自动生成正式 `AnnotationRevision`；
- AI 不得自动 Review PASS，也不得自动 Cleaning PASS；
- 人工正式 `AnnotationRevision` 是动作标签唯一来源；
- 没有 Candidate、Candidate 质量较差或 handedness 无法判断时，人工标注流程仍可继续。

## 3. P0 手部检测验收

P0 要求：

```text
MP4 入库
→ AIJob
→ MediaPipe 实际运行
→ SUCCEEDED
→ HAND_DETECTED / NO_HAND_DETECTED
→ Candidate 数据结构与时间戳正确（发现手时 Candidate > 0）
→ Skeleton Overlay 可显示
```

暂不作为 P0 Gate：Left/Right 正确率、两手 identity consistency、遮挡鲁棒性、复杂动作召回率、关键点精度指标和模型评估分数。handedness 保留为 `LEFT / RIGHT / UNKNOWN` 辅助元数据；无法识别的方向不得使结构有效的手部 Candidate 失效，也不得影响 Annotation、Review、Cleaning 或导出准入。

## 4. 播放器与 Overlay

- 普通笔记本无需全屏即可同时看到视频主体、Overlay、检测状态和后续操作；
- 播放器保持原始画面比例并限制在工作台可读上限，目标高度约 `60–65vh`；
- 全屏目标必须是同时包含 `<video>` 与 SVG/Canvas Overlay 的共同容器，不能只让 `<video>` 全屏；
- 不引入新播放器库，不重写 Overlay；
- 短期播放授权和过期安全策略保持不变，用户过期后重新播放即可获取新授权。

## 5. 人工流程与可用数据准入

只有以下事实同时成立的数据才是当前可用训练数据：

1. 视频为未删除的 `INGESTED` MP4；
2. 人工视频质量为 `QUALIFIED`；
3. 动作标签来自当前正式 `AnnotationRevision`；
4. 人工 Review 为 `APPROVED`；
5. 与当前 asset SHA、revision document SHA、label schema digest 和 quality version 绑定的 Cleaning run 为 `SUCCEEDED`，结果为 `PASS`。

AI Candidate 的存在、数量、Left/Right 或分数都不能代替上述人工与 Cleaning 准入事实。

## 6. 最小训练数据导出

P0 保留显式、本地、只读 `tools/minimal-export`，并补充一个供 Web 下载的项目级、显式、同步、只读 API。两者共同读取数据库权威投影 `training_data_eligibility` 与 `training_data_candidate_observations`，不各自维护资格 SQL：

```text
Cleaning PASS 可用数据
→ training_data.parquet
```

```text
GET /api/v1/projects/{project_id}/training-data/preview
GET /api/v1/projects/{project_id}/training-data/download
```

API 只允许全局 `ROLE_ADMIN` 且具有当前项目 ACTIVE `ADMIN` membership 的身份；下载使用
`attachment; filename="training_data.parquet"` 和 `Cache-Control: no-store`。Preview 的
`training_row_count` 是 Parquet 行数，不是视频数：每行是一个 MediaPipe Candidate 手部观测落在一个
当前人工 `APPROVED` 动作区间 `[start_ms, end_ms)` 内。当前不引入 DatasetVersion、Export Job、Worker、Queue 或新表。
当前 Parquet schema 为 `training-data.v2`；`action_start_ms`、`action_end_ms` 直接来自当前人工
`AnnotationRevision` 的 segment，且每行满足 `action_start_ms <= timestamp_ms < action_end_ms`。

每行表示人工动作时间段内的一个 MediaPipe 手部观测，至少包含：

```text
video_id
timestamp_ms
action_start_ms
action_end_ms
action_label
annotation_revision_id
hand_index
hand_presence
hand_mask_available
candidate_annotation_id
handedness
handedness_score
handedness_is_ground_truth
21 × (x, y, z)
algorithm_key
algorithm_version
model_sha256
profile_sha256
```

`action_start_ms`、`action_end_ms` 和 `action_label` 直接来自当前人工正式 `AnnotationRevision` 的
`annotation_document.segments`，采用 `[start_ms, end_ms)`；`timestamp_ms` 必须属于该区间。
`algorithm_key`、`algorithm_version`、`model_sha256`、`profile_sha256` 是每行必需的 Candidate provenance。
`hand_presence` 表示该行的候选手存在；当前没有像素 mask 时 `hand_mask_available=false`，不得补造第二只手或假的 landmark。
文件元数据必须明确：动作标签和动作区间来自人工正式 revision；手部几何来自 Candidate 且
`hand_geometry_is_ground_truth=false`；坐标系为 `normalized_image_xy_and_mediapipe_relative_z`；
`handedness` 和 `handedness_score` 仅为 Candidate 手部元数据，`handedness_is_ground_truth=false`，不提供 generic `confidence` 字段。

导出规则：

- 动作区间采用 `[start_ms, end_ms)`；区间外 Candidate 不进入训练行；
- 未通过当前 Cleaning PASS 的数据不能进入输出；
- 默认不导出 MP4，`video_id` 只用于回查平台原视频；
- 两次只读查询必须使用同一一致性快照，数据库会话强制只读；
- 默认只允许 synthetic profile；当前没有正式的非合成数据授权模型，非合成 profile 必须 fail closed；
- 输出必须可由 PyArrow 等通用工具离线回读。

## 7. 明确非目标

本版本不建设或恢复：

- DatasetVersion UI、复杂 freeze/approval/export pipeline；
- 新 Export Worker、新 Queue 或自动批量导出；
- 默认视频打包、Parquet 用户平台或训练平台；
- LeRobot 平台、机器人 action/state 或平台核心模型改造；
- CaptureSync、多相机同步播放、Canonical synchronized Parquet；
- MediaPipe 准确率优化作为当前流程 Gate。

现有 `datasetexport`、export-worker、历史契约、迁移和测试保留但继续 FROZEN；不做 Physical Reduction。后续如需 LeRobot，使用平台外的简单转换器映射 `video_id/timestamp/landmarks/action_label`，不得伪造机器人状态或动作。

## 8. P0 完成定义

至少一条合成或明确授权并隔离的视频完成：

```text
接收
→ INGESTED
→ MediaPipe
→ Candidate / Skeleton Overlay
→ 人工 AnnotationRevision
→ Review APPROVED
→ Cleaning PASS
→ 可用数据
→ training_data.parquet 可回读
```

同时必须证明：Candidate 与正式标签隔离、Left/Right 不影响流程、AI 不自动 Review/Cleaning、未通过 Cleaning 的数据无法导出、默认输出不含视频。
