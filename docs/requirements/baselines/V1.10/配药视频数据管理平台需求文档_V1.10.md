# 配药视频数据管理平台需求基线 V1.10

> 文档版本：V1.10
> 文档状态：当前基线
> 生效日期：2026-07-30
> 前一版本：V1.9
> 生效规则：本版本继承 V1.9；本版本明确修改的条款优先于 V1.9 及其历史继承基线。

## 1. 本次变更

P0 数据集闭环收敛为已经具备真实生产者和校验规则的主 Step 训练数据：

```text
原始视频
→ 人工质量判断
→ 主 Step 时间段标注
→ 独立复核
→ post-clean
→ 数据集冻结
→ 内部训练导出
```

Object 框、`privacy_region`、帧抽取和 COCO 导出不再是 P0 验收项。它们进入 P1，只有在真实训练用例、轻量标注工具边界、标签规范和验收样本获批后才实现。

## 2. P0 导出契约

新建数据集构建配置必须固定 `p0-dataset-export-v2`。该 Profile 只包含：

- `README.md`
- `label_schema.json`
- `manifest.jsonl`，每条记录必须包含 `streams`
- `action_segments.jsonl`
- `splits/`
- `videos/raw/`
- `SHA256SUMS`

Profile 的标注范围为 `STEP_ONLY`，输入策略为 `RAW_CLIP_ASSET_V1`，划分单位为 `CAPTURE_SESSION`。`videos/raw/` 表示当前冻结快照引用的原始 ClipAsset，不表示对外共享、隐私放行或派生清洗视频已经生成。导出仍限内部 `MODEL_TRAINING` 用途，并受项目权限、独立审批、明确有效期、审计和短期下载授权约束。

## 3. 兼容与演进

1. 已存在的 `p0-dataset-export-v1` 构建配置和导出申请保持可读、可校验和可继续执行，不改写历史事实。
2. 部署 V1.10 后只允许新建 `p0-dataset-export-v2` 构建配置。
3. 数据库只接受 v1 或 v2 的准确 key/digest 配对，拒绝交叉组合和未知 Profile。
4. `objects_coco.json`、`frame_manifest.jsonl`、`frames/`、派生 `videos/clean/` 及其他扩展产物进入后续版本，不创建空文件或伪实现。
5. 导出批准必须与首次 ExportAttempt、Outbox 和真实消费者在同一纵向切片中实现；在此之前，申请继续停留在 `REQUESTED`，不得只增加一个无消费者的批准状态。

## 4. 最低验收

1. 新建构建配置固定准确的 v2 key 和 SHA-256。
2. 历史 v1 构建配置的幂等重放、冻结校验和导出申请继续成立。
3. OpenAPI、React 类型、Flyway 约束和后端校验同时接受准确的 v1/v2 历史响应，并拒绝未知或错配 Profile。
4. Profile v2 不宣称存在 Object、COCO、帧或派生清洗视频。
5. Java、React Web、Python、OpenAPI、迁移和模块边界门禁通过后，才能宣布该切片完成。

## 5. 继承与冲突处理

除本版本明确调整的 P0 标注范围和导出契约外，V1.9 的全部条款继续有效。历史基线中要求 P0 Object 标注、`privacy_region`、`objects_coco.json` 或 `videos/clean/` 的条款，统一由本版本替换；发生其他冲突时，V1.10 优先。
