# 配药视频数据管理平台需求文档 V1.23

> 文档版本：V1.23
> 状态：当前正式业务需求基线（FLOW-FIRST LEAN-P0）
> 生效日期：2026-08-20
> 正式继承基线：V1.21 FINAL
> V1.22：仅为 DRAFT / DEFERRED，不属于本正式继承链

## 1. 基线定位

V1.23 是在 V1.21 FINAL 之上的小范围正式变更基线。除本文件明确覆盖的条款外，V1.21 以及其未被替代的 V1.20、V1.18 条款继续有效。

V1.23 不把 `docs/history/requirements/drafts/V1.22/` 中的未来多视角设计转为正式需求，也不修改、删除或否定该 Draft。V1.22 继续保持 DRAFT / DEFERRED，待未来单独形成正式基线后再实施。

## 2. 当前唯一 P0 主线

当前产品必须保持一条可运行、可审计、可回退的纵向闭环：

```text
边端接收
→ CaptureSession / Camera / ClipAsset 事实
→ Media Probe
→ INGESTED
→ 单视频 MediaPipe Hand Candidate
→ 人工质量判断
→ AnnotationRevision
→ Review
→ Cleaning
→ training-data.v2 / training_data.parquet
```

P0 的视频接收、视频管理、媒体探测、AI 候选、人工标注、复核、清洗和最小训练数据导出必须继续可用。AI 输出只能进入 `CandidateAnnotation`，不得绕过人工确认、正式 revision、复核和清洗进入正式训练数据。

`handedness`、`handedness_score`、algorithm/model/profile provenance、审计和权限是可追溯性与安全约束，不得因本次物理瘦身删除。

## 3. 当前 P0 边界

CaptureSync、多相机同步和 `synchronized-frame` 不属于当前 V1.23 P0 runtime。当前产品保留上传过程中的 CaptureSession、CameraSet、CameraStream、camera identity、时间戳和 `DeclaredSyncStatus` 等接入事实，但不提供 CaptureSync 同步作业、同步查询、同步 HTTP API 或同步运行编排。

未来多视角、时间基准、校准和 3D 重建仍是产品演进方向，暂由 V1.22 Draft 及相关历史/专题文档承载，不要求当前 P0 为其保留未接线的运行代码。

## 4. Physical Reduction 授权

在逐项证明没有当前 P0 producer、consumer 和 runtime dependency 后，可以物理移除不属于当前 P0 的 CaptureSync Core API 闭包，包括：

- CaptureSync Java runtime、应用服务、Controller、worker HTTP 入口和专属异常处理；
- CaptureSync 专属 DTO、job/revision/stream model、repository 和 persistence/integration adapter；
- CaptureSync 专属 OpenAPI operations、schemas 和 contract tests；
- CaptureSync 专属安全 matcher、worker authentication branch 和测试。

本版本授权的是当前 Core API 运行面退役，不授权一次性清除所有未来资料。CaptureSync 的 worker、message、schema、golden-capture-g0 和其他独立工具属于后续独立批次，必须再次审计后处理。

## 5. 必须保留的能力和事实

以下能力不因 CaptureSync runtime 退役而改变：

- `CaptureSession`、`CameraSet*`、`CameraStream*`、`ClipAsset*`；
- `DeclaredSyncStatus` 以及上传 metadata 中用于描述采集事实的字段；
- Upload / ingest、Media Probe、媒体作业和 `/videos` 视频管理；
- MediaPipe / HandPose Candidate、`AIJob`、`AIJobAttempt` 和自动调度；
- `CandidateAnnotation`、Skeleton Overlay、Quality、`AnnotationRevision`、Review、Cleaning；
- `MinimalTrainingDataExportService` 和 `training-data.v2`；
- `iamproject`、`governance`、`mediaprivacy`、IAM、审计、数据完整性和安全配置；
- P0 所需的 Inbox / Outbox、worker lease/heartbeat/result 和安全边界；
- 当前 OpenAPI、事件和 JSON Schema 中服务 P0 的上传、视频、媒体、候选、标注、复核、清洗和训练数据契约。

## 6. 数据库与历史资料

V1.23 不修改或删除任何历史 Flyway migration，不重编号、不改写、不新增 DROP migration。V1～V66 均为 `HISTORICAL_IMMUTABLE`，包括 V62、V63、V65 和 V66。

CaptureSync 历史数据库表可以暂时 dormant；本次 Physical Reduction 不要求数据库表名、历史 migration 或历史数据归零。数据库物理清理必须在未来通过独立评审和新的 forward migration 决定。

## 7. V1.22 的状态

V1.22 继续为 DRAFT / DEFERRED，不覆盖 V1.23，不授权当前多视角实现。V1.23 不删除 V1.22 文档，也不把未来方向描述为永久取消；本版本只规定当前 P0 不为未接线的未来 runtime 提前保留实现。

## 8. 验收要求

本版本变更完成后必须证明：

1. V1.21 P0 主线和其安全、审计、权限、数据完整性约束未被削弱；
2. CaptureSync Core API 运行面不存在悬空 Controller、生产调用者或 OpenAPI operation；
3. P0 Java 编译、定向测试、Spring Modulith、契约/OpenAPI 和 requirements manifest 校验通过；
4. 历史 Flyway、V1.22 Draft、未来 worker/message/schema/tooling 未被本批次误删；
5. 变更可通过单一提交回退，且不涉及强制推送或历史重写。
