# 配药视频数据管理平台需求基线 V1.7

> 文档版本：V1.7
> 文档状态：当前基线
> 生效日期：2026-07-24
> 前一版本：V1.6
> 生效规则：本版本继承 V1.6；本版本明确修改的条款优先于 V1.6 及其历史继承基线。

## 1. 本次变更

P0 的平台使用者是内部训练数据团队。视频上传完成并通过对象完整性与 SHA-256 校验后，已加入项目的内部成员应能直接手动查看视频；不把异步媒体技术检测误设为人工查看的前置审批。

```text
边端自动上传或平台本地上传
→ 上传完整性校验完成
→ 项目成员直接手动查看
→ 媒体技术检测（可并行或随后执行）
→ 人工质量结论
→ 标注、复核、清洗、冻结和导出训练数据集
```

医院侧只负责采集和自动上传，不使用本平台管理端。平台不自动播放，内部成员必须显式点击播放；播放授权仍是短期、项目范围内的只读授权，并保留授予审计。

## 2. 播放、技术检测与质量结论的边界

1. ACTIVE 项目 ADMIN/MEMBER 可对已完成上传完整性校验、未删除且为受支持 MP4 的 `ClipAsset` 显式申请短期 `DATA_REVIEW` 播放地址；`UPLOADED`、`INGESTING`、`INGESTED` 和 `INGEST_FAILED` 都不因媒体任务状态本身拒绝人工查看。
2. 项目 Membership、未删除状态、受支持内容类型、最短 TTL、`no-store` 响应、地址不落库和追加式播放授权审计仍是必须保留的边界。
3. 媒体技术检测继续负责时长、编码、完整解码和 `MediaReport` 等技术事实；它不自动播放，也不自动给出人工质量结论。
4. 人工质量结论 `QUALIFIED`、创建标注任务、提交正式标注及进入训练候选，仍要求媒体检测成功并处于 `INGESTED`。检测失败的视频可以被人工查看、判定不合格并由管理员软删除，但不能绕过技术事实进入标注或训练。
5. 播放失败应明确显示浏览器或对象存储问题及重试入口；平台不承诺所有上传内容一定可被浏览器解码，不能将播放成功误写为媒体检测或质量通过。

## 3. 最低验收

1. 合成 MP4 完成上传后，在尚未发起媒体检测时，ACTIVE ADMIN/MEMBER 可显式取得短期播放授权并在浏览器手动查看。
2. `INGESTING` 或 `INGEST_FAILED` 不会单独阻止人工查看；已删除、跨项目或非 MP4 资产仍被服务端拒绝。
3. 媒体检测、人工质量、标注和训练候选的状态边界保持不变：未 `INGESTED` 的视频不能被记录为 `QUALIFIED` 或创建标注任务。
4. 页面把“视频查看”“检测媒体信息”和“人工质量判断”表达为三个不同动作，不使用“审核完成后才能播放”等误导性文案。
