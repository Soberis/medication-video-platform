## 1. 产品定位与责任边界

Platform 是一个面向视频数据生产的处理平台。它接收外部采集端上传的视频和必要的接收声明，维护视频归组与媒体事实，运行 Media Probe、MediaPipe 和动作候选分析，在项目确实需要 human ground truth 时提供人工标注与确认，并生成受控的训练数据导出。

Platform 负责：

- 接收 Local Upload 或 External Ingest 提供的视频数据及其显式归属；
- 按 CaptureGroup 维护一次采集记录及其 CameraStream、ClipAsset 成员；
- 生成媒体技术检查、MediaPipe 检测和 Action Candidate 等可追溯事实；
- 在授权、版本、媒体身份和 provenance 校验下支持人工标注及受控导出；
- 维护权限、审计、幂等、重试、租约、心跳和失败恢复边界。

Platform 不负责：

- Hospital、Ward、Patient、Nurse、HIS 等医院业务或身份系统；
- 药品业务、处方业务、护理业务或医院工作流；
- physical camera fleet、物理摄像头资产、摄像头控制、标定或设备管理；
- 采集端运维、工控机控制、机器人、PLC 或其他真实硬件；
- 模型训练、训练效果保证或自动宣布数据合格；
- 从文件名、上传顺序或时间接近度猜测视频归属。

开发、测试和 CI 只使用合成数据；平台不得接触生产患者视频、医院生产账号、生产密钥或生产数据库。原视频、模型文件、令牌、私钥和预签名 URL 不得提交到仓库或写入日志。

## 3. 领域对象与命名

### 3.1 CaptureGroup 是一次采集记录

CaptureGroup 表示上游明确声明为同一次采集的一组视频及其接收事实。它是项目范围、成员边界、媒体事实、AI 证据、人工标注和导出的统一归属。

N=1 与 N>1 使用同一模型：

~~~text
CaptureGroup
└─ CameraStream #1..N
   └─ ClipAsset
~~~

N=1 只表示当前采集记录包含一路视频，不创建第二条 single-video 产品流程。

### 3.2 CameraStream 是视频视角

CameraStream 是 CaptureGroup 内的一个视频视角及其来源、时间基准和接收状态。它不是 Platform 管理的物理摄像头资产，不提供设备注册、设备生命周期、摄像头控制或摄像头 fleet 管理。

来源设备标识、camera index、camera channel、time offset 和 DeclaredSyncStatus 只作为外部来源与接入 provenance 保留。CaptureSession、CameraSet 及 metadata 声明仍是接入事实，不因“无设备管理”而删除。device_time_utc 表示拍摄侧时间，created_at 表示平台记录时间，二者不得混为同一时间。

### 3.3 ClipAsset 是不可变媒体证据

ClipAsset 代表受控对象存储中的一个视频版本及其内容身份。当前有效性必须由媒体状态、对象身份和 SHA-256 等事实证明；换源或重新绑定必须形成新的输入版本，不能改写已经引用的人工 revision 或 AI evidence。

## 4. 唯一主链

当前产品主链固定为：

~~~text
数据接收
  ↓
CaptureGroup
  ↓
Media Probe
  ↓
├─ MediaPipe 手部事实
└─ Action Candidate 动作候选
  ↓
必要时人工标注 / 确认
  ↓
Export Eligibility
  ↓
human-demonstration-hdf5.v1
~~~

其中：

- 数据接收必须使用上游明确的 CaptureGroup 归属，不依据偶然文件特征自动合组；
- Media Probe 建立媒体技术事实，MediaPipe 与 Action Candidate 在媒体可读取后可以独立运行；
- Action Candidate 只在存在受控人工任务且满足自动派发准入时自动派发；特殊或未决场景保留授权用户手动触发；
- 人工标注链仅在项目需要 human ground truth 时启用，不是所有视频接收或 MediaPipe detection evidence 的强制前置；
- Export Eligibility 是导出前的唯一后端权威判定；
- HDF5 是训练数据文件，不是关系数据库、原始视频备份或 AI 运行日志的替代物。

不建立通用 Workflow Engine，不持久化通用 next_action、blockers 或与当前主链无关的工作流状态。

主链表达职责顺序，不要求每条采集记录跑完两个 AI 分支。未启用人工标签的记录可停留在视频与 MediaPipe 证据阶段；由于当前唯一 HDF5 包含人工标签，该记录尚不能导出。纯人工标注不依赖 Action Candidate 成功，Action Candidate 也不是 HDF5 的硬闸门。现役 CaptureGroupView 只读投影和前端派生提示继续保留，不因名称含 View 或 blockers 被当作通用工作流删除。

## 5. 数据接收、媒体与项目工作区

### 5.1 接收与归组

- Local Upload 和 External Ingest 都必须将文件与显式的项目、采集记录和来源声明关联。
- 接收保留 upload batch、capture session、CameraStream、ClipAsset、声明值与服务端复核值。
- 多机位数据必须在同一个 CaptureGroup 中保留其成员边界；单路数据也使用 CaptureGroup。
- 平台不控制上传端的录制、缓存、重传策略和物理设备。
- 已发布的 external ingest compatibility API、历史 migration 和既有接收事实不得因产品概念收敛而自动删除。

上传声明、对象实际 SHA 和服务端复验分别保留；断点续传、幂等、接收关闭、缺失机位与媒体处理状态不能相互替代。metadata 与 ingest manifest 按各自已发布契约承载来源事实，不能假定互为副本。接收尚未闭合的记录不通过超时自动判合格；COMPLETE 与 CLOSED_INCOMPLETE 保留真实收件含义，不等于技术质量 PASS。

### 5.2 Media Probe

Media Probe 只产生媒体技术事实，例如可读取性、时长、帧率、编码和媒体报告。它不伪装成人工质量，也不直接宣布动作标签正确。

缺少已验证时长、媒体无法读取、当前 ClipAsset 不存在或输入身份不匹配时，后续依赖该事实的操作必须明确阻断或保持待处理，不得用默认时长、文件名或 UI 状态补齐证据。

## 6. 两条独立的 AI 证据链

### 6.1 MediaPipe 手部事实

MediaPipe 是几何检测证据链，只能写入 MediaPipe job、attempt 和 CandidateAnnotation 等机器事实，不得写入人工质量、AnnotationRevision、AnnotationReview、Cleaning 或导出批准结论。

逐视图机器状态保持不同语义：

- HAND_DETECTED：检测到一个或多个手部候选；
- NO_HAND_DETECTED：作业成功完成，但当前输入没有检测到手；
- UNKNOWN：结果暂时不能形成可用判断；
- FAILED：机器执行、解码或结果处理失败。

成功但没有手不等于失败。API 查询或读取 MediaPipe 结果失败属于结果可用性/读取故障，不得被改写为 AI job FAILED；只有作业执行失败或服务端明确判定结果失败时才改变作业失败状态。读取失败不能被当作有效空结果，也不能伪造坐标。

每项当前证据至少应能追溯到 CaptureGroup、CameraStream、ClipAsset SHA-256、输入摘要、算法/模型/profile、job/attempt、分析范围和结果摘要。迟到、重复或旧来源结果不得覆盖当前有效证据。

手部采样使用已冻结 profile 的真实 PTS 与固定目标时间网格，选择目标时刻及之后首个实际帧；不按假定帧率补帧。10 fps 是已有 MediaPipe profile 的采样规则，不是动作模型的采样率或检测精度承诺。handedness 仅作辅助元数据，不能作为人工标注、复核、Cleaning 或导出准入条件；21×3 landmarks 不代表经标定的真实世界三维轨迹。

### 6.2 Action Candidate 动作候选

Action Candidate 是机器生成的动作时间段草稿，是辅助人工工作的候选证据，不是人工 Ground Truth，不是质量结论，也不是可直接导出的最终标签。

动作候选规则：

- 使用任务绑定的不可变 label schema，不硬编码一组脱离任务的动作标签；
- 片段保存 start_ms、end_ms、label，使用主视频原始时间轴和半开区间 [start_ms, end_ms)；
- 必须满足 0 ≤ start_ms < end_ms ≤ 已验证视频时长；
- 单层 PRIMARY_STEP 候选不得重叠；空白表示尚未覆盖，不自动解释为 IDLE、无动作或不合格；
- 候选回传必须校验当前 job、attempt、任务、主视频、输入版本、schema、标签合法性、窗口完整性和 provenance；
- 越界、非法标签、截断、重叠冲突或来源失效时，不发布为可采纳的完整草稿；保留可诊断的原始失败信息；
- 有效空数组表示本次模型没有给出候选，不证明视频没有动作；
- 模型自报 confidence 不是校准正确率，也不触发自动批准；首版不要求 confidence 必须存在，缺失时不得补造 1.0 或其他置信度；
- AI 不能自动确认、提交、复核、清洗、放行或改写人工 revision。

动作预标注不等待 MediaPipe 成功。配套 HDF5 导出才要求当前 MediaPipe 证据和人工标签同时满足最终准入。

### 6.3 动作自动派发与手动兜底

合格自动派发的准入至少同时满足：

1. 主视频存在、媒体已就绪且当前输入有效；
2. CaptureGroup 处于允许进入人工标注的组级质量结论；
3. 已存在授权、有效的人工标注任务；
4. 当前任务、输入版本、label schema 和推理配置没有相同的 ACTIVE 或 SUCCEEDED 作业。

系统覆盖先建任务后完成组级质量、先完成组级质量后建任务和主视频后就绪等到达顺序；重复事件只产生一个等价动作作业。质检未决、特殊视频或其他不满足自动准入的场景不自动占用 GPU，但在权限、媒体和来源校验通过后保留任务内手动触发。

无人工任务时不自动创建任务。手动触发仅绕过自动调度条件，不绕过权限、媒体/隐私、任务输入和来源守卫，也不自动授予人工提交或导出资格。“覆盖不同到达顺序”要求对已有合法任务重新检查条件，不要求放宽任务创建准入或恢复退休的质量合格自动建任务事件。

自动派发、手动触发和 Worker 回传都必须使用既有 job、attempt、outbox、inbox、lease、heartbeat、retry 和幂等边界。动作作业失败不阻塞从零人工标注；部分窗口失败不作为完整动作草稿发布。

### 6.4 动作推理与资源边界

首轮沿用已选定的评估起点：RTX 4090 24GB、Qwen/Qwen3-VL-8B-Instruct、BF16、每卡一个串行消费者。15–30 秒窗口、1 fps 基线及 2 fps 对照是待实测配置，不是产品准确率、吞吐、显存上限或无 OOM 承诺。模型与依赖固定版本，模型在仓库外受控准备并记录 SHA-256，运行时只从本地加载。

长视频必须保留真实时间戳、窗口边缘上下文和回映射，不能以假定 30 fps 或静默裁剪修正非法输出；重复动作不能仅凭同名与时间相交自动合并。完整窗口校验失败时报告失败，保留人工入口。平台内合成占位 Worker 只证明契约路径；外部动作 Worker 的真实推理、显存与质量须单独验证。首版不增加 YOLO、训练、模型服务平台或历史任务批量回填。

## 7. 标签 Schema

标签库是全局账号级资源。全局 ADMIN 可发布标签；普通成员只能读取被授权的当前 schema。项目级 GET 可作为任务页面的兼容读取入口，但标签真源仍是全局不可变 schema。

每次发布得到新的不可变 schema 和 schema digest：

- label_id 稳定且机器可用；
- display_name、description 和起止判据面向标注员；
- 新任务绑定创建时的 schema；
- 已有任务、revision、候选和导出历史继续使用原 schema/digest；
- 不编辑、删除、排序或按项目覆盖已经发布的标签语义；
- 不因模型输出自动创建标签；
- Worker、前端和服务端优先读取任务绑定的 schema，不以本地调色板或旧版本硬编码作为业务真源。

派发、回传校验、候选展示和人工提交使用同一任务绑定版本。执行期间发布新全局 schema 不改变已有 job 的标签集合；缺少任务 schema 时不能用最新全局版本或硬编码集合冒充已验证快照。标签显示名称、说明、起止与易混淆判据应可从该版本解析；颜色映射只负责展示。

project-scoped 标签 POST 是待退役的兼容表面，见 D4。在 D4 决策和后续契约变更完成前，不删除端点、OpenAPI 描述或相关历史测试。

## 8. 人工标注、确认与 Revision

人工标注是可选的 human ground truth 流程，而不是 MediaPipe 机器证据的默认前置。项目需要时，一个 CaptureGroup 在当前有效输入上进入受控 AnnotationTask；任务页面是视频工作区中的任务视图，不形成第二个独立产品。

用户通过显式、受权限和幂等保护的 assignment 命令表达人工标签意图；单独提交合格质量结论不创建任务。每个 CaptureGroup 保持唯一任务及版本历史，不因重复命令重复建单或悄悄改派。当前输入已提交后锁定主视频时间基准；输入变化时由授权管理员显式更新任务输入并返工，新输入尚未提交时可重新选择主视频，旧 revision 与时间基准不变。普通成员只读取和提交自己被分配的任务。

标注员可以在原始视频时间轴上：

- 创建、修改、删除、拆分、合并和撤销动作片段；
- 调整 start_ms 和 end_ms，或使用当前播放时刻设置边界；
- 从任务绑定 schema 中选择合法标签；
- 检查候选覆盖与所有空白，不能把播放过当作人工确认；
- 在无法判断时保留空白，不能补写没有画面证据的动作。

正式提交生成 append-only AnnotationRevision。提交不自动确认、不自动导出；人工 revision 必须经过既有 AnnotationReview 规则，只有人工确认后的 APPROVED Revision 才能成为最终训练标签。

沿用当前权限语义：全局 ADMIN 且具有 ACTIVE 项目 ADMIN Membership 的管理员可以确认自己提交的标注，不要求额外的日常双人确认；非授权用户不得提交或确认。被拒绝的 revision 不被改写，返工形成新的 revision 并保留审计。

如果人工草稿使用了 Action Candidate，revision 必须保留其来源 job/候选关联或等价的可查询 provenance。候选晚到、重新推理、输入变化或 schema 变化都不得静默覆盖页面未提交内容、既有草稿或已提交 revision。

### 8.1 初始化、编辑与失败恢复

- 仅完整校验通过、来源当前有效且任务从未编辑时，自动将候选呈现为待人工检查的初始草稿；此操作不生成正式 revision、不提交质量或 Review。
- “未编辑”同时检查服务端版本和浏览器未保存修改；用户清空草稿也算编辑。候选晚到或版本改变时提示用户，不覆盖现有工作。
- 解析失败、部分窗口失败、来源失效和有效无候选分别反馈。部分结果仅供诊断，首版不允许选择性采纳失败作业；人工仍可从零标注。
- 时间轴联动主视频，支持拖动边界，也提供数字输入、设为当前时刻等非拖拽等价操作；参考机位播放时不能把其时刻写为主视频区间。
- 保留全部空白并支持按时间顺序巡检，不以固定阈值隐藏短空白；长候选内部也可拆分补标。毫秒是存储单位，不承诺模型或播放器具有毫秒精度。
- 折叠、切换机位、离开或刷新不得静默丢失未提交输入。Tab 保持原生导航，快捷键不干扰输入框，按钮提供等价操作。

## 9. Quality、Review 与 Cleaning 语义

以下事实保持区分：

- Media technical quality：媒体/设备技术状态，是媒体有效性的事实；
- CaptureGroup quality review：判断该采集记录是否允许进入人工标签流程；
- AnnotationReview：判断人工 revision 的标签质量；
- Export Eligibility：判断当前记录是否满足最终训练导出全部条件。

Cleaning 不再作为用户必须经过的工作流阶段。它没有独有的数据清洗动作，而是对已有人工质量、组质量、Review、媒体和输入条件的确定性复算。历史 Cleaning 表和历史记录保留；是否停止生成新的独立 Cleaning 事实由 D1 决定。在 D1 和后续明确授权前，不删除 Cleaning runtime、字段、migration 或历史数据。

Quality、Review 和 Export 的职责不能因为“简化”而互相伪装：人工 Review APPROVED 不等于媒体技术质量通过，MediaPipe 成功不等于人工标签正确，前端状态也不等于后端最终放行。

## 10. 唯一导出与 Export Eligibility

### 10.1 唯一产品导出

当前唯一用户可见训练导出格式是：

~~~text
human-demonstration-hdf5.v1
~~~

不恢复 hand-landmarks.v1 CSV、human-annotations.v1 CSV、旧事件 manifest、training-data.v2、LIBERO/robomimic、LeRobot、RLDS、Parquet 或其他第二套训练导出。

### 10.2 导出 UI：一个列表、一套选择交互

导出入口位于当前项目的视频工作区，提供当前项目可导出记录列表：

- 默认不选；
- 勾 1 条表示单条导出；
- 勾多条表示多条导出；
- 全选表示本次完整加载的当前项目可选择记录；这些记录仍须通过下载时的后端最终校验；
- 显示已选择 N 条；
- 候选列表独立读取当前项目完整授权范围，不以主视频分页列表的已加载页冒充项目全集；
- 下载始终携带明确的 capture_group_id；零选择不能下载；
- 列表加载中不可选择，失败可重试，下载失败不静默跳过失效记录；
- 详情页不另建第二套导出范围或数据集版本概念。

前端“可选择/可导出”只是 UX 初筛与预判。前端不得把已完成、已批准或本地状态直接表述为最终导出成功。

入口要求全局 ADMIN 与 ACTIVE 项目 ADMIN。候选列表通过现有 cursor API 读完项目 CaptureGroup 和 PROJECT 授权范围的人工任务，按 ID 去重；正常显示 COMPLETED 且当前 revision APPROVED 的记录，并标为“可选择”。缺页、失败、取消、游标循环或非 PROJECT 响应不能当作项目全集。关闭弹层终止读取并忽略迟到响应；重新打开重新读取，下载失败保留选择。

此人工条件初筛可能包含后端最终拒绝的记录，不能宣称是最终资格集合的子集。全选不包括打开列表后尚未展示的新记录；用户无需另选“单条/多条/全部”范围。旧 API 省略 ID 的行为仅作兼容保留，当前 UI 始终发送明确 ID，本次不修改 API contract。

### 10.3 后端最终 fail-closed 条件

下载时后端重新读取并校验每一条所选记录。最终可导出至少同时满足：

- 当前用户为全局 ADMIN 且具有 ACTIVE 项目 ADMIN Membership，项目仍为 ACTIVE，且选择范围属于当前项目；
- 视频和 ClipAsset 当前有效，对象身份与 SHA-256 可证明；
- Media Probe 与媒体状态有效，存在已验证视频时长；
- 技术质量达到最终批准要求；是否额外要求 stream/session 的 quality_status = PASS、适用哪些视图及如何处理 WARNING/PENDING/REJECT，由 D2 决定，PASS 不能替代其他守卫；
- CaptureGroup 人工质量允许进入标注；
- 当前输入对应的最新 AnnotationRevision 已由 AnnotationReview 判定 APPROVED，任务为 COMPLETED；不得回退读取旧输入或旧批准 revision 来补资格；
- Revision、标注区间和任务输入与当前视频 SHA、输入版本、主机位和 provenance 一致；
- 当前 MediaPipe 结果来源、job/attempt、model/profile、input/result 摘要有效；
- 该 episode 的已批准区间集合内至少存在一条实际的当前 MediaPipe sample；不要求每帧都有手，也不把“每个区间必须有样本”作为未经批准的新规则；
- 当前运行配置满足 synthetic-only 与其他治理要求；
- 上述必需证据不存在失败、来源漂移、未完成或不可证明状态；可选 Action Candidate 失败不单独阻断导出。

任一所选记录失去资格，整次选择拒绝；不得静默生成部分文件、跳过失效项或生成空的“可训练”文件。Export Eligibility 是组合后的后端权威判断，可以由各模块提供只读事实并在不同阶段复验，不要求集中成一个巨型服务或删除必要的重复校验。前端初筛、人工提交守卫和最终导出校验职责不同，应保留。

D2 未决期间不凭本文放宽或新增 runtime 条件，也不声称技术质量目标已验收。V73 的旧 eligibility 视图已经由 V75 迁移退役；当前收敛不恢复该视图，不能将历史 SQL 当作仍在线的第二真源。迁移执行情况属于具体环境事实，本次未查询数据库。

### 10.4 HDF5 语义与布局

一个合格 CaptureGroup 对应一个 HDF5 episode，单次选择生成一个 HDF5 文件。训练主数据面为 samples。以下是当前 exporter 的关键结构摘录（省略部分属性；不是新 layout 契约）：

~~~text
data/demo_000000
├── attributes：采集记录、主视频 SHA、revision、label schema/digest
├── samples
│   ├── attributes：视频与 AI job/attempt/model/profile/input/result provenance
│   ├── candidate_annotation_id
│   ├── frame_timestamp_ms
│   ├── hand_index
│   ├── landmarks[N,21,3]
│   ├── handedness
│   ├── handedness_score、image_width、image_height
│   ├── label
│   ├── segment_start_ms
│   └── segment_end_ms
├── annotations
└── views/camera_NN
    ├── attributes：视频身份、检测状态与可用 provenance
    └── candidates（成功且有手部结果时）：全量检测样本
~~~

samples 的每一行是主视频中实际存在、且落入已批准人工区间 [start_ms, end_ms) 的 MediaPipe sample；不为未检测到手的帧补造坐标，不自动时间对齐参考机位。保留能够证明每条 sample 来源的 clip_asset、camera、AI job/attempt、algorithm、model、profile、input 和 result provenance。

主视频 views/*/candidates 的全量 landmarks 与 samples 的重复写入属于 D3 待决的 layout 精简项。D3 决定前不删除、不改写当前 HDF5 结构；若确认没有仓库外训练消费者，后续才可把主视频关键点收敛为 samples 单写，并同步更新契约测试。

samples 是主视频 candidates 按人工区间筛选后的子集，两者并非全量等价；删除后会失去该视图中未标注区间的检测样本。主视频编号也不固定为 camera_01。D3 必须明确这种信息损失、参考机位保留范围与消费者兼容方案；审计提议的独立 provenance/ 分组不是当前已实现结构。input_sha256、model SHA、样本标签与区间等来源信息继续保留，不因字段值相同而删除。

HDF5 不包含 MP4 字节、对象存储键、预签名 URL、患者身份、机器人状态、控制动作、虚构的 states/actions/reward/success 或模型训练结果声明。

## 12. 模块、异步与可靠性约束

Platform 使用一个 Java 21、Spring Boot、Spring Modulith Core API。核心领域模块包括 iamproject、assetcapture、mediaprivacy、annotationreview、qualitycleaning、datasetexport、aicandidate 和 governance；integration 只承载 CVAT、S3、RabbitMQ、OIDC 等端口与适配器，不拥有业务真值。

模块只能写自己拥有的表。跨模块写入通过公开应用服务或版本化领域事件；跨模块读取通过公开查询接口或只读投影。Python Worker 只处理媒体和 AI 作业并回传结果，不直接写业务表。

以下可靠性边界是产品数据可信度的一部分，必须持续保留：

- ai_job 与 ai_job_attempt：作业事实和单次执行事实分开；
- inbox、outbox：消息去重和事务性派发；
- lease、heartbeat：执行所有权与存活证明；
- retry、退避、死信和受控恢复；
- idempotency：重复请求、重复投递和重复结果不产生第二份业务事实；
- ClipAsset SHA-256、model SHA-256、profile/input/result digest；
- 原始输入、执行 attempt、错误原因和追加式审计；
- 导出 fail-closed 与来源漂移拒绝。

Redis 不作为事实数据库，RabbitMQ 不保存最终业务状态，对象存储不承载关系型业务状态。耗时、跨进程或需要重试的工作使用受控异步作业；可以在单个 Core API 事务内可靠完成的操作不额外引入消息或缓存。

## 13. 前端与用户体验

前端遵守 [设计系统](../../../DESIGN_SYSTEM.md) 的 Video-first Quiet Professional Workspace with Neutral Light + Medical Blue 身份，以及 [Web 前端与用户体验设计规范](../../../architecture/web-ux-and-frontend-guidelines.md)。

当前界面规则：

- 视频是主要工作入口；列表展示当前项目的采集记录，详情以播放器和当前机位为主；
- 多机位使用紧凑切换，明确当前视角、缺失原因和时间基准，不暗示已同步播放；
- 任务是视频工作区中的视图和待办，不另建并行产品页面；
- 标注面板按需展开；智能初始化只能在完整合规候选、任务未编辑且来源仍有效时发生；
- 候选冲突、部分失败、来源失效或任务已有编辑时，不静默覆盖，允许人工从零标注；
- 结果状态用准确文字表达，不能只靠颜色，也不能把查询失败猜成作业失败；
- 技术 ID、模型参数、历史和审计渐进披露；真实阻断、权限提示、失败原因和未提交修改始终可见；
- 状态中文映射属于 presentation 层，重复 formatter 计划合并，但不改变服务端事实；
- 当前项目导出列表是唯一导出交互；不在行、详情或任务页面扩散第二套导出入口；
- legacy redirect 暂时保留，不再新增旧页面、旧文案或旧组件依赖。

页面简化的目标是减少重复判断和点击，不是隐藏权限、人工判断、失败恢复或 provenance。

### 16.1 验收分层

文档验收检查本文自包含、入口、分类清单、需求追踪和摘要一致性；本阶段仅执行这一层。实现验收按受影响链路运行合成测试及契约检查；真实模型集成验收另需锁定环境和运行证据。历史测试通过数不作为 V1.35 验收结果。

### 16.2 人工减负试验

先用 3–5 段合成片段验证解析、时间映射、重复/快速动作、空白、遮挡和错误恢复；再比较“从零标注”与“AI 草稿加人工修正”。两组使用相同标签判据，独立质量复核仅用于试验，不改变日常管理员同人确认权限。

| 指标 | 固定口径 |
| --- | --- |
| 人工成本 | 人工总分钟 / 视频总分钟，包含检查、补标、修改、提交、复核返工和 AI 阻塞等待 |
| 节省比例 | 1 − AI 辅助组单位视频人工耗时 / 纯人工组单位视频人工耗时；至少 30% 为试点目标，非保证 |
| 最终标签质量 | 报告漏标、误标、类别与边界误差；预先固定质量容差，不以平均耗时掩盖质量下降 |
| 模型诊断 | 同类片段一对一匹配的 precision/recall、时间 IoU、边界误差；未匹配片段计入漏检/误检 |
| 资源稳定性 | 冷启动与热启动分开；报告解码到解析的端到端耗时、峰值显存、失败率、OOM、样本量和不确定性 |

按人员、批次和难度分组并交叉分配，避免同一操作的切片或机位泄漏到调参集和评估集；按完整视频或批次统计，不把相邻帧当独立样本。匹配阈值、边界容差与质量可接受差异在试验前确定；样本不足不标记通过。1366×768、1440×900、1920px 及既有窄屏回退需覆盖播放器、面板、未保存保护和键盘操作，不新增视觉体系。
