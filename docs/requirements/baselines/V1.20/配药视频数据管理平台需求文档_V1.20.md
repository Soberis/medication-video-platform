# 配药视频数据管理平台需求基线 V1.20（LEAN-P0）

> 文档版本：V1.20<br>
> 文档状态：**当前业务需求基线**（LEAN-P0）<br>
> 生效日期：2026-08-13<br>
> 前一版本：V1.18（V1.19 为历史 Draft，见下）<br>
> 生效规则：本版本把产品面收敛回唯一 P0 主线。V1.18 未明确替代的安全、权限、审计、数据完整性、领域边界和"一条视频闭环"验收条款继续继承；V1.19 多相机同步方向为 DEFERRED，不属于当前交付目标。

## 1. 唯一业务主线

平台对接但不控制医院边端。云端只做一条数据生产主线：

```text
边端接收
→ 视频管理
→ 单视频 MediaPipe 手部预标注
→ 配药动作标注
→ 复核
→ 清洗
→ 可用数据
```

其余一切能力（多相机同步、数据集、导出、AI 评估平台化、训练）均不在当前产品面内。

## 3. CaptureSession 定位

```
Runtime:   REQUIRED    （接入与多相机归组事实，P0 闭环可靠运行依赖）
Surface:   NONE        （纯内部领域事实）
P0 Dep:    TRANSITIVE  （支持接入正确性，用户主链不直接操作）
User view: HIDDEN      （当前用户无需理解）
```

不建设：Session 列表产品、Session 详情产品、多相机同步播放产品。现有后端 CaptureSession 链（Session / CameraStream / CameraChannel / CameraSetSnapshot）保留、参与编译测试，但不再获得新的产品能力。

## 4. MediaPipe 定位

MediaPipe 不是独立 AI 平台，只是：

- 视频数据管理中的一个处理动作；以及
- 配药动作标注的辅助 Candidate 来源。

AI 只能生成 `CandidateAnnotation` 与 run summary。AI 绝不能自动生成正式 `AnnotationRevision`、自动 Review PASS、自动 Cleaning PASS、自动放行可用数据。

## 5. Parquet 定位

Parquet 不属于 P0 用户工作流，当前用户无需打开 Parquet。未来可作为训练数据、大规模 frame/annotation、dataset export 的机器交换格式；在此之前不进入产品入口、不作为当前验收项。

## 7. P0 完成定义

至少有一条视频能完整走通：

```text
接收
→ INGESTED
→ MediaPipe
→ Candidate
→ Skeleton Overlay
→ 人工标注
→ Review
→ Cleaning
→ 可用数据
```

## 8. 数据与安全

继承 V1.18 未变更条款：权限与 Membership 守卫、审计与 provenance、不可修改原视频（SHA-256 校验）、模型 SHA / profile SHA / input digest 溯源、人工放行原则（删除、数据放行、隐私审批、AI 转正式标签、数据集冻结与导出）、测试数据安全（合成或明确授权并隔离，禁止真实患者视频/生产账号/密钥/生产数据库）。

## 9. 禁止产品复杂化

第二个真实需求出现前：不新建通用框架、不提前新建 Worker、不提前建 queue、不提前建 module、不提前建 dataset 平台、不提前建 AI 管理平台。每次只交付一个可运行、可测试、可回退的 P0 纵向切片。
