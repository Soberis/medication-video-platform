# V1.27 单一 CaptureGroup 产品路径

> 状态：CURRENT / DESIGN FROZEN
> 生效日期：2026-09-01
> 当前需求基线：[V1.27 配药视频数据管理平台需求基线](../requirements/baselines/V1.27/配药视频数据管理平台需求文档_V1.27.md)

本文定义 V1.27 的当前产品路径和领域边界。它不回写 V1.26 历史设计，也不删除 Flyway 历史迁移或历史文档。旧单视频表面不再是 V1.27 的产品承诺；Task C 已将对应运行时、公开契约和旧读模型从当前实现移除，Task D 仅对确认为空、或已由管理员明确处置完数据的遗留数据库对象执行 forward-only 清理。

## 1. 唯一业务主链

```text
Local Upload / External Ingest
→ CaptureGroup
→ CameraStream / ClipAsset
→ Media Probe
→ MediaPipe Candidate
→ per-view Quality
→ CaptureGroup Quality
→ one CaptureGroup AnnotationTask
→ AnnotationRevision
→ Review
→ deterministic CaptureGroup Cleaning
→ training-data.v3
```

`CaptureGroup` 是用户理解和处理的唯一业务对象。当前实现使用 `CaptureSession` 承载该稳定身份；`CameraSetSnapshot` 固化视图集合，`CameraStream` 表示事件内的机位，`ClipAsset` 表示对应的物理视频证据。

## 2. 当前产品信息架构

```text
项目
├── 视频管理
│   └── 配药事件列表（CaptureGroup）
│       └── 配药事件工作台
│           └── 1..N 个 CameraStream 机位视图
└── 配药动作标注
    └── CaptureGroup task inbox
        └── 深链回对应配药事件工作台
```

- “视频管理”只有一个面向用户的主入口，目标是配药事件列表。
- “配药动作标注”只提供 `CaptureGroup` 任务待办，不创建按机位拆分的任务。
- 事件工作台统一承载接收、机位质量、事件质量、动作标注、Review 和训练资格结果。
- `/projects/:projectId/videos` 和 `/projects/:projectId/assets/:id` 不属于当前业务入口或独立工作台，当前 Core API 不再暴露这些产品目录路径。ClipAsset 详情、播放授权、Media Probe 和 MediaPipe `/videos/{video_id}/hand-pose-*` 仍是低层证据/作业接口，不构成独立视频工作流。

## 3. N=1 统一模型

本地单视频上传不是单视频特例流程，而是普通的单视图事件：

```text
CaptureGroup
└─ CameraStream #1
   └─ ClipAsset
```

界面可以将该视图称为“机位 1”，但不得新增 `CaptureGroupView` 数据库实体、单视频任务、单视频 Cleaning 或第二套导出。`N=1` 和 `N>1` 共享同一权限、审计、质量、Annotation、Review、Cleaning 和 `training-data.v3` 语义。

## 4. 领域事实与模块边界

以下是 V1.27 必须保留的低层事实，不等于独立的产品工作流：

| 事实 | V1.27 作用 |
| --- | --- |
| `ClipAsset` | 物理/原始视频证据、对象存储引用、内容大小、`SHA-256`、媒体状态、播放授权事实和软删除状态 |
| `CaptureSession` | 当前 `CaptureGroup` 的接入与业务身份承载 |
| `CameraSetSnapshot` / `CameraStream` | 冻结视图集合、机位、通道、录制与同步声明，并将视图绑定到 `ClipAsset` |
| upload pipeline / External Ingest | 接收文件、manifest、显式事件/机位绑定和完整性校验 |
| Media Probe / `MediaReport` | 验证媒体可读、时长、流信息和输入摘要 |
| `ai_job` / `ai_job_attempt` / `CandidateAnnotation` | MediaPipe 运行、候选输出、模型/输入/运行摘要和重试事实 |
| Quality / Annotation / Review / Cleaning | 分层人工事实、正式修订、人工闸门和确定性训练资格检查 |
| audit / permissions / provenance / governance | 项目隔离、角色授权、不可覆盖的事实记录和风险控制 |

模块只能写入自己拥有的表。AI Worker 只处理媒体和 AI 作业，不直接写 `AnnotationRevision`、Review、Cleaning 结论或冻结数据集；对象存储不承载关系型业务真值。

## 5. 阶段与人工闸门

Media Probe 和 MediaPipe 是每个视图的辅助事实准备，不是额外的用户业务阶段。主业务阶段为：

```text
接收 → 机位质量 → 事件质量 → 配药动作标注 → 人工复核 → 训练资格检查
```

自动化边界：

- 允许自动准备 Media Probe 和 MediaPipe Candidate；
- 允许在明确批次完成事实下完成本地 `N=1` receipt；外部或多机位 receipt 仍需显式 finalize；
- 允许在有效事件质量后幂等创建唯一 `CaptureGroup AnnotationTask`；
- 允许在 Review `APPROVED` 后按冻结规则执行 `CaptureGroup Cleaning`；
- 允许在服务端成功后刷新权威快照、聚焦下一未决视图和安全导航。

必须人工明确提交：逐视图质量、事件质量、Primary View、正式 `AnnotationRevision` 和 Review。`HAND_DETECTED`、`NO_HAND_DETECTED`、`UNKNOWN`、Candidate 为零或 AI/媒体失败都不能自动变成质量、正式标签、Review 或 Cleaning 结论。

## 6. 任务、修订、Review 与 Cleaning

有效 `CaptureGroupQualityReview` 后，系统只创建一个组任务。该任务产生一条 append-only `AnnotationRevision` 链；主视图是正式 action interval 的权威时间基准，其他视图不会被未经验证地自动复制动作区间。

Review 是人工闸门。只有 `APPROVED` 才能进入确定性的 `CaptureGroupCleaning`；Cleaning 保存规则版本/digest、输入事实、参与/排除视图、结果、理由、检查项、provenance 和审计。管理员 recheck 只能重新执行规则，不能手工选择 PASS、WARNING 或 REJECT。

## 7. 导出边界

V1.27 当前唯一支持的输出是 `training-data.v3`：

- 以 `CaptureGroup` 为事件和 split 单元；
- 输出组、主视图、视图集合、Revision、Review、Cleaning 和既有候选 provenance；
- 不复制 MP4，不创建 DatasetVersion，不引入新的 Export Worker 或冻结数据集平台；
- 不把 Candidate geometry 或 `handedness` 当作 Ground Truth；
- 既有 AI evidence identity、attempt/result lineage、Media Report 绑定和导出物独立复现缺口，按 V1.27 追溯审计列为后续工作。

`training-data.v2`、`training_data.parquet` 和单视频导出不属于当前 V1.27 产品输出。对应运行时、公开契约和最小导出工具已退役；Flyway 历史迁移、历史数据库列和历史文档仍保留为迁移/审计材料，不能从中推导当前支持承诺。

## 8. 退役与后续变更规则

V1.27 不再支持以下业务语义：独立 `/videos` 视频工作台、独立 `/assets/:id` 工作台、单视频 AnnotationTask、单视频任务自动创建、单视频 Cleaning、`training-data.v2` 以及 V1.24-compatible runtime behavior。Task C 已移除这些运行时路径、旧读模型、旧 Cleaning/export 服务和对应公开契约；保留低层 ClipAsset/MediaPipe 证据接口以及历史数据库事实。

Task D 使用两段独立的 forward-only 数据库清理：V72 在确认无历史行时直接移除 v2 eligibility view、旧单视频清洗表和 `annotation_task.clip_asset_id` 关系，并把当前任务/修订/复核约束收敛到 CaptureGroup；存在旧清洗结果或单视频任务行时，则原样保留整组旧对象并继续升级。管理员完成明确的数据保留或删除决策并清空旧行后，V74 再移除这组被保留对象；V74 自身不删除业务行，检测到遗留行或对象集合不完整时会 fail closed。两者都不改写 V1--V71 Flyway 文件，非级联 `DROP` 遇到未知依赖仍会停止迁移，也不提供自动 down migration；回退依赖迁移前的数据库备份/快照。

当前 V1.27 的 AI 证据缺口与建议见：[V1.27 AI evidence pipeline audit](./v1.27-ai-evidence-audit.md) 和 [V1.27 training traceability audit](./v1.27-training-traceability.md)。这些审计结论不改变“Candidate 只能辅助、人工决定最终业务事实”的边界。
