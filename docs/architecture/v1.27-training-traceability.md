# V1.27 训练数据可追溯性审计

> 状态：AUDIT / CURRENT<br>
> 审计日期：2026-09-02<br>
> 审计口径：以 V1.27 需求基线、V1.27 单一 CaptureGroup 产品路径、当前导出实现、数据库迁移、模块代码和现有测试为准；`training-data.v2` 仅作为退役历史实现审计对象。审计只使用合成数据和静态代码/契约证据，不接触真实患者视频或生产数据。

## 结论摘要

当前必须把“事件资格/来源 manifest”和“机器学习特征样本”分开判断。当前可验证的导出运行时包括 v3 manifest 和 `hand-landmarks.v1` 服务端 CSV；尚无实际训练 consumer 读取后者的证据。当前 v3 与退役 v2 路径的结论不同：

| 导出 | 当前语义 | 可追溯结论 |
| --- | --- | --- |
| `training-data.v2` | 历史单视频 Parquet；一行是一个落在人工批准动作区间内的 MediaPipe hand candidate observation | 通过 `video_id`、`candidate_annotation_id` 和 `annotation_revision_id` 可以在数据库辅助下重建相当一部分链路；导出物本身缺少 CaptureGroup/Camera/View、Review/Cleaning 实体、AI job/attempt/result 和源媒体 digest，因此不能独立复现 |
| `training-data.v3` | 新 CaptureGroup JSON event manifest；一个事件代表一组通过当前准入投影的 group/event 事实，而不是 frame/hand/sample 行 | group、revision、Review、Cleaning 和候选摘要较完整；V73 已在导出前选择每组唯一 current revision，并重新验证参与媒体的当前状态、软删除、版本、归属和 `sha256`，冲突或歧义直接 fail closed。它仍没有稳定 sample、完整 annotation 或 AI 执行证据，不能独立复现 |
| `hand-landmarks.v1` | V1 定义的实际 MediaPipe hand landmark training export；一行/一个样本对应一个 sampled Primary-View frame 内的一只手 | 已形成服务端生成的 CSV runtime，并由 Java contract 与 Python readback smoke test 验证；尚无训练 consumer 读取证据，不能宣称真实模型训练已成功 |

因此，当前可以做到的是“以数据库和当时仍可访问的业务表为前提的 v3 事件资格事后重建”，以及按当前冻结事实动态生成可读的 `hand-landmarks.v1` CSV 样本。两者都不是持久化 export identity 或独立训练平台；`training-data.v3` 必须继续被称为 CaptureGroup 事件资格/来源 manifest，不应把 `eventCount` 或 event row 解释为 sample count；`hand-landmarks.v1` 才是实际的 ML feature export。尚无实际 training consumer 读取后者的证据。

## 当前状态与边界

新 CaptureGroup 路径的纵向链路是：

~~~
CaptureSession (CaptureGroup identity)
  → CameraSetSnapshot / CameraStream / ClipAsset
  → 逐视图质量
  → CaptureGroup 质量准入
  → 一个 CaptureGroup AnnotationTask / AnnotationRevision
  → AnnotationReview
  → CaptureGroupCleaning
  → training_data_group_eligibility_v3_integrity（只读完整性预检）
  → training_data_group_eligibility_v3
  → training-data.v3 JSON（CaptureGroup eligibility / provenance event manifest）
  → hand-landmarks.v1 CSV（Primary View landmark samples；管理员显式预览/下载）
~~~

退役单视频路径（仅用于历史迁移/审计，不属于 V1.27 当前产品；V72 会清理无历史行的数据库，V74 会在显式处置完遗留行后清理其余数据库）是：

~~~
ClipAsset
  → AnnotationTask / AnnotationRevision
  → AnnotationReview
  → cleaning_run / cleaning_result
  → training_data_eligibility
  + training_data_candidate_observations
  → training-data.v2 Parquet
~~~

`assetcapture` 通过 `CameraStream → CaptureSession/CaptureGroup → ClipAsset` 保存视频来源关系；接收时，`CaptureSessionIngestService` 会将外部 manifest、上传文件和 `ClipAsset` 的文件名、大小、`SHA-256`、机位和录制时间相互校验。`annotationreview` 保存 append-only `AnnotationRevision`、`AnnotationReview` 及其人工快照，`qualitycleaning` 保存事件级 Cleaning 事实，`datasetexport` 只读这些投影，不拥有媒体或标注事实。这一模块所有权划分与 V1.27 的边界一致；历史单视频清洗只保留为迁移/审计证据。

当前 v3 与 `hand-landmarks.v1` 导出都只允许 `synthetic` data profile，都不复制 MP4、不创建 `DatasetVersion`；退役 v2 不属于当前产品输出。`preview` 和 `download` 在 `REPEATABLE_READ` 事务中读取当前投影；V73 在读取公开 v3 投影前执行完整性预检，若当前 PASS 行的媒体或 revision/context 证据无法证明，直接返回 `TRAINING_DATA_V3_ELIGIBILITY_INVALID`（422），不会把无效行静默过滤成可导出结果。两次调用之间仍没有持久化的 export identity、source snapshot 或 artifact digest；下载文件只是一次动态查询的结果。`hand-landmarks.v1` 已有公开服务端 CSV runtime 和自动化 readback 证据，但没有实际 training consumer 读取证据。

## 当前导出字段

### 退役的 `training-data.v2`（仅历史审计）

历史路由为 `/api/v1/projects/{projectId}/training-data/preview` 和 `/download`，格式为 `training-data.v2` Parquet，固定文件名为 `training_data.parquet`。它不属于 V1.27 当前产品输出；每个 Parquet row 的历史字段是：

~~~
video_id
timestamp_ms
action_start_ms
action_end_ms
action_label
annotation_revision_id
hand_index
hand_presence
hand_mask_available
candidate_annotation_id
handedness
handedness_score
handedness_is_ground_truth
algorithm_key
algorithm_version
model_sha256
profile_sha256
landmark_0_x ... landmark_20_z
~~~

其中 63 个 landmark 字段表示 MediaPipe 几何；`hand_presence`、`hand_mask_available` 和 `handedness_is_ground_truth` 是明确的语义元数据，candidate geometry 不是人工 ground truth。

Parquet metadata 当前包含：

~~~
schema_version
cleaning_gate
action_label_source
action_interval_source
hand_geometry_source
hand_geometry_is_ground_truth
candidate_algorithm_source
handedness_is_ground_truth
handedness_score_source
hand_mask_policy
eligibility_projection
candidate_projection
coordinate_system
video_policy
~~~

历史 V64 的 `training_data_eligibility` 读取并校验了 asset status/deletion/content type、asset SHA-256、质量准入、annotation document 及其 digest、label schema ID/digest、Review、Cleaning outcome/status/rule digest 等字段；历史 `training_data_candidate_observations` 还读取 `ai_job_id`、algorithm/model/profile digest、frame/hand 和 landmarks。但这些事实大部分只用于查询准入，不会进入 Parquet row 或 metadata。特别是 v2 导出没有 `project_id`、`capture_group_id`、camera/view、`annotation_review_id`、`cleaning_result_id`/`cleaning_run_id`、`ai_job_id`、attempt/result 引用、`input_sha256`、media report 或 source upload/object 引用。V72 只在这些历史对象无行时移除它们；含历史清洗或任务行时原样保留旧对象并继续升级，等待单独的数据保留与迁移决策。决策完成且旧行已显式清空后，V74 移除这些被保留对象，并在仍有旧行时拒绝迁移。

v2 的候选投影比 v3 更强的一点是：它把最新成功 MediaPipe job 与当前 asset 的 `sha256` 做匹配；但这个匹配事实没有写入 artifact，下载后无法证明当时使用的是哪一个 job execution。

### `training-data.v3`

当前路由为 `/api/v1/projects/{projectId}/training-data/v3/preview` 和 `/download`，格式为 `training-data.v3` JSON，固定文件名为 `training_data_v3.json`，split unit 为 `capture_group`。event 当前包含以下事实组：

~~~
capture_group_id
annotation_revision_id / revision
action_label / action_labels
primary_clip_asset_id / primary_camera_number / primary_interval
confirmed_view_set / input_version
participating_views / excluded_views
group_quality / group_quality_revision / group_quality_review_id
group_quality_reviewed_by / group_quality_decided_at
annotation_review_id / review_decision / reviewed_by / reviewed_at
qualified_views / rejected_missing_views
candidate_evidence
capture_group_cleaning_id
cleaning_rule_set_key / cleaning_rule_set_version / cleaning_rule_set_digest
cleaning_outcome / cleaning_reason_codes / cleaning_executed_checks
cleaning_input_fingerprint / cleaning_evaluated_by / cleaning_authorization_basis / cleaning_evaluated_at
mapping_provenance
candidate_provenance
~~~

其中：

- `action_label`/`action_labels` 从 `annotation_document.segments.label` 派生，不是完整 annotation document；`primary_interval` 来自 Cleaning 投影。
- `participating_views` 和 `excluded_views` 保留 group/view/质量/状态类证据；参与视图额外保留 Cleaning 时冻结的 `clip_asset_sha256`，供导出预检与下载后的源媒体核对使用。supporting view 的 action interval 和映射字段会被移除，并标为 `EVENT_LEVEL_EVIDENCE`；主视图是唯一正式 action timebase。
- `candidate_evidence` 是 Review 快照中的按 ClipAsset 固定的 provenance snapshot，`candidate_provenance` 是 Cleaning 快照中的同一 snapshot；两者包含当前 ClipAsset SHA、执行状态、job/attempt/message/result identity、input SHA、algorithm/model/profile、完整 run summary 和候选集合 digest，但都不是 Candidate 原子记录或完整 AI result artifact。无 job、排队中、运行中、失败、成功但无手和成功且有 Candidate 均有明确状态；无效身份会阻断 v3 导出。
- SQL 投影虽选出 `mapping_provenance`，但 `TrainingDataV3ExportService` 的 mapper 固定输出空数组；OpenAPI 也标为 deprecated/always empty。
- `preview` 将 event 数同时作为 `eligibleGroupCount` 和 `eventCount`，没有 sample count、frame count 或 hand count。

### V1 当前契约 `hand-landmarks.v1`

`hand-landmarks.v1` 与 `training-data.v3` 不是同一个 artifact：前者是实际供机器学习使用的 MediaPipe landmark feature export，后者只提供 CaptureGroup eligibility / provenance event manifest。V1 的机器学习契约固定为：

| 字段 | V1 语义 |
| --- | --- |
| `feature` | MediaPipe hand landmarks |
| `sample unit` | 一个 sampled Primary-View frame 内的一只手；同一 frame 的多只手分别成 sample |
| `label` | 经人工 `Review` 批准的 `AnnotationRevision` action segment label；不是 MediaPipe action label |
| `time association` | `frame_timestamp_ms` 落在 Primary View annotation interval `[start_ms, end_ms)` 内 |
| `provenance` | `CaptureGroup`、Primary-View `ClipAsset` SHA-256、AI job/model、`AnnotationRevision` |

V1 只允许 Primary View。Supporting View 的 source-local timestamp 不得在没有 verified reliable mapping 时与 Primary View interval 对齐；不得伪造跨相机 labels。只输出实际检测到的手部样本，不补造 fake no-hand rows。`hand-landmarks.v1` 已形成服务端 CSV runtime，并以现有 CaptureGroup 质量、人工 Revision、Review 和确定性 Cleaning 闸门为前提；当前仍没有实际 training consumer 读取闭环或真实模型训练成功证据。

## 链路逐节点判定

| 链路节点 | 数据库中已有的事实 | v2 artifact | v3 artifact | 结论 |
| --- | --- | --- | --- | --- |
| Training Sample / 导出单元 | Candidate、时间戳、hand index、完整 landmarks；v3 只有 event | 有候选行和候选 ID，但没有独立稳定的 `sample_id` | 没有 frame/hand/sample 行 | v2 是可重连的 candidate observation，不等于人工 ground-truth sample；v3 不是 sample 导出 |
| `hand-landmarks.v1` ML feature sample | AI Candidate 的 MediaPipe landmarks + Primary View 人工 interval + CaptureGroup/ClipAsset/Revision provenance | 当前 v2 仅为历史单视频路径，不能作为 V1.27 artifact | 服务端生成 CSV；Java contract 与 Python readback 已验证 | 实际 sample export 已实现；没有 training consumer/UAT 证据，不能宣称真实模型训练成功 |
| `AnnotationRevision` | revision、完整 `annotation_document`、`document_sha256`、schema version、label schema ID/digest、提交者/时间 | 只有 revision ID、派生 label 和动作区间 | 有 revision ID/number、派生 label 和主区间 | 能定位 revision，但 artifact 不能证明完整文档和 schema 身份 |
| Review | decision、actor、time、revision/group context 和快照 | 仅通过 eligibility 过滤为 approved；Review ID/快照未导出 | Review ID/decision 及部分 actor/time 已导出 | v3 可直接定位 Review 实体，但仍需数据库取得快照；v2 只能间接回查 |
| Cleaning | 单视频 `cleaning_run/result` 或事件级 `CaptureGroupCleaning`，规则集 digest、input fingerprint、检查事实 | metadata 只有 `cleaning_gate=PASS`；实体 ID/规则 digest 未导出 | Cleaning ID、outcome、reason/checks、ruleset digest、fingerprint 已导出 | v3 的准入解释较强，但 fingerprint 不是完整 provenance digest |
| CaptureGroup / Session | `capture_session` 保存 group、manifest、设备、同步和接收事实；V1.27 继续使用 `capture_session_id` 承载 group identity | 不输出 group；可由 `video_id` 回查 stream/session | 输出 `capture_group_id`，但不另带 project/session/manifest source facts | v3 可定位 group，v2 需要数据库反查 |
| Camera / View | snapshot/member、stream、camera channel/index/role/mount、clip asset、同步声明和版本 | 不输出 camera/view | 输出 stream/clip/camera/状态/质量/版本类 view evidence；参与视图带冻结的 asset digest | v3 可解释参与视图集合并可在导出时复核其当前源媒体；仍未输出所有底层对象身份 |
| `ClipAsset` / 原始视频 | source upload/client file、content type、大小、`sha256`、object reference、status、soft-delete facts | `video_id` 通常可定位 asset；其 digest/对象身份未输出 | primary/view clip IDs；参与视图输出 Cleaning 冻结的 `sha256`，预检重新核对当前 `INGESTED`、未软删除、版本和 digest；大小、source file/object 未输出 | 两者都不是媒体副本；artifact 单独不能提供完整对象身份，但已不会在当前源媒体失效后继续导出 PASS 事件 |
| AI job / Candidate / Evidence | job algorithm/model/profile/input digest、attempt、result inbox digest、hand result；Candidate 绑定 job/asset 并保留 geometry | Candidate ID、算法和 model/profile digest、geometry 已输出；job/attempt/result/input digest 未输出 | 按 ClipAsset 保存 job/asset ID、执行状态、算法、model/profile、input SHA、attempt/message/result digest、run summary、候选数量/时间范围和候选集合 digest；不输出 Candidate ID/geometry | AI 仍只能作为 advisory evidence，但 artifact 可回答“哪次执行处理了哪份 ClipAsset bytes”并可用候选集合 digest 回数据库核对 |
| Original Video → AI Evidence | v2 candidate view 会用 asset SHA 与 job input SHA 匹配；v3 provenance snapshot 同样要求 job input SHA 等于当前 ClipAsset SHA | 选行时有较强校验，下载后证据仍不完整 | v3 Review/Cleaning 快照及导出同时保留 ClipAsset SHA、AI job input/attempt/result digest 和执行状态；不包含 MediaReport/object key | v2/v3 仍是数据库辅助的部分 AI 链路；Task C 闭合了输入 bytes 与执行 identity 的证据边界，不把 AI 证据升级为业务准入 |
| Split | API 只校验同一 CaptureGroup 不被分到多个 split | 不持久化、不写入 artifact | 不持久化、不写入 artifact | split 规则不能与 revision/cleaning/source fingerprint 绑定，不能作为完整实验 provenance |

## 关键实现证据与审计风险

| 编号 | 等级 | 风险与证据 | 影响 |
| --- | --- | --- | --- |
| R-01 | P0 | v3 是事件级 manifest：`TrainingDataV3Event` 没有 `sample_id`，`preview` 将 `events.size()` 同时作为 `eligibleGroupCount` 和 `eventCount`，原始 annotation document 和 Candidate 原子记录也未导出；V1 的实际 ML sample 契约另定义为 `hand-landmarks.v1` | `training-data.v3` 不能提供 frame/hand/label 样本；必须使用独立的 `hand-landmarks.v1` CSV，不能把 v3 当作主要 ML feature dataset |
| R-02 | P0 | **已关闭（V73）**：`training_data_group_eligibility_v3_integrity` 在导出前遍历 Cleaning `participating_views`，要求冻结的 stream/asset ID、camera number、stream/asset version、`clip_asset_sha256` 和参与状态存在，并核对当前同组 `CameraStream`、`ClipAsset` 的 `INGESTED`、未软删除、版本和 digest | B/C 集成测试证明主/参与 asset 软删除或 digest 变化时 preview/download 都返回 `TRAINING_DATA_V3_ELIGIBILITY_INVALID`（422），不会继续导出旧 PASS 事件 |
| R-03 | P1 | **已关闭（V73）**：内部完整性投影按任务链最新 `revision_number` 选择每个 `(project_id, capture_group_id)` 的 current Revision；同时统计同组仍满足自身 Review/Cleaning/context/source 证据的 PASS Revision 数量 | D/E 集成测试证明 current Revision 未批准时不回退旧 PASS；同组出现两个表面可导出的 PASS Revision 时 fail closed，不生成重复事件 |
| R-04 | 已关闭（Task C） | `CandidateEvidenceQueryService.findByClipAssets` 对每个 ClipAsset 生成状态化 snapshot，校验 project/ClipAsset/input SHA，保留 job/attempt/message/result、algorithm/model/profile、hand result、候选集合 digest，并由 v3 严格校验 `candidate_evidence` 与 `candidate_provenance` 一致 | v3 可区分无 job、非终态、失败、成功但无手和成功有 Candidate；替换 asset、旧 result、缺失 digest 或不一致 attempt 会 fail closed。Candidate 仍不成为人工闸门或 Cleaning admission criterion |
| R-05 | P1 | V69 `capture_group_cleaning` 对 revision 使用 `(project_id, annotation_revision_id)` 复合外键，但 group、Review、group quality、primary asset 多为单 ID 外键，跨字段相等性主要依赖应用层。V60 已对 `ai_job` 的 project+clip 及 `candidate_annotation` 的 project+job+clip 建立复合绑定；剩余缺口是 Candidate 没有直接的 attempt/result inbox 复合引用 | 直接 SQL、迁移遗漏或未来代码缺陷仍可能写入“revision 属于 A group、review/quality/primary 属于 B”的不可解释状态；AI 执行链也不能从 Candidate 直接证明具体 result message |
| R-06 | P1 | Cleaning `input_fingerprint` 现已包含参与视图的源 asset content digest 和版本化 `candidate-evidence.v1` canonical snapshot（含 run summary）；但仍不包含完整 annotation/label schema digest、完整 confirmed view JSON 或 export artifact 身份；规则集 digest 虽持久化，`executed_checks` 主要是检查名称 | 源媒体与 Candidate evidence 变化的边界已加强，但仍不能从 v3 或 fingerprint 独立重建当时的完整输入集合 |
| R-07 | P1 | supporting view 的跨视图 `mapping_provenance` 在 v3 导出时被清空，且 supporting view 的 action 时间字段被主动移除 | 当前 event-level 语义是安全的，但下游无法知道是否曾计算过映射、使用了哪个版本或为什么没有映射；若下游把 supporting view 当作动作级监督，存在语义误用 |
| R-08 | P1 | v2 row 只输出 `video_id`、revision、label/interval、Candidate 几何和算法元数据；Review/Cleaning/asset/group/camera/AI job 的实体 ID 和 digest 多数只存在于 eligibility projection | v2 下载物可用于数据库辅助的历史训练读取，但脱离数据库后无法解释其准入、源媒体身份和 AI 执行来源 |
| R-09 | P2 | 同一组视图事实分别复制到 group quality、Review、Cleaning 和 v3；候选摘要同时出现在 Review 与 Cleaning；各层快照没有统一的 canonical provenance envelope/hash | 事实所有权本身清晰，但快照层次多且命名不同；修订或重算时，难以快速判断哪一份是权威输入、哪些只是不可变历史快照 |
| R-10 | P2 | `readback` 只做 JSON 反序列化，不做 OpenAPI/字段语义校验；v2/v3 都没有 export ID、生成时间、source snapshot digest 或持久化 artifact 版本，preview/download 也不绑定同一 export | 文件格式合法不等于 provenance 完整；同一项目在两次下载之间变化时，无法精确证明某个文件对应哪一次准入快照 |
| R-11 | P2 | V69 迁移未看到 `CaptureGroupCleaning` 的数据库级不可变触发器；实体上的 `updatable=false` 主要是 ORM 写入约束。AnnotationRevision、Review 等 append-only 语义也需要结合数据库写权限和迁移继续核验 | 若存在绕过应用服务的写路径，快照可被修改而没有新的领域事件或相应的 artifact 身份；审计可信度依赖数据库访问边界 |
| R-12 | P0 | 当前已有 `hand-landmarks.v1` 服务端 CSV export runtime，并有 Java contract/readback evidence；仍没有实际训练 consumer 读取它的证据；v3 只包含事件资格/来源 manifest | 在真实 consumer 读取并验证 landmark samples 前，不得声称真实模型训练成功或完成真实 ML dataset UAT |

## 推荐的最小增量

以下 v2/v3 增量不要求提前引入 `DatasetVersion`、消息队列或通用工作流引擎，目标是先让事件 manifest 拥有可定位、可校验的来源边界；它们不等于 `hand-landmarks.v1` 的 ML sample export 实现。

| 增量 | v2（历史单视频） | v3（CaptureGroup 事件） |
| --- | --- | --- |
| 导出身份 | 在 file metadata 增加 `export_id`、`generated_at`、schema version、artifact SHA-256、source snapshot/export fingerprint | 在 JSON envelope 增加同样字段，并增加明确的 `unit_semantics=CAPTURE_GROUP_EVENT`、`event_count` 与 `sample_count`（当前 sample count 应为“不适用”） |
| 最小源媒体身份 | `project_id`、`clip_asset_id/video_id`、asset `sha256`、size/content type、capture session/group、camera stream/view；需要时带受控 source upload/object reference | `project_id`、group/session、每个 participating/excluded view 的 stream/clip/asset `sha256`、size/content type 和 camera identity；不要放预签名 URL |
| 正式标注与准入 | `annotation_task_id`、revision、`annotation_document_sha256`、label schema ID/digest、`annotation_review_id`/decision/time、`cleaning_run_id`/`cleaning_result_id`、ruleset digest/outcome/time | revision、完整 document/schema digest、Review snapshot identity、Cleaning input fingerprint 与准入时间；保留当前已有的 group quality/view facts |
| AI 证据 | `candidate_annotation_id` 之外增加 `ai_job_id`、job `input_sha256`、attempt、message/result digest、明确 outcome；必要时增加 Candidate set/artifact digest | 将紧凑摘要升级为可判别的 `NO_JOB`/`FAILED`/`SUCCEEDED_NO_HAND`/`SUCCEEDED_WITH_CANDIDATES`，带 job input/attempt/result digest 和 Candidate set digest/受控引用 |
| 一致性边界 | 保持当前 v2 的 asset SHA 与 job input SHA 校验，并把校验结果写入 artifact；保留当前 candidate/revision 回查能力 | 选出每个 CaptureGroup 唯一 current revision；导出前重新校验参与 asset 状态和 digest，失败时 fail closed |

统一 digest 应基于稳定的 canonical JSON/字段序列和明确算法版本，不应依赖语言对象的 `toString()`。原始媒体仍通过现有授权播放/查询边界访问，不把存储 object key 或签名 URL 当作公开训练 manifest 的替代 provenance。

## 建议的实施顺序

1. **已冻结“样本”口径和版本边界（Task D）。** `training-data.v3` 是 CaptureGroup 事件资格/来源 manifest；`hand-landmarks.v1` 是实际的 frame/hand/label ML feature export，sample unit、Primary View 时间关联、人工 AnnotationRevision label 和 provenance 已明确，不得用 v3 event row 代替 sample。

2. **先增加 export envelope 和 canonical provenance。** 为 v2/v3 增加 export identity、生成时间、artifact/source snapshot digest；为 v2 row 或 file metadata、v3 event/view 分别补齐 project、asset content digest、annotation/label digest、Review/Cleaning identity。不要在公开 manifest 中放预签名 URL。

3. **已实施（V73）：显式保证每组唯一 current revision。** 当前定义为 CaptureGroup AnnotationTask 链中最高 `revision_number` 的 Revision；公开 v3 投影只使用该 Revision。查询同时统计同组满足自身 Review/Cleaning/context/source 证据的 PASS Revision，发现多个时 fail closed。A–G 合同测试覆盖“同组旧 revision PASS + 新 revision”及重复事件断言，而不只测试 split assignment。

4. **已实施最小媒体和 AI evidence 重验证（V73/Task C）。** Cleaning fingerprint 和参与视图快照包含源 asset digest；导出前重新验证主/参与媒体的当前 `INGESTED`、未软删除、同组 stream/asset 绑定、版本和 digest。Review/Cleaning/v3 还保存 Candidate evidence 的 canonical snapshot 与候选集合 digest。若产品需要删除原始媒体，仍应明确将已通过事件标记为不可导出、冻结受控副本，或保留可审计的长期来源，而不是让旧 `PASS` 自动继续有效。annotation/label digest、confirmed view set digest、MediaReport identity 和独立 export artifact identity 仍是后续增量。

5. **已实施（Task C）：把 AI evidence 做成可判别的快照。** 保留无 job、排队/运行中、失败、成功但无手、成功且有 Candidate 等状态，并带上 job `input_sha256`、algorithm/model/profile、attempt identity/number、message/result digest、run summary 和 Candidate set digest。Candidate 仍只能是 evidence，不得成为正式标注或 Cleaning 准入条件；当前不新增独立 result artifact 或 Candidate→attempt 外键。

6. **部分实施（V73）并继续补足跨表一致性保护和诊断。** v3 内部只读完整性投影已检测 group/revision/task/review/quality/primary asset 互相不一致并让导出 fail closed；可行处仍可增加 project-scoped composite foreign key/unique key 或数据库 check，AI job 输入 digest 与 Candidate project/asset 关系也仍需独立审计。

7. **保留并显式化多机位时间边界。** 当前 supporting view 的 event-level 语义应继续保留。后续若需要可靠映射，不应复活空泛的 `mapping_provenance` 字段；应新增明确的 mapping status、算法/版本、输入 digest、输出 digest 和人工/自动授权边界。没有这些事实时，建议在新版本中移除 deprecated 字段，避免下游误以为存在动作级映射。

8. **增加契约、语义和数据完整性测试。** 至少覆盖：旧/新 revision 唯一性、主资产软删除或 digest 变化、跨 project/group/review/quality/primary 错配、AI 无 job/失败/无手/输入 digest 错配、Candidate evidence 传播、mapping provenance 明确为空、schema/readback 语义校验和 preview/download 的 artifact identity。完成这些测试前，不应把 synthetic `training-data.v3` manifest 宣称为可独立复现的训练样本集。

9. **已实施并验证 `hand-landmarks.v1` 的最小运行时。** 当前只输出 Primary View 的实际 landmark samples，包含人工 label、源媒体/AI/Revision provenance，并由 Java contract 与 Python readback smoke test 验证；下载是按当前冻结事实生成的 CSV，不创建 DatasetVersion、frame extraction platform、新 AI training service 或 automatic model training。实际 training consumer 读取、真实样本 UAT 和模型训练成功仍未发生，不能据此宣称完成。
