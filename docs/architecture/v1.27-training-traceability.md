# V1.27 训练数据可追溯性审计

> 状态：AUDIT / CURRENT<br>
> 审计日期：2026-09-01<br>
> 审计口径：以 V1.26 需求基线、V1.26 工作台设计、当前 `training-data.v3` 导出实现、数据库迁移、模块代码和现有测试为准。审计只使用合成数据和静态代码/契约证据，不接触真实患者视频或生产数据。

## 当前状态

当前纵向链路是：

```text
CaptureSession/CaptureGroup
  → CameraSetSnapshot / CameraStream / ClipAsset
  → 逐视图质量
  → CaptureGroup 质量准入
  → AnnotationTask / AnnotationRevision
  → AnnotationReview
  → CaptureGroupCleaning
  → training_data_group_eligibility_v3
  → training-data.v3 JSON
```

`assetcapture` 通过 `CameraStream → CaptureSession/CaptureGroup → ClipAsset` 保存视频来源关系；接收时，`CaptureSessionIngestService` 会将外部 manifest、上传文件和 `ClipAsset` 的文件名、大小、`SHA-256`、机位和录制时间相互校验。`annotationreview` 保存 append-only `AnnotationRevision`、`AnnotationReview` 及其人工快照，`qualitycleaning` 保存不可变的事件级清洗快照，`datasetexport` 只读这些投影，不拥有媒体或标注事实。这一模块所有权划分与 V1.26 的边界一致。

导出实现明确声明是 V1.25 继承的最小 group/event manifest：`training-data.v3` 只输出事件，不复制媒体、不创建 `DatasetVersion`；`preview` 和 `download` 都在 `REPEATABLE_READ` 事务中读取同一类当前投影，但两次调用之间没有持久化的 export identity。当前导出仅允许 `synthetic` data profile。

| 链路节点 | 当前保留的事实 | `training-data.v3` 的可追溯程度 |
| --- | --- | --- |
| 导出单元 / Sample | `TrainingDataV3Event` 以 `capture_group_id` 为 split unit，`eventCount` 等于事件行数 | 没有 `sample_id`、frame/sample 行或候选标注实体；计数是 event count，不是 sample count |
| `AnnotationRevision` / Review | 数据库保留 revision、完整 `annotation_document`、`document_sha256`、`annotation_schema_version`、`label_schema_id/digest`、提交者和时间；Review 保留 decision、actor、time | 输出只有 revision ID/number、从文档派生的 label、主时间区间和 Review 的主要字段；完整文档与其 digest、label schema digest 未输出 |
| CaptureGroup / Camera / View | `confirmed_view_set`、`input_version`、参与/排除视图、视图质量、stream/asset version 和同步声明会进入清洗快照 | 输出有 group、主 `ClipAsset`、机位号和视图 ID/状态类证据，但没有每个源资产的内容 digest |
| 原始视频 | `ClipAsset` 保留 `source_upload_file_id`、client file、内容类型/大小、`sha256`、存储对象引用、删除状态；`CameraStream` 绑定 session、snapshot member、camera channel/index 和 clip asset | 输出没有 `ClipAsset.sha256`、大小、`source_upload_file_id`、外部 manifest video digest 或原始对象的可审计引用；仅凭 manifest 无法验证取到的字节是否是同一视频 |
| AI evidence / Candidate | `AiCandidateJob` 保存 algorithm/model/profile、`input_sha256`、输入大小、attempt 和 result inbox digest；Candidate 归属于 job，且正常执行路径校验输入 | v3 只带 Review/清洗冻结的“最新成功 job 摘要”：job/asset ID、算法版本、模型/profile digest、候选数量和首尾时间；没有输入 digest、attempt/result digest、`hand_result`、候选 ID/几何或失败/无 job 状态 |
| Review → Cleaning | Review 通过后由服务端重新读取当前 group quality、视图事实和候选摘要，`CaptureGroupCleaning` 保存 Review、质量、主区间、视图证据、规则集 key/version/digest、reason、checks、input fingerprint、actor/time | 这是当前最完整的准入审计链；v3 能看到 Cleaning ID、`PASS`、规则和 fingerprint，但 fingerprint 不是完整 source/sample provenance digest |
| Split | API 只校验同一 CaptureGroup 不被分到多个 split | split assignment 不持久化、不进入导出 artifact，也没有与 revision/cleaning fingerprint 绑定 |

当前设计中，主视图是唯一正式 action timebase；非主视图在 v3 被明确降级为 event-level evidence，去除 action-aligned interval 和 `mapping_provenance`。这符合 V1.26 对“不得自动推断跨机位动作对齐”的边界，但意味着当前导出不能复现跨视图时间映射。另一个实现事实是：SQL 投影选出了 `mapping_provenance`，但 `TrainingDataV3ExportService.map` 将 v3 字段固定写成空数组；OpenAPI 也把该字段标为 V1.25 MVP 的 deprecated/always empty。

现有测试覆盖了 JSON readback、split 泄漏保护、历史 supporting-view interval 清洗，以及主要的 group quality/annotation/review/cleaning 合同；没有覆盖完整导出链的样本唯一性、源媒体 digest、AI 输入 digest、删除后的导出、跨表引用一致性、映射字段传播或 v3 语义 schema 校验。现有验收证据仍是 synthetic-only，没有真实或获授权样本 UAT。

## 风险

| 编号 | 等级 | 风险与证据 | 影响 |
| --- | --- | --- | --- |
| R-01 | P0 | v3 是事件级 manifest：`TrainingDataV3Event` 没有 `sample_id`，`preview` 将 `events.size()` 同时作为 `eligibleGroupCount` 和 `eventCount`，原始 annotation document 和 Candidate 原子记录也未导出 | 如果 V1.27 的“训练数据样本”指 frame/hand/label 样本，则无法从一个导出物定位到具体样本、正式标注内容和候选证据；只能追溯到一个通过清洗的事件 |
| R-02 | P0 | 输出只有 `ClipAsset`/view ID，没有源视频 `SHA-256`、大小和 source upload 事实；`ClipAssetDeletionService` 允许管理员软删除并仅更新 asset/stream，V69 的 v3 eligibility view 通过 Cleaning 快照取数，没有重新检查当前 asset 是否 `INGESTED`、未删除或 digest 仍一致 | `PASS` 事件可能继续出现在导出中，但原始视频已不可播放或无法证明是同一字节；“可追溯”与“可复现”脱钩 |
| R-03 | P1 | V69 的 `latest_cleaning` 按 `(project_id, annotation_revision_id)` 取每个 revision 的最新清洗，而不是按 CaptureGroup 选唯一 current revision；SQL 也没有每组唯一导出事件约束。当前领域对象在 APPROVED 后将 task 置为 `COMPLETED`，正常入口不会再次提交，但历史数据、未来 reopen 或绕过应用服务的状态仍可产生同组多个 PASS revision | 导出可能重复表示同一 CaptureGroup，或在 revision 选择不明确时把旧批准结果与新结果同时作为训练事件；split unit 防泄漏不能替代 current revision 选择 |
| R-04 | P1 | `CandidateEvidenceQueryService` 只取每个 clip 的 latest successful job 的紧凑汇总；Review/ Cleaning 复制该摘要，但没有 `input_sha256`、attempt/result digest、明确的 job outcome、原子 Candidate ID/内容或 evidence hash | 无法判断 Candidate 是否来自导出的那份视频、哪个执行 attempt 产生，或区分无 job、失败、成功但未检测到手；AI 证据只能作为不完整的旁证 |
| R-05 | P1 | `CaptureGroupCleaning` 对 revision 使用 `(project_id, annotation_revision_id)` 外键，但 group、review、quality、primary clip 多为单 ID 外键，缺少跨字段相等性约束；`annotation_review` 的 group context 也主要依赖应用层；`ai_job`/`candidate_annotation` 没有完整的 project + asset/job 复合引用约束 | 直接 SQL、迁移遗漏或未来代码缺陷可能写入“revision 属于 A group、review/quality/primary 属于 B”的不可解释状态；导出查询可能静默过滤问题行，难以发现数据损坏 |
| R-06 | P1 | Cleaning 的 `input_fingerprint` 包含 revision、Review、质量、区间和部分 view version/status，但不包含源 asset content digest、完整 annotation document/label schema digest、完整 confirmed view JSON、Candidate evidence 或 export artifact 身份；规则集 digest 虽已持久化，但 `executed_checks` 主要是检查名称 | 能重放“某些数据库事实下的规则判断”，却不能从 v3 或 fingerprint 独立重建当时的完整输入集合 |
| R-07 | P1 | supporting view 的跨视图 `mapping_provenance` 在导出时被清空，且 supporting view 的 action 时间字段被主动移除 | 当前事件级语义是安全的，但任何依赖多机位同步/映射的下游无法知道是否曾计算过映射、使用了哪个版本或为什么没有映射；若下游把 supporting view 当作动作级监督，存在语义误用 |
| R-08 | P2 | 同一组视图事实分别复制到 group quality、Review、Cleaning 和 v3；候选摘要同时出现在 Review 与 Cleaning；`input_version`、各层 JSON 快照和 Cleaning fingerprint 没有统一的 canonical provenance envelope/hash | 事实所有权本身清晰，但快照层次多且命名不同；出现修订或重算时，难以快速判断哪一份是权威输入、哪些只是不可变历史快照 |
| R-09 | P2 | `readback` 只做 JSON 反序列化，不做 OpenAPI/字段语义校验；导出没有 export ID、生成时间、源快照 digest 或持久化 artifact 版本，preview/download 也不绑定同一 export | 文件格式合法不等于 provenance 完整；同一项目在两次下载之间变化时，无法精确证明某个文件对应哪一次准入快照 |

## 建议

1. **先冻结 V1.27 的“样本”口径和版本边界。** 如果继续保留当前能力，应明确把 `training-data.v3` 定义为“CaptureGroup 事件资格 manifest”，不要把 `eventCount` 或 event row 叫作 sample count。如果目标是 frame/hand/label 级训练样本，应发布新的显式版本或兼容扩展，至少包含稳定 `sample_id`、sample/frame 时间、正式 annotation 内容或其 digest，以及从 sample 回到 revision、Review、Cleaning 和 source asset 的完整链路。

2. **建立 canonical source provenance envelope。** 每个事件/样本至少应能安全地表达 `project_id`、`capture_group_id`、`capture_session_id`、`camera_set_snapshot`/`camera_stream`、`clip_asset_id`、asset `sha256`、大小、content type、source upload/client file、camera identity，以及 `annotation_document_sha256`、`label_schema_id/digest`、confirmed view set digest。不要在公开训练 manifest 中放预签名 URL；媒体应通过已有授权查询/播放边界访问。

3. **在导出选择上显式保证每组唯一 current revision。** 明确 current revision 的定义（task 当前 revision、Review/cleaning 状态和 group quality 版本的组合），查询应先按 CaptureGroup 选唯一 revision；发现多个可导出的 PASS revision 时 fail closed。补充“同组旧 revision PASS + 新 revision”的集成测试和重复事件断言，而不只测试 split assignment。

4. **让媒体可用性和内容身份参与准入重验证。** Cleaning fingerprint 应包含源 asset digest、annotation/label digest、confirmed view set digest 和 Candidate evidence digest。导出前至少重新验证主资产及参与视图仍是允许状态且 digest 未变；若产品需要删除原始媒体，应明确将已通过事件标记为不可导出、冻结受控副本，或保留可审计的长期来源，而不是让旧 `PASS` 自动继续有效。

5. **把 AI evidence 做成可判别的快照。** 保留 `NO_JOB`、`FAILED`、`SUCCEEDED_NO_HAND`、`SUCCEEDED_WITH_CANDIDATES` 等明确状态，并带上 job `input_sha256`、algorithm/model/profile、attempt/result digest 和 Candidate artifact digest/受控引用。Candidate 仍只能是 evidence，不得成为正式标注或 Cleaning 准入条件。

6. **补足跨表一致性保护和诊断。** 可行处增加 project-scoped composite foreign key/unique key 或数据库 check；应用服务继续做跨模块业务校验。无论是否立即改表，都应提供只读审计查询，检测 group/revision/task/review/quality/primary asset 互相不一致、AI job 输入 digest 不等于当前 asset digest、Candidate 的 project/asset 不等于 job 的情况，并让导出对此类状态 fail closed。

7. **保留并显式化多机位时间边界。** 当前 supporting view 的 event-level 语义应继续保留。后续若需要可靠映射，不应复活空泛的 `mapping_provenance` 字段；应新增明确的 mapping status、算法/版本、输入 digest、输出 digest 和人工/自动授权边界。没有这些事实时，建议在新版本中移除 deprecated 字段，避免下游误以为存在动作级映射。

8. **增加导出 artifact 身份与契约验证。** 导出 envelope 建议包含 `export_id`、`generated_at`、schema version、source snapshot/export fingerprint、事件数与 sample 数的明确语义、必要的规则/迁移版本，并对输出执行 OpenAPI schema 与跨字段语义校验。若需要可复现实验，应把生成的 manifest digest 与该 snapshot 绑定；否则只能把下载文件视为一次动态查询结果。

9. **把上述边界转成最小的合成集成测试。** 至少覆盖：旧/新 revision 唯一性、主资产软删除或 digest 变化、跨 project/group/review/quality/primary 错配、AI 无 job/失败/无手/输入 digest 错配、Candidate evidence 传播、mapping provenance 明确为空、schema/readback 语义校验和 preview/download 的 artifact identity。完成这些测试前，不应把 synthetic `training-data.v3` manifest 宣称为可独立复现的训练样本集。
