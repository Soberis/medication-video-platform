# Web 前端与用户体验设计规范

> 导出选择按 V1.35 执行：弹窗完整读取当前项目候选后提供单选、多选和全选；“已选择”是本次用户选择数量，不是工作台业务汇总指标。

## 1. 文档定位

本文定义配药视频数据平台 Web 管理端的前端实现边界、用户体验原则、页面启用条件和验收方法。它服务于需求基线中的数据接收、资产管理、标注复核、清洗、数据集和治理流程，不复制业务需求、领域状态机或 API 字段定义。

视觉方向、Token、AppShell 与通用交互语言统一见[前端设计系统](../DESIGN_SYSTEM.md)。本文件只补充领域 UX、实现、权限、状态和验收规则，不建立第二套视觉语言。

发生冲突时按以下顺序处理：

1. `AGENTS.md` 与 `docs/requirements/requirements-manifest.json` 指向的 V1.35 Consolidated Baseline；V1.35 冻结产品语义，但不表示实现或验收已完成；
2. V1.35 明确引用的当前架构支持文档和已批准技术决策；
3. `docs/adr/` 中已批准的技术决策；
4. [状态机与领域守卫](./state-machines.md)、[安全、隐私与保留销毁](./security-privacy-retention.md)等当前专题设计；
5. OpenAPI、真实实现和测试结果。

本文不把设计工具、Codex Skill、MCP 或插件定义为生产运行依赖。

## 2. 产品定位与非目标

Web 是配药视频数据的云端管理端。界面只展示管理员和普通用户；自动标注、异常接管、复核和导出等能力由后端策略与权限决定，不再把每个权限集合都显示为独立角色。它帮助用户理解数据当前状态、处理异常、完成受控业务操作并追溯结果。

平台当前产品主线以一个真实配药事件（领域身份为 `CaptureGroup`，接入身份复用 `CaptureSession`）为工作对象。“配药事件”负责发现事件并进入 current-task-first 事件工作台；“标注任务”是任务待办入口，并深链回对应事件和当前操作。单路视频（产品 API 中的 `video_id`，映射既有 `clip_asset_id`）是事件内视图，不再与配药事件形成两套并行主流程。

视频可以由医院侧设备或系统远端上传，也可以由用户在平台页面选择本机文件上传。两种入口使用同一套入库规则，Web 不控制医院侧采集设备。

平台区分三种上传入口，但只维护一套 Upload、Multipart、METADATA、Complete 和 CaptureSession 入库协议：

1. 医院远端上传：医院侧设备或系统通过正式接口上传拍摄视频；
2. 自动化合成上传：本地工具生成合成 MP4、元数据和事件日志，用于开发、回归、CI 和批量造数；
3. 平台本地上传：用户在 Web 页面选择本机视频，按项目权限和文件规则上传。

医院远端上传和平台本地上传都必须调用正式协议，禁止通过 Web 私有接口或直接插库伪造入库结果。`/uploads/new` 必须由后端校验角色、项目权限和文件规则；LEAN-P0 不展示文件夹选择。文件由浏览器使用短期预签名 URL 直传对象存储，不经过 Core API，也不得持久化预签名 URL。开发、测试和 CI 仍只使用合成数据。

P0 非目标：

- 不控制摄像头、机器人、PLC 或边端采集；
- 不承担实时监控；
- 未经目标浏览器、网络和容量 UAT，不宣称平台本地上传具备 2GB 中断恢复能力；
- 不展示真实对象存储凭据、upload ID、预签名 URL 或内部堆栈；
- 不根据视频画面判断药品、剂量、处方或操作是否正确；
- 不为未来能力创建空页面、空 Store、假数据或不可执行操作。

## 3. 体验原则

### 3.1 状态优先

页面首先回答四个问题：

1. 当前对象处于什么状态；
2. 为什么处于该状态；
3. 当前用户可以做什么；
4. 操作后会发生什么、如何追溯。

状态名称必须来自正式契约或领域状态机，不使用只存在于前端的近义状态。颜色只能辅助表达，必须同时提供文字、图标或结构化说明。

在此基础上，业务页面应让用户依次确认：正在处理什么对象、当前是什么状态、为什么如此、下一步能做什么，以及操作后如何确认结果。视觉呈现遵循[前端设计系统](../DESIGN_SYSTEM.md)，但不改变业务状态机、权限或 API 事实。

### 3.2 服务端事实优先

- 数据库和服务端查询是业务事实来源；
- 前端不得根据本地计时器伪造上传、作业或审批进度；
- 刷新、轮询或重新进入页面后应能恢复真实状态；
- 乐观更新只用于可安全回滚且契约明确允许的低风险操作；
- 高风险命令成功前不得在界面中显示最终成功状态。

### 3.3 渐进披露

列表优先展示识别对象和判断下一步所需的最少字段；技术摘要、请求标识、状态历史和完整错误细节放入详情或可展开区域。敏感字段按权限最小化展示。

视频操作记录在详情页按需读取，默认不增加后台审计请求；只展示完成判断所需的最小事件摘要，审计详情 JSON、trace、授权引用和存储信息不得进入浏览器响应。

### 3.4 防误操作

删除、审批、数据集冻结、导出和其他不可逆或高风险操作必须：

- 明确显示作用对象和影响范围；
- 使用服务端权限和状态守卫，不能只依赖按钮隐藏；
- 要求必要的理由、审批或二次确认；
- 返回可追踪的结果；
- 不把危险操作放在高频普通操作的默认焦点位置。

### 3.5 工作台交互基线

- 同一业务上下文最多只有一个视觉上的 primary action；其他正常动作降为次要按钮或文本链接，删除等危险操作与播放、质量判断、标注和导出分离。
- Status 描述已经发生的事实，Next Action 描述用户现在应做什么；状态列与“下一步”列不得重复同一句长文案。当前无需操作时应明确写“等待系统处理”或“等待其他角色处理”，不留空也不制造假按钮。
- SummaryStrip 与列表汇总必须来自同一筛选条件下的服务端正式查询。前端不得抓取多页数据后自行汇总，也不得为视觉统一混合待标注、待复核、待清洗等不同统计语义。
- Evidence Rail 只能映射服务端状态、结果、当前权限和正式工作流事实；不得根据本地时间伪造完成、预测百分比或用动画暗示不存在的后台进度。状态未知时如实表示未知、尚未获取或暂无结果。
- 原始 AI Candidate 是辅助证据，不是人工标签、审批、质量结论或训练准入结论。候选初始化只准备草稿，不能代替显式提交；`NO_HAND_DETECTED` 是正常结果；AI `FAILED` 不得被表现为无条件的主链 blocked。
- 手部检测结果仅表示机器 evidence；当前导出按 V1.35 的唯一 HDF5 规则关联 已提交且 Review APPROVED 的 Revision 结果与同源样本，不提供独立手部 CSV 入口，不宣称模型训练成功。

### 3.6 V1.28 配药事件工作台边界

本节保留历史工作台语义；导航、导出及动作候选冲突处以本文件顶部的 V1.35 关系为准，历史描述不恢复旧产品入口。

- 事件页按“事件身份与当前阶段 → 聚焦视频与唯一 Current Action → 渐进详情”组织，优先回答对象、阶段和当前动作。
- 主业务 rail 只有接收、机位质量、事件质量、配药动作标注、人工复核、事件级清洗六个节点。Media Probe、media status、technical quality、MediaPipe 和 Candidate 作为辅助证据展示，不扩充主流程节点。
- Current Action 是页面唯一常驻动作中心；主操作必须由现有服务端状态和 capability 共同授权。前端可用 feature-local 纯函数集中推导展示，但不得新增持久化状态、通用状态机或浏览器侧权限。
- `N=1` 直接显示视频和低权重机位身份，不显示冗余选择轨道；`N>1` 使用紧凑、键盘可操作的机位选择器，只突出扫描和选择所需状态。
- `N>1` 首次进入时自动聚焦同一轮完整成功读取且未发现版本冲突的服务端事实集合中的首个未决机位；机位质量提交成功后必须先刷新权威事实，再安全聚焦下一未决机位。失败、并发冲突或刷新失败时留在原任务语境，不先行跳转。
- 自动聚焦、刷新和导航只减少找路，不自动播放、伪造业务结论、复制质量结果或授予权限。服务端已唯一确定的对象不要求用户重复选择；异常人工判断和高风险动作仍由人明确提交，所有最终标注都须由授权用户显式提交。
- `Current Action` 有动作时保持主导；等待或完成时收敛为紧凑状态说明，不用空侧栏、重复摘要、假按钮或连续普通确认弹窗填充页面。
- 技术详情、Candidate、同步声明、ID、上传/文件事实、Revision/Review 历史、草稿来源、Cleaning provenance、审计和危险操作默认渐进披露，不删除权威事实。
- Review APPROVED 是现有人工复核事实；提交与复核分开。Cleaning / 训练资格检查是确定性评估，不能代替提交或 Review。
- `stage`、`primaryAction`、等待原因和 blocker 必须从同一轮完整成功读取且未发现版本冲突的服务端事实集合与 capability 推导；依赖事实缺失或一致性不可证明时显示状态暂不可确认，不得使用旧浏览器状态补齐或猜测。

### 4.1 视频主链与历史页面

- `/projects/:projectId/capture-groups` 是当前“配药事件”默认业务入口；事件列表和详情以服务端 CaptureGroup 事实为准，不自动播放或预加载视频；
- `/projects/:projectId/videos` 是退役的历史单视频表面；不得把它作为 V1.28 兼容入口、当前导航或新事件跳转目标；
- `/projects/:projectId/sessions` 与详情仅保留历史兼容路由和测试，不进入当前导航；不得继续增加同步、批量检测或 Dataset 草稿动作；
- 每个单个已入库视频自动提交一个幂等的 MediaPipe 手部姿态检测；媒体就绪后 Action Candidate 也由后台按视频独立、幂等派发，不等待人工任务、负责人或人工质量。Candidate/handedness 不得伪造质量或阻断异常人工标注；
- AssetFolder 管理 API 和页面已退出；旧 folder ID、`clip_asset.folder_id` 与上传字段已由 V65 退役，不进入 LEAN-P0 页面；
- `/assets/:id` 详情只服务历史单视频数据或受控管理/诊断；属于 CaptureGroup 的资产必须进入事件工作台，不恢复独立资产工作流；
- `/assets/:id` 只展示当前已持久化且获准返回的元数据。播放器、缩略图、下载和对象存储定位在授权契约完成前不得出现；
- 工作台所需的异常数、待办数和状态汇总必须来自专用服务端查询，不得通过浏览器拉取多页列表后自行汇总。
- 顶部导航的上下文归属固定为：`/projects` 属于“项目”，`/projects/:projectId/capture-groups` 与事件详情属于“配药事件”，`/projects/:projectId/annotation-tasks` 属于“标注任务”。历史 `/videos` 与 `/assets/:id` 不进入当前导航；管理菜单只承担真实管理和诊断入口，视频详情不得高亮“管理”。

### 4.1.1 V1.28 应用壳层、面包屑与跨页上传状态

- 当前侧栏保持 `配药视频 / 数据管理` 品牌区，工作区导航为“项目”“配药事件”“标注任务”；管理区按权限和项目上下文提供“本地上传（辅助）”“项目成员”“账号管理”，底部显示当前用户名、角色和退出登录。上传状态与异常仅从上传失败的上下文入口进入，不作为一级导航；仍保留真实 `/uploads` 路由供管理员和获授权的上传操作者查询。仅链接真实路由，不新增全局搜索、通知、工作区切换或帮助入口。
- “配药事件”页面和“配药动作标注任务”页面已有侧栏上下文与唯一 `h1`，不再重复显示面包屑。嵌套事件详情可以保留 `配药事件 / <event identity>`，不建立另一层导航。
- 平台本地上传的跨页活动状态沿用现有 `LocalUploadProvider`：上传中、部分成功和失败保持可见，直到用户进入上传页面处理；全部成功在用户确认后可通过现有清除动作收起。不得新增通知中心、持久化 toast 历史、全局任务 Store 或后端状态。

### 4.2 当前可用筛选与渐进披露

当前只呈现服务端已有事实支持的筛选：

- 默认筛选区只保留已有服务端契约支持的最少必要筛选，具体高频组合留待 UAT 验证；其余已支持筛选进入“更多筛选”。收起不得清除条件，已应用条件必须始终可见并可逐项移除；

- 配药事件：来源、拍摄时间、固定相机编号、媒体状态、手部状态/结果、配药动作标注状态和清洗结论；汇总与列表必须使用同一筛选；
- Session：设备、拍摄时间范围、组装状态、质量状态；
- ClipAsset：所属 session、批次、设备、相机角色、拍摄时间范围和资产状态；
- 场景、科室、隐私、标注、清洗和质量分等筛选仅在相应字段、所有权和查询契约落地后启用，不能展示无效控件或用前端假数据代替；
- 项目入口只列认证主体具有 ACTIVE Membership 的项目；进入后由 `/projects/:projectId/...` 路由显式携带上下文，后端仍逐请求校验 Membership。不得仅靠前端选择器实施隔离。
- 历史文件夹查询不影响授权，也不得把文件夹 ID 当作项目或对象路径；当前产品不展示该筛选。

## 5. 页面状态规范

每个服务端数据页面至少处理以下状态：

| 状态 | 最低要求 |
| --- | --- |
| 首次加载 | 显示页面目标和加载提示，不显示伪造数据 |
| 刷新中 | 保留仍有效的已加载内容，并说明正在刷新 |
| 空数据 | 说明为空的原因和可执行下一步，不将空数据表述为错误 |
| 成功 | 展示关键事实、更新时间和后续动作 |
| 可重试失败 | 展示稳定错误码、可理解说明和明确重试入口 |
| 不可重试失败 | 说明需要修改的输入、权限或业务前提 |
| 无认证 | 引导重新认证，不泄露目标资源是否存在 |
| 无权限/跨项目 | 使用安全文案；服务端仍需返回正确的 `403` 或按安全策略隐藏为 `404` |
| 已过期 | 说明过期对象不能继续使用以及重新开始方式 |
| 部分成功 | 逐项展示成功和失败，不用单一绿色提示覆盖失败项 |

错误展示规则：

- 优先使用 OpenAPI 中稳定的 `error_code` 映射用户文案；
- 保留 `request_id` 供排障，但不展示堆栈、SQL、对象存储内部地址或令牌；
- 未知错误使用安全兜底文案，不能猜测业务原因；
- 同一错误码在不同页面保持一致含义。

### 5.1 多相机状态语义

多相机页面必须区分以下事实，不能统一显示为“已上传”或“正常”：

| 页面表达 | 服务端事实 | 禁止推断 |
| --- | --- | --- |
| 已绑定流 | CameraStream 已绑定 ClipAsset | 不代表媒体可读或已完成探测 |
| 已入库流 | CameraStream/ClipAsset 已完成媒体入库 | 不代表质量、隐私或同步复核通过 |
| 预期流 | 冻结 CameraSetSnapshot 中启用的相机数量 | 不代表本次实际收到相同数量 |
| 边端同步声明 | 上传元数据中的 `sync_status`、`time_offset_ms` | 不得展示为平台验证结论 |
| 技术检测状态 | 完整摘要和全流解码验证投影出的 CameraStream/CaptureSession 状态 | `PENDING` 必须显示为“待检测”，不能显示为人工质量通过或训练可用 |

缺失相机、视频已绑定但未探测、探测失败是三种不同情况。完整性比例的分子必须明确写成“已绑定”或“已入库”，不得只显示一个无定义的百分比。

## 6. 角色、权限与隐私体验

### 6.1 角色可见性

- 管理员处理项目、成员、视频上传与删除、标注任务和复核；AssetFolder 管理退出当前产品面；
- 普通用户只访问已加入的项目，可按项目权限本地上传、播放获短期授权的原始 MP4，并执行分配任务；
- 当前按 V1.35 规则，`ROLE_ADMIN` 且拥有 ACTIVE 项目 `ADMIN` Membership 的管理员可确认人工接管结果，包括自己提交的标注，无需另一人复核；草稿准备与显式提交结果不冒充人工确认，保留不可变结果与历史审计记录；
- 未来增加复核员、质检员或导出用户时只新增权限模板，不改变页面对象和服务端事实。

前端可以根据授权结果调整导航和操作入口，但服务端授权始终是最终门禁。

平台管理端提供内部账号登录页；登录后显示账号与 ADMIN/MEMBER 全局角色，项目列表和项目详情返回的 Membership 仍是项目权限事实。浏览器不得伪造角色、保存密码或持久化会话/CSRF token；边端设备不使用 Web 登录页，而是使用独立上传凭据。账号引导、会话和 CSRF 规则见 [ADR-0002](../adr/0002-platform-account-authentication.md)。

### 6.2 敏感状态表达

原始、脱敏、隐私待确认、隐私风险和隔离数据必须有清晰且一致的文字标识。未经授权不得请求或预加载原始视频；缩略图、缓存、错误日志和浏览器历史也不能成为绕过权限的渠道。

### 6.3 高风险反馈

高风险操作结果必须显示：执行人、执行时间、对象、结果和可用的审计/请求标识。数据集冻结、导出、删除和隐私放行不能使用模糊的“确定吗”作为唯一确认信息。

## 7. 前端技术与启用门槛

### 7.1 基线

- React 19、TypeScript、Vite 和 React Router；
- 使用函数组件、严格 TypeScript 和 React StrictMode；
- API 访问集中在 `src/api/` 或明确的领域 API 模块；
- 页面负责路由参数和编排，展示组件通过 props/callbacks 交互；
- 服务端数据默认使用页面局部状态，不复制为第二份业务事实。

### 7.2 Ant Design

Ant Design 已是批准的 React 组件技术选型，但按需启用。满足以下任一条件时引入：

- 首个复杂资产或 Session 列表需要筛选、分页和批量选择；
- 出现重复使用的表单、对话框、日期选择或树形选择；
- 原生组件开始产生重复实现和一致性成本。

当前单一只读进度页不因此重写。引入时先确认按需导入、主题变量、中文文案、可访问性和医院浏览器兼容性，不建立无实际消费者的二次组件框架。

Session/资产列表是首个满足启用条件的页面。首次接入限定为列表、筛选、描述列表、状态标签、空态和分页所需组件；不因组件库可用而提前加入批量操作、上传器、播放器或全局业务组件层。

Web 视觉 Token 以 `src/theme/tokens.ts` 为唯一语义来源，`ConfigProvider` 主题和 CSS 变量从同一映射产生。自定义 CSS 只能引用这些语义变量，不在组件、页面或样式文件重复定义颜色、圆角、间距或状态主题。

### 7.3 客户端状态

登录会话和当前用户使用 React Context。当前项目继续由显式路由参数表达；筛选、批次、资产、标注和数据集等状态优先使用页面局部 state/reducer 与小型 hooks。

服务端对象不得仅因多个组件使用就整体复制进全局 Store。出现第二个真实跨路由客户端状态用例前，不引入 Redux、Zustand、TanStack Query 或通用缓存层。

### 7.4 平台本地上传

平台本地上传必须复用正式上传状态机，并满足：

- 服务端校验用户和项目权限；
- 校验文件数量、大小、类型和总量；
- 浏览器按 Part 读取文件并使用短期预签名 URL 直传对象存储，Core API 不代理视频字节；
- 不在日志、Store、localStorage 或业务表中保存预签名 URL；
- 显示服务端确认的 Part、文件和批次进度，不伪造成功状态；
- 记录导入来源、操作者、项目、时间、结果和请求标识；
- 一次选择多个文件时，不由前端猜测它们是否属于同一个 CaptureSession；按服务端已批准规则提交；
- 开发、测试和 CI 仍只允许合成数据。

平台本地上传的格式、大小、批量数量、取消和中断恢复范围以目标环境 UAT 结果为准。

### 7.5 播放和删除

- 资产详情只有在服务端确认项目 Membership 和媒体状态并签发短期授权后才创建 `<video>`；页面初始不得预加载对象内容。
- 当前 P0 在资产为未删除、上传完整性校验完成的 MP4 时向 ACTIVE 项目成员显示“播放视频”。点击后才签发 `DATA_REVIEW` 地址，地址只保存在组件局部状态；显示次要的到期时间、失败重试和关闭按钮，不自动播放，也不把播放当作质量结论。播放器在普通笔记本保持约 `60–65vh` 的工作台上限；全屏目标是同时包含 `<video>` 与 Skeleton Overlay 的共同容器。Overlay 渲染 bbox、21 点和骨架，只显示最近候选帧；Left/Right 以低权重辅助信息显示，不作为流程判断。媒体技术检查补充时长、编码和完整解码事实，但不阻断人工查看。
- 播放与质量判断相邻但彼此独立：项目成员查看视图后选择合格、不合格或需复核；不合格与需复核必须选择固定原因，保存时显示服务端当前版本冲突并允许刷新后重试。事件级质量结论保存为有效准入时，详情页只展示服务端确认的“组任务已自动分配”事实和受理人，不显示正常路径的手动受理人选择器；任务查询未完成或失败时如实显示确认中或可重试错误。
- P0 播放器验证首帧、时长、Range seek、授权过期、加载失败和重试；多相机切换保持 Session 上下文，多路同步播放另行评审。
- 尚未就绪、处理中、无权播放和处理失败使用不同文案，不用黑色视频框伪装为正在加载。
- 视频列表和详情页提供删除入口；确认框明确显示视频名称、项目和影响。
- 删除成功后刷新列表，删除失败时显示服务端返回的权限、引用或状态原因。

### 7.6 标注复核与历史 Cleaning 展示

- 标注任务状态必须来自服务端：`ASSIGNED` 显示待标注/待修改，`SUBMITTED` 显示等待管理员复核，
  `COMPLETED` 显示复核完成；前端不得仅根据点击“通过”本地推断完成。
- 当前 V1.35 的默认自动入口是媒体就绪后的 Action Candidate 派发；它不创建人工 Revision、Review 或人工任务。进入人工提交路径时，授权用户准备或复用 CaptureGroup AnnotationTask，再显式提交整份标注。
- `APPROVED` 和任务 `COMPLETED` 由服务端复核操作完成。请求失败时页面保留原状态并重新加载，不显示一半成功的“复核通过”。
- 历史 Cleaning `PASS/WARNING/REJECT` 只读展示中文含义和稳定原因，不提供新建、自动重算或“重新核对清洗”操作；不把历史快照写成当前导出结论。
- 当前唯一 HDF5 从视频工作入口的项目级选择弹窗导出，遵循 V1.35 的完整读取和明确 ID 规则，并检查已提交且 Review APPROVED 的 Revision 结果及同源 MediaPipe provenance；不恢复旧 CSV、DatasetVersion UI 或自动导出，不宣称真实模型训练成功。
- 当前切片不增加 `/cleaning` 页面、后台进度轮询、Worker 状态、队列提示或跨资产统计；这些能力不属于当前产品主链。

### 7.7 Vite 与环境配置

- 本地开发通过 `/api` 代理到 Core API；
- 前端不内嵌数据库、S3 或生产服务地址；
- 仅 `VITE_` 前缀的非敏感配置可以暴露给浏览器；
- 令牌、对象存储密钥和预签名 URL 不写入构建时环境文件；
- 内部管理终端浏览器矩阵冻结前，不宣称兼容性验收完成，也不提前增加无证据的 legacy 插件。

### 7.8 桌面视口与内容宽度

- P0 只验收内部笔记本和桌面工作站，目标视口为 1366 × 768、1440 × 900、1920 × 1080、2560 × 1440 和 3840 × 2160；测试证据必须记录操作系统显示缩放比例。
- 1080p 及以下保持紧凑的单工作台布局；2K 和 4K 使用分档内容宽度提高表格、筛选和项目列表的空间利用率，不使用 CSS `zoom`、整体 transform 或按分辨率放大基础字号。
- 页面外层保持统一居中边界；工作台型内容可以随分档变宽，播放器、正文和长表单仍保留各自可读上限。
- 目标视口不允许页面级横向滚动、控件重叠和主要操作被裁切；确有必要时只让表格容器局部滚动。
- 当前已有的窄屏回退可以保留，但手机浏览器、触摸优先交互和移动端独立导航不属于 P0 验收范围。

1440 × 900 是默认完整工作台体验的验收参考；1366 × 768 不得遮挡关键状态或主操作，允许更紧凑；1920 × 1080 不得以无限拉宽内容或增加装饰填充空间。窄屏回退不得破坏，但不因此扩大为移动端产品承诺。

## 8. 领域信息表达

视觉方向、颜色、层级和通用交互语言统一见[前端设计系统](../DESIGN_SYSTEM.md)。本文只补充以下领域信息规则：

- 桌面端列表默认使用稳定服务端排序和游标分页；前端列排序只有在 API 明确支持时才能启用；
- “拍摄时间”使用 `device_time_utc`/`record_start_utc`，“平台接收时间”使用 `server_receive_time`，不得统一标为含糊的“时间”；
- 枚举状态显示中文解释，同时在详情保留正式英文状态码，便于排障和审计；
- 设备 ID、批次 ID、session ID 和资产 ID 可以复制或完整查看，但列表默认缩略显示，不能用完整 UUID 挤占主要判断信息；
- 当前没有合法预览源时展示“预览尚未开放”的原因，不使用黑色视频框、假缩略图或加载动画暗示视频正在处理。

## 9. 可访问性

P0 页面至少满足以下要求：

- 使用语义化 HTML、正确标题层级和表单标签；
- 所有操作可通过键盘完成，焦点顺序可预测；
- 弹窗打开后管理焦点，关闭后返回触发点；
- 状态变化和错误不能只靠颜色表达；
- 文本与背景保持可读对比度；
- 加载、错误和完成等动态状态可被辅助技术感知；
- 图标按钮具有可访问名称；
- 不以自动播放视频或闪烁内容干扰任务。
- 精简视觉装饰不得降低状态可辨识性；加载、错误和真实 blocked 状态必须能被辅助技术识别。

目标以 WCAG 2.2 AA 为指导；实际内部管理终端和辅助技术支持范围在 UAT 前确认。

## 10. 性能与刷新策略

- 常用列表第一页响应目标继承需求基线的 3 秒要求；
- 页面不得使用高频无界轮询；轮询间隔、停止条件和失败退避必须明确；
- 页面隐藏、对象进入终态或组件卸载后停止轮询；
- 人工命令成功后优先进行一次有界快照刷新并停止旧轮询；刷新成功后才允许安全聚焦或导航到下一项，刷新失败时保留当前上下文和重试入口；
- 大列表使用服务端分页、筛选和稳定排序；
- 不预加载无权限或尚未请求的视频；
- 视频预览、Canvas 和多相机同步进入实现前建立独立性能预算。

列表契约统一使用不透明 cursor 和有上限的 `limit`，默认按稳定的时间与 ID 组合倒序。前端不得解析 cursor、拼接数据库字段或将其持久化为业务标识；筛选条件变化后必须清空旧 cursor。第一页 3 秒目标包含权限过滤、筛选和返回页面所需摘要字段，不允许通过逐行追加请求形成 N+1 查询。

## 11. 测试与验收

| 层级 | 职责 |
| --- | --- |
| ESLint | 静态代码规则 |
| `tsc` | TypeScript 与 JSX 类型检查 |
| Vitest | 组件状态、错误映射、交互和 API 边界单元测试 |
| Playwright | 真实浏览器中的路由、关键流程、权限和失败恢复 |
| Accessibility 检查 | 键盘、语义、焦点、对比度和动态状态 |
| UAT | 真实角色在批准环境中使用合成或授权数据完成任务 |

每个启用页面的最低验收：

1. 加载、空、成功、失败和无权限状态均有测试或可执行证据；
2. 稳定错误码映射正确，未知错误安全降级；
3. 不泄露令牌、预签名 URL、内部存储地址或敏感数据；
4. 键盘可完成主要任务，焦点和状态反馈明确；
5. `lint`、`type-check`、单元测试和生产构建通过；
6. 关键跨页面流程在进入 UAT 前增加 Playwright；
7. 真实目标浏览器或内部管理终端结果不得用开发机推断代替。

## 12. 设计与开发辅助工具

设计、浏览器自动化和可访问性工具按任务使用，不是生产架构依赖。工具输出必须回到需求、契约、真实实现和测试证据中验证，不得因工具可用而扩大交付范围。
